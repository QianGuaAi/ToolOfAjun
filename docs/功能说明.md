# 功能说明

## FRP 预设端口下拉列表

### 目标
在「隧道穿透」模块的添加规则区域提供常用端口预设，用户选择后自动填入本机端口、公网端口和备注，减少手工输入错误。

### 核心逻辑
1. 固定服务器默认地址为 `47.120.63.249`，仅在已保存地址为空时填入，不覆盖用户已有配置。
2. 预设列表固定 10 项：RDP、HTTP 80、开发 8080、开发 8000、SSH、MySQL、PostgreSQL、Redis、SMB、VNC。
3. 下拉选择只填充 `DraftRule.LocalPort`、`DraftRule.RemotePort` 和 `DraftRule.Description`，不直接添加规则。
4. 端口合法性和远程端口重复校验继续复用原有 `AddRuleCommand` / `CanAddDraftRule`。

### 涉及文件
- `src/MyTools/Services/FrpService.cs`：`FrpPortPreset`、`FrpPortPresetCatalog`、`FrpDefaults`。
- `src/MyTools/ViewModels/FrpViewModel.cs`：`PortPresets`、`SelectedPortPreset`、预设应用逻辑和默认地址兜底。
- `src/MyTools/Views/FrpView.xaml`：添加规则卡片顶部的预设 `ComboBox`。

## FRP 服务器预设

### 目标
在「隧道穿透」模块的服务器配置区域提供服务器预设，用户选择后自动填入服务器地址和 frps 控制端口。

### 核心逻辑
1. 服务器预设固定为「阿里云主服务器」，地址 `47.120.63.249`，端口 `7000`。
2. 服务器预设不包含 Token，Token 仍由用户在客户端输入，并通过 Windows DPAPI 加密保存。
3. 选中预设只修改 `FrpServerAddress` 和 `FrpServerPort`，不会启动隧道或保存配置。
4. 服务器端已安装 `frps v0.50.0` 并以 `frps.service` 运行，监听 `7000/tcp`；未修改现有 nginx Web 服务。

### 涉及文件
- `src/MyTools/Services/FrpService.cs`：`FrpServerPreset`、`FrpServerPresetCatalog`。
- `src/MyTools/ViewModels/FrpViewModel.cs`：`ServerPresets`、`SelectedServerPreset`、服务器预设应用逻辑。
- `src/MyTools/Views/FrpView.xaml`：服务器配置卡片顶部的服务器预设 `ComboBox`。

## 主窗口菜单式导航

### 目标
将主窗口从左侧侧边栏导航改为传统桌面程序的顶部菜单式导航，窗口结构为标题栏、菜单栏、主操作区和底部状态栏。

### 核心逻辑
1. 顶部菜单使用 WPF 原生 `Menu` / `MenuItem`，不引入新依赖。
2. 菜单分为“文件、系统、工具、多媒体、日程、设置、帮助”七组。
3. 菜单项复用 `MainViewModel` 现有 `Show*Command`、`OpenLogFolderCommand`、`ToggleAutoStartCommand` 和 `ExitCommand`。
4. “退出程序”复用 `ExitCommand`，保持托盘退出、资源释放和 `App.IsExiting` 流程一致。
5. 所有系统子模块（系统优化、当前网络、启动管理、程序卸载、系统信息、性能测试、系统设置）均作为独立 `CurrentModule` 通过菜单直接进入，不再有嵌套 Tab 切换。
6. 底部状态栏绑定 `CurrentNavigationText`，显示用户可读的当前位置，例如"系统优化"或"当前网络"。

### 涉及文件
- `src/MyTools/MainWindow.xaml`：顶部菜单、主内容区三行布局、底部状态栏。
- `src/MyTools/MainWindow.xaml.cs`：帮助菜单的“关于”和“打开项目规范”点击事件。
- `src/MyTools/ViewModels/MainViewModel.cs`：`CurrentNavigationText` 状态栏文本。
- `src/MyTools/Resources/Theme.xaml`：菜单栏和状态栏样式资源。

### 安全与限制
- 不新增 NuGet 包，不改变 `.NET Framework 4.8` 目标框架。
- 不在窗口构造函数中读取文件、注册表或执行 WMI。
- 打开 `AGENTS.md` 只在用户点击帮助菜单后执行，文件不存在时静默返回。

## 启动性能优化

### 目标
缩短主窗口首帧等待时间，避免启动时一次性创建所有功能模块界面。

### 核心逻辑
1. `MainWindow.xaml` 只保留顶部菜单、底部状态栏和轻量内容宿主。
2. 首页 UI 移入 `Views/HomeView.xaml`，在窗口显示后延迟加载。
3. 非首页模块 UI 移入 `Views/MainModulesView.xaml`，首次进入对应模块时加载。
4. 托盘图标不再由 XAML 创建，改为窗口显示后延迟初始化。
5. 开机自启注册表状态不在 `MainViewModel` 构造函数中同步读取，改为空闲阶段读取。

### 涉及文件
- `src/MyTools/App.xaml.cs`：记录 `Show()` 返回耗时。
- `src/MyTools/MainWindow.xaml(.cs)`：轻量主窗口、延迟加载首页和托盘图标。
- `src/MyTools/Views/HomeView.xaml(.cs)`：首页内容。
- `src/MyTools/Views/MainModulesView.xaml(.cs)`：非首页模块内容与相关 UI 事件。
- `src/MyTools/ViewModels/MainViewModel.cs`：延后读取开机自启状态。
- `docs/规划/启动性能基线-2026-05-22.md`：本次启动性能基线。

### 安全与限制
- 不关闭全局异常处理、日志、DPAPI 或 SQL 白名单校验。
- 首次进入非首页模块时会加载对应模块视图，可能有一次性轻微等待。

## 启动项管理

### 目标
管理 Windows 注册表 Run 启动项，并降低部分软件在被禁用后又自行恢复开机自启的概率。

### 核心逻辑
1. 列表读取当前用户与所有用户的 `Software\Microsoft\Windows\CurrentVersion\Run`。
2. 禁用启动项时，程序先把原始 Run 值备份到 `Software\AJunTools\DisabledRun`，再写入 `Explorer\StartupApproved\Run` 的 Windows 禁用标记，最后移除 Run 值。
3. 如果某个软件后续重新写回同名 Run 值，刷新列表时会读取 `StartupApproved\Run`，将其显示为“注册表 Run（Windows 已禁用）”，按钮仍显示为“启用”。
4. 启用启动项时，程序从 MyTools 备份或现有 Run 值恢复命令，写回 Run，并同步写入 Windows 启用标记。
5. 永久删除启动项时，同时清理 Run、MyTools 禁用备份和 `StartupApproved\Run` 中的同名值。

### 涉及文件
- `src/MyTools/Services/StartupService.cs`：启动项枚举、禁用、启用、删除和 Windows `StartupApproved` 状态读写。
- `src/MyTools/ViewModels/MainViewModel.cs`：复用原有刷新、禁用/启用和删除命令。
- `src/MyTools/Views/StartupView.xaml`：展示来源分类和状态按钮。

### 安全与限制
- 系统级（所有用户）启动项仍需管理员权限修改。
- 本模块只处理注册表 Run 启动项；计划任务、服务和驱动级自启不在当前列表范围内。
- 不在程序启动期扫描启动项，仅在用户进入模块或点击刷新时读取注册表。

## 截图 / 录像 / 录音

### 目标
提供全屏截图、区域截图、窗口截图、区域录像和独立录音能力；截图快捷键在程序启动后即可全局使用，不要求先打开截图功能界面。

### 核心逻辑
1. `MainWindow.OnSourceInitialized` 初始化 `HotkeyService` 后，调用 `MainViewModel.ScheduleStartupHotkeyRegistration()`。
2. 快捷键配置读取延后到 `DispatcherPriority.ApplicationIdle`，异步读取程序同目录 `MyTools.settings.json` 并注册全局热键，避免阻塞主窗口首帧。
3. 进入截图界面时只补充加载录像输出目录和截图历史，不再作为截图快捷键首次生效的前置条件。
4. 截图热键触发后复用 `TriggerScreenshotAsync()`，按当前设置执行全屏、区域或窗口截图，并根据设置打开编辑器或写入剪贴板。
5. 截图编辑器窗口创建前调用 `DeferredUiResourceService.EnsureLoaded()`，确保快捷键路径未进入截图界面时也能加载 MaterialDesign / MahApps 样式资源。
6. “划区域”截图的选区窗口在 HWND 创建后使用真实 DPI 与虚拟屏幕物理像素重新定位；选区换算为像素时左上取 floor、右下取 ceiling，避免右边界被截掉。写入剪贴板时统一生成 32 位 BGRA 位图，并同时提供 WPF Image、DIB 与 PNG 格式，兼容微信、Office、画图等不同粘贴目标。

### 涉及文件
- `src/MyTools/MainWindow.xaml.cs`：窗口句柄初始化后安排启动期热键注册。
- `src/MyTools/ViewModels/MainViewModel.cs`：拆分截图热键设置加载与截图界面数据加载。
- `src/MyTools/Views/RegionSelectorWindow.xaml.cs`：区域截图蒙层窗口、DPI 校准和选区像素矩形换算。
- `src/MyTools/Services/ScreenshotService.cs`：截图捕获、鼠标光标绘制和兼容式图片剪贴板写入。
- `src/MyTools/Services/HotkeyService.cs`：封装 Win32 `RegisterHotKey` / `UnregisterHotKey`。
- `src/MyTools/Services/DeferredUiResourceService.cs`：截图编辑器需要打开时按需加载延迟 UI 资源。

### 安全与限制
- 启动期不同步读取截图历史、扫描目录或加载大对象。
- 如果快捷键被其他程序占用，设置页面保存时会提示；启动期静默失败，不弹窗阻塞用户。

## 多媒体

### 目标
提供图片查看、音视频播放、常用文档浏览、格式转换和图片/PDF互转入口；图片预览和沉浸看图时支持上一张/下一张切换，并支持直接复制当前图片。

### 核心逻辑
1. 多媒体页通过 `MultimediaViewModel` 管理当前选中文件、预览图片、沉浸图片、PDF 和常用文档。
2. 用户选中图片后，预览区加载 `PreviewImageSource`；双击进入沉浸模式后加载 `ImmersiveImageSource`。`PreviousImageCommand` / `NextImageCommand` 在当前媒体列表中查找相邻图片，跳过音频、视频和 PDF。
3. 图片预览区和沉浸看图区显示“上一张 / 下一张”按钮；到达第一张或最后一张图片时，对应按钮自动禁用。
4. 页面捕获 `Ctrl+C`，当前内容为图片时调用 `CopyCurrentViewedImageToClipboard()`，复用 `ScreenshotService.SetClipboardCompatible()` 写入剪贴板。
5. 右键点击图片时可执行“图片转 PDF”，程序在图片同目录生成单页 `.pdf` 文件，并刷新当前文件夹列表。
6. 右键点击 PDF 时可执行“PDF 转图片”，程序按页渲染为 `.png` 图片，文件名使用 `_page_001` 递增，并刷新当前文件夹列表。
7. 通用“格式转换”只处理图片、音频和视频；PDF 只走专门的 PDF 转图片入口，避免误送入音视频转换流程。
8. 媒体文件列表支持“详细信息 / 列表 / 大图标”三种查看方式，切换时保留当前选中项、勾选状态、双击沉浸预览和右键菜单操作。
9. 音视频预览和沉浸播放的进度滑块支持拖动定位；松开鼠标后立即从滑块所在时间点继续播放。
10. 音视频预览和沉浸播放提供 0% 到 100% 连续音量滑块，拖动音量滑块时立即作用于当前播放器。
11. 大图标模式禁用横向滚动并按可用宽度自动换行；图片直接显示缩略图，视频通过 ffmpeg 后台抽取首帧缩略图并缓存到程序同级 `MediaThumbnails/`。
12. 文件内容列表会显示 `.txt/.log/.csv/.json/.xml/.ini/.yaml`、`.md`、Word、Excel、PowerPoint 文件；文本和 Markdown 在左侧预览区显示前 32 KB 内容，Office 文件显示文件信息并提供外部打开。

### 涉及文件
- `src/MyTools/Views/MultimediaPage.xaml(.cs)`：多媒体页面、预览/沉浸模式、音视频进度定位、音量调节、列表查看方式、图片切换按钮、右键菜单和键盘快捷键。
- `src/MyTools/ViewModels/MultimediaViewModel.cs`：当前媒体/文档状态、文件列表查看方式、图片加载、文本预览、上一张/下一张导航、剪贴板复制、图片转 PDF 和 PDF 转图片命令。
- `src/MyTools/Services/MediaFileTypeHelper.cs`：识别图片、音频、视频、PDF、文本、Markdown、Word、Excel 和 PowerPoint 文件。
- `src/MyTools/Services/PdfConvertService.cs`：图片生成单页 PDF、PDF 渲染为 PNG 图片。
- `src/MyTools/Services/ScreenshotService.cs`：兼容式图片剪贴板写入。

### 安全与限制
- `Ctrl+C` 只在当前查看内容是图片时生效，不复制音频、视频或 PDF。
- 图片复制使用已加载的预览位图，不重新同步读取磁盘大文件。
- 上一张/下一张只在图片之间切换，不会跳到音频、视频或 PDF。
- 图片转 PDF 生成单页 PDF；多图合并为一个 PDF 暂不支持。
- PDF 转图片依赖 Windows 系统 PDF 渲染能力，Windows 7 不支持时会提示失败。
- 视频缩略图依赖本机可用的 `ffmpeg.exe`；未找到或抽帧失败时保留扩展名占位图标，不阻塞文件列表浏览。
- Word、Excel、PowerPoint 不做内嵌解析，不依赖 Office COM；双击不会进入沉浸模式，可通过“外部打开”交给系统默认程序。

## 排班管理

### 目标
在“日程 / 排班”中维护按月份分组的排班版本，支持直接编辑、自动设置休息日、当前月份另存、清空全部单元格、清空随机单元和导出 Excel。

### 核心逻辑
1. 双击左侧版本列表加载排班表，加载后姓名、每日总休和班次单元格立即可编辑，不再需要进入编辑模式。
2. “保存”将当前版本写回当前月份目录：`%LOCALAPPDATA%\MyTools\Schedules\{YYYY-MM}\{版本名}.json`。
3. “另存”只要求用户输入新版本名，程序固定使用当前排班表的年月保存，不提供跨月份保存入口。
4. “设置休息日”调用 `ShiftAutoOptimizer` 生成随机排班结果，`IsManual=true` 的用户手动单元格不会被覆盖；硬性约束包含每日总休、连续上班不超过 5 天、每人每月最少休息 9 天；勾选“无警告再显示”后，程序会在后台反复尝试生成，只有当优化器最终无警告且冲突侧栏无警告时才把结果显示到表格，阶段 D 可修复的中间过程不算最终警告；连续尝试 99 次仍无法生成无警告表时停止，只有检测到 `IsManual=true` 的手工格本身已违反每日总休或连续上班不超过 5 天等硬性规定时，才弹出手工设置错误提示。
5. 班次弹出菜单提供“小1”快捷项；点击后从当前格开始依次设置“小、大、休、休”四格，越过月底的部分自动忽略；弹出菜单中的“大夜”仍只写入原“大”班次代码，当前格显示为“大”。
6. “清空”会清空所有员工所有日期的班次单元格，将 `Code` 置空、`IsManual=false`，并重置 `GeneratedAt`。
7. “清空随机单元”只清空 `IsManual=false` 的单元格，并保留用户手动设置的单元格；清空后重置 `GeneratedAt`，导出 Excel 前需要重新自动生成。
8. 表格数据变化时优先刷新已有单元格、统计格和冲突状态，不重建整张动态 Grid；仅人员数量、月份或列数变化时重建表格结构。
9. 员工行使用可视区域渲染：滚动条保留整月全表高度，但界面只创建当前可见员工行及上下缓冲行的控件，降低大人员表的卡顿和内存占用。
10. 冲突侧栏点击“定位”时自动滚动到对应人员或日期附近，再高亮当前冲突单元格。
11. 低优先级警告在硬性约束之后检查：同一列内“副 / 卡 / 感”只有同一种代码出现 2 次及以上时发出警告；例如“副+卡”不警告，“副+副”警告；同时尽量避免上一天休一天、尽量让休息日连续 2 天或以上。

### 涉及文件
- `src/MyTools/ViewModels/ScheduleViewModel.cs`：排班版本、保存/另存、自动生成、清空全部单元格、清空随机单元、统计、硬性约束和低优先级警告检查。
- `src/MyTools/Views/SchedulePage.xaml(.cs)`：排班工具栏、动态表格、班次弹窗、局部刷新，以及节假日整列浅蓝色底色和“休”单元格米黄色底色。
- `src/MyTools/Services/ScheduleService.cs`：按月份目录读写排班 JSON 版本。
- `src/MyTools/Services/ScheduleModels.cs`：班次代码；“大夜”只是弹窗文案，底层仍使用“大”代码，并兼容旧“夜”输入。
- `src/MyTools/Services/ScheduleExcelExporter.cs`：导出排班 Excel 时将夜班显示为“夜”。
- `src/MyTools/Services/ShiftAutoOptimizer.cs`：自动设置休息日并避开用户手动单元格，生成时优先满足 9 天总休硬约束，再低优先级偏向连续休息。

### 安全与限制
- 另存不会改变当前排班表的年月，只能在当前月份下创建新版本名。
- “清空”不会删除人员、姓名或每日总休目标，但会清空所有班次单元格和手动标记。
- “清空随机单元”不会删除人员、姓名、每日总休目标或用户手动设置的班次。
- 未完成自动生成、清空全部单元格或清空随机单元后，Excel 导出会被拦截，防止导出未生成版本。
- 每人每月最少休息 9 天是硬性约束；上一天休一天、单天休和“副 / 卡 / 感”同一种代码在同列重复 2 次及以上属于低优先级警告。

## frp 隧道穿透

### 目标
在 MyTools 中新增「穿透」模块，用于配置 frp 客户端，把当前 Windows 电脑上的指定本机端口通过远端 frps 服务器暴露为公网端口。

### 核心逻辑
1. 用户填写 frps 服务器地址、控制端口和 Token。
2. 用户添加 TCP 隧道规则，规则包含本机端口、远程端口和说明。
3. 程序将 Token 使用 Windows DPAPI 当前用户范围加密后保存到 `MyTools.frpconfig.json`。
4. 程序将规则保存到 `MyTools.frprules.json`。
5. 点击启动时，程序从嵌入资源解压 `frpc.exe` 到 `%TEMP%\MyTools\frpc.exe`。
6. 程序生成 `%TEMP%\MyTools\frpc.ini`，使用 frp v0.50.0 支持的 ini 格式。
7. 程序启动 `frpc.exe -c %TEMP%\MyTools\frpc.ini` 并根据输出更新连接状态。
8. 点击停止或退出程序时，终止当前 frpc 进程。

### 涉及文件
- `src/MyTools/NativeBinaries/frpc.exe`：嵌入的 frp v0.50.0 Windows amd64 客户端。
- `src/MyTools/Services/FrpService.cs`：负责配置读写、DPAPI 加解密、ini 生成、frpc 解压和进程管理。

## Codex 账号切换器

### 目标
在 Codex 配置面板提供多账号本地档案库与一键切换能力，使用户可以在家里、办公室等多台个人电脑上各自维护多个 Codex 账号档案，避免重复手动登录；用户首次在 Codex CLI 完成一次登录后，工具读取 `~/.codex` 入库，之后所有切换均无需再次输入账号密码，直到 `refresh_token` 过期才需要重登并刷新档案。

### 核心逻辑
1. 档案库存放在 `%LOCALAPPDATA%\MyTools\Codex\profiles.json`，使用 Windows DPAPI 当前用户范围加密整文件；激活态记录在 `%LOCALAPPDATA%\MyTools\Codex\active.json`，仅用于 UI 高亮，不参与鉴权。
2. 每条档案记录包含别名、邮箱（脱敏展示为 `xxx***@example.com`）、备注、最后导入时间、`access_token` 解析得到的过期时间（`refresh_token` 不是 JWT 不解析）、加密后的 `config.toml` 与 `auth.json`、`Status` 标签（正常 / 即将过期 / 已过期 / 未知）。
3. 添加（导入当前账号）：用户先在 Codex CLI 登录目标账号，然后在工具中点击“导入当前账号”并填写别名 → 工具读取 `~/.codex` → DPAPI 加密 → 入库。也可点击“导入 CPA Token”选择 CPA JSON 生成实验档案；该流程只本地转换为 Codex ChatGPT 登录结构的实验 `auth.json`（`auth_mode = chatgpt`、`tokens.id_token/access_token/refresh_token/account_id`）并加密入库，不主动刷新 token，应用后由用户测试 Codex App 是否识别。
4. 切换：用户点击列表中的某条档案 → 弹出确认对话框；若未启用本地中转，按钮显示“切换”，自动把当前 `~/.codex/config.toml` 与 `~/.codex/auth.json` DPAPI 加密备份到 `Backups\<别名>_<时间戳>.bak.dpapi` → 解密目标档案并覆盖 `~/.codex` → 设置 `IsActive` → 写 `active.json` → 状态文本提示用户重启 Codex；若已启用本地中转，按钮显示“本地切换”，先测试目标 NewAPI，测试通过后只切换本地中转上游，通常不覆盖 `~/.codex`、无需重启；如果检测到当前 Codex 配置已被手动还原、不再固定到 `mytools_local_relay`，则自动备份并修复 `~/.codex/config.toml`，并提示重启 Codex App。
5. 刷新：用户在 Codex CLI 重新登录该账号后，点击对应档案的“刷新” → 工具重新读取 `~/.codex` 并覆盖该档案的 token，更新最后导入时间与过期时间。
6. 复制：用户点击某条档案的“复制” → 工具解密原档案中的 `config.toml` 与 `auth.json` → 使用当前 Windows 用户 DPAPI 重新加密写成一条新档案；新档案名称自动追加 `_复制` 并查重，不设为激活，不继承中转测试结果，默认不加入轮换池，也不覆盖当前 `~/.codex`。
7. 应用到所有：用户点击某条档案的“应用到所有” → 工具先确认模板 `config.toml` 存在 `base_url = ...` 行 → 弹出确认框 → 将当前档案库 DPAPI 加密备份为 `Backups\profiles_config_sync_<模板名>_<时间戳>.profiles.dpapi` → 以该档案的 `config.toml` 作为模板同步到其他档案；每个目标档案保留自身原有 `base_url = ...` 行，只覆盖除此之外的配置内容；不修改 `auth.json`、别名、备注、轮换设置，也不立即覆盖当前 `~/.codex`。
8. 删除：列表中点击“删除”需经过二次 `MessageBox` 确认后才从档案库移除，硬删除（除非已用加密导出包备份）。
9. 改名 / 备注：弹出输入框，新别名查重，备注最多 200 字。
10. 回滚：从 `Backups/` 目录找最新一份 `.bak.dpapi` 解密写回 `~/.codex`，用于切换出错时一键恢复。
11. 加密导出包：用户输入两次一致的口令 → 导出前在内存中解开当前用户 DPAPI 档案内容，写入便携载荷 → PBKDF2-HMAC-SHA256（盐 16 字节、迭代 200000）派生 64 字节 → 前 32 字节 AES-256-CBC + PKCS7 加密便携载荷，后 32 字节 HMAC-SHA256 覆盖文件头到 ciphertext 末尾的全部字节 → 输出 `.codexbox` 单文件，文件头 ASCII `CDXB`。
12. 加密导入包：在另一台电脑或同台机器另一个 Windows 用户下，用户输入相同口令 → 验证 HMAC（定时比较）→ AES-CBC 解密 → 将便携载荷用当前 Windows 用户 DPAPI 重新加密入库 → 与现有库合并；按别名冲突时弹出“跳过 / 覆盖 / 重命名”选择。旧版 `.codexbox` 若仍包含源 Windows 用户 DPAPI 密文，则需在源用户下用新版重新导出。
13. `Status` 标签由 `LoadCodexProfilesAsync()` 完成后、刷新、复制、加密包导入合并后自动重算，不提供独立按钮。
14. 测试中转：用户点击顶部“测试中转”后，工具逐条解密档案内的 `config.toml` 与 `auth.json`，解析 `base_url`、`model`、`wire_api`、`requires_openai_auth`、`env_key` / `api_key` / `OPENAI_API_KEY` 或 token，并对对应中转发起一次最小化在线探测；有 `model` 时优先按 `wire_api` 测试 `/responses` 或 `/chat/completions`，并自动追加 `/v1/...` 回退路径；没有 `model` 时测试 `/models`；如果档案使用 `requires_openai_auth = true` 且没有普通 API key，则只验证中转网关可达与配置完整性。测试结果保存为“可用 / 不可用 / 未知 / 测试中”、测试时间和 160 字以内摘要，列表用绿灯 / 红灯 / 灰灯展示，不记录 token 或响应正文；点击“立即轮换”或在本地中转模式下点击档案“切换”时，也会对目标档案执行同一套中转测试，测试失败则停止轮换，不备份、不覆盖当前 `~/.codex`。
15. 启动本地中转：用户点击顶部“启动本地中转”后，工具读取当前 `~/.codex` 或已保存的本地 relay 设置，保存真实上游 `base_url` 与 key 到 `%LOCALAPPDATA%\MyTools\Codex\LocalRelay\local-relay.json`（key 使用 DPAPI 加密），拉起 `MyTools.exe --codex-local-relay`，并以完整 `/health` 响应确认本地 relay 是否可达，再通过 `http://127.0.0.1:<port>/v1` 发起一次当前 NewAPI 探测；探测成功时面板 relay 灯号变绿，失败变红，过程中为黄色，不会修改 `~/.codex/config.toml`。
16. 停止使用本地中转：用户点击顶部“停止使用本地中转”后，工具把 `%LOCALAPPDATA%\MyTools\Codex\LocalRelay\local-relay.json` 标记为 `Enabled=false`，请求隐藏 relay 退出，并立即把所有档案行主按钮从“本地切换”恢复为“切换”；后续点击档案会走普通切换流程。
17. 重启 Codex 使用中转：只有 relay 灯号为绿色时，“重启 Codex 使用中转”按钮才可用；点击后工具才把当前 `~/.codex/config.toml` 固定到 `[model_providers.mytools_local_relay]` 与 `auth.command` helper，随后温和重启 Codex App。
18. 多机维度：每台电脑各自维护一份本地档案库，DPAPI 密钥与机器 + 当前 Windows 用户绑定，互不互通；跨机迁移走加密导出包流程。

- 严禁存储 OpenAI 账号密码；UI 不出现“请输入账号密码”字样；不内置 Selenium、Puppeteer、headless 浏览器或任何模拟登录逻辑。CPA Token 导入仅用于用户自有 token 的本地实验档案生成，不访问远程刷新接口。
- 除用户主动点击“测试中转”按钮、点击“启动本地中转”测试当前 NewAPI、点击“立即轮换”触发目标档案轮换前测试，或在本地中转模式下点击档案“切换”触发目标上游测试外，严禁向远程服务器发起请求；过期判断完全本地基于 `access_token` JWT `exp` 字段。
- 档案库与备份文件统一存 `%LOCALAPPDATA%\MyTools\Codex\`，禁止默认放到 OneDrive、Documents、Desktop、`%APPDATA%\Roaming\` 等可能被云同步或漫游的目录；如检测到 LocalAppData 被云同步，状态栏会提示警告。
- 加密策略仅依赖 .NET Framework 4.8 BCL：DPAPI 用于本地档案库与备份；导出包用 PBKDF2-HMAC-SHA256 + AES-256-CBC + HMAC-SHA256 EtM；不引入 BouncyCastle、AesGcm、Sodium 任一加密类 NuGet 包。
- 本地中转的上游 key、本地 auth.command token 文件均使用 DPAPI 当前用户范围加密；生成的 PowerShell helper 只包含解密读取逻辑和 token 文件路径参数，不写入真实上游 key。
- 解密前必须先 HMAC 定时比较验证，不一致一律报“口令错误或文件损坏”，禁止“打开了部分文件”之类提示。
- 日志只记别名、时间戳、备份路径、操作计数；严禁记录 `access_token` / `refresh_token` / `id_token` / 口令 / 完整邮箱本地部分；单条日志 ≤ 1 KB；异常仅记 `ex.GetType().Name + ex.Message`，不输出含 token 的 `ex.ToString()`。
- 删除与切换均需二次确认（`MessageBox.OKCancel`），避免误操作。
- DPAPI 与机器 + 当前 Windows 用户绑定，重装系统、换电脑、换 Windows 用户都会让本地档案库无法解密；跨机器迁移必须使用加密导出包。
- 如果 `auth.json` 字段命名 OpenAI 后续变化（snake_case 与 camelCase 都尝试），解析失败仅返回 null，UI 显示“未知”状态，不崩溃。
- 不规避 OpenAI 服务端的“在 X 设备上登录”邮件提示与设备指纹；用户在两台电脑频繁切换同账号触发该提示属正常风控行为，工具不参与处理。

### Codex 账号轮换

支持多个 Codex 账号之间的手动一键切换。普通轮换会写入 `~/.codex/auth.json` 与 `~/.codex/config.toml`，当前已运行的 Codex App 后端不会稳定热加载登录态，通常需完全退出并重新打开 Codex App 后生效。面板提供"重启 Codex"辅助动作：先请求 Codex 主窗口正常关闭，等待主进程退出后再从开始菜单 AppID 重新打开；已保存的对话历史通常会保留，正在生成中的回复或命令会被中断。本机 Codex 26.602.4764.0 复核结果：Windows 上 `codex app-server daemon` 生命周期命令仍提示仅支持 Unix，当前桌面 App 也没有公开的 reload auth/config 控制入口；因此本地中转采用两步：先点击“启动本地中转”启动 relay 并经本地 relay 测试当前 NewAPI，灯号为绿色后才能点击“重启 Codex 使用中转”把 `~/.codex/config.toml` 改成 MyTools 固定本地 provider 并重启一次，同时把 `disable_response_storage` 固定为 `false` 以保留 Responses API 续接状态；之后不同 NewAPI `base_url` 与 key 的切换只更新本地中转上游，通常无需再次重启。

#### 核心逻辑

1. 每个账号档案新增"加入轮换"开关和"优先级"数字属性；勾选后该账号进入轮换池，默认不参与轮换。
2. 轮换池按 RotationPriority ASC + LastAppliedAt ASC 排序；数字越小越先被选中，相同优先级下最后使用的账号优先。
3. 点击"立即轮换"：从当前激活账号的下一个开始，按轮换池顺序切换到下一个可用账号。
4. 点击"立即轮换"后，先对即将轮到的目标档案执行一次中转测试；测试不通过时将目标灯号标为“不可用”，状态文本提示停止原因，不备份、不覆盖当前 `~/.codex`。
5. 目标中转测试通过后，若已启用本地中转，则只更新 `%LOCALAPPDATA%\MyTools\Codex\LocalRelay\local-relay.json` 中的上游 `base_url` 和 DPAPI 加密 key，更新 `active.json` 与最近轮换时间，正常情况下不覆盖 `~/.codex`、不提示重启；如果当前 Codex 配置不再指向本地 relay，则会先备份并修复固定本地 provider，再提示重启；隐藏后台 relay 每次请求前读取最新设置，因此 MyTools 主窗口关闭后仍可继续转发；若未启用本地中转，则自动备份当前 `~/.codex` 到 `Backups/`，随后覆盖写入目标账号的 `auth.json` 与 `config.toml`。
6. 切换后显示托盘气泡通知（可关闭），提示 From → To；本地中转模式提示“下一次请求使用新上游”，普通写配置模式提醒重启 Codex App 后生效。
7. 普通写配置轮换成功后可选择立即温和重启 Codex App；也可在面板顶部点击"重启 Codex"单独执行。
8. 点击“启动本地中转”后，若本机尚未保存本地中转设置，工具读取当前 `~/.codex`，解析当前 `base_url` 与 token，把真实上游 key 使用 DPAPI 当前用户范围加密写入 `%LOCALAPPDATA%\MyTools\Codex\LocalRelay\local-relay.json`，生成本地 auth.command token 文件和 `ReadCodexLocalRelayToken.ps1`，并拉起隐藏后台 relay；随后工具使用本地 relay 对当前 NewAPI 做最小探测，绿灯代表可达、红灯代表不可达，且这一步不修改当前 `~/.codex/config.toml`。
9. 只有 relay 灯号为绿色时，“重启 Codex 使用中转”按钮才可用；点击后工具才把当前 `config.toml` 切到 `[model_providers.mytools_local_relay]`，并把根级 `disable_response_storage` 设为 `false`，再温和重启 Codex App。若本机已保存本地中转设置且当前 Codex 已固定到 relay，则启动检测会复用 MyTools 自身的 DPAPI 上游配置，不依赖当前 `~/.codex` 中仍保留上游 key；若旧配置仍关闭 response storage，则会备份并修复后提示重启。
10. 点击“停止使用本地中转”后，工具禁用本地 relay 设置，请求隐藏 relay 退出，并把面板状态切回普通模式；所有档案卡片主按钮立即从“本地切换”恢复为“切换”，后续切换会重新备份并覆盖 `~/.codex`。
11. 本地中转启用后，“立即轮换”和档案卡片“切换”会在目标中转测试通过后切换上游；如果目标档案解析不到 token，或 `wire_api` 与当前本地 provider 不一致，则停止并提示，避免让 Codex 继续使用不兼容路径。
12. 面板顶部提供“全选轮换”和“反选轮换”按钮：全选会把当前档案库所有档案加入轮换池；反选会逐条取反 `EnableRotation`，并一次性保存档案库。
13. 档案卡片提供“复制”按钮：复制当前档案的加密配置内容为新记录，自动生成唯一名称，新记录不设为激活、不继承中转测试结果、默认不加入轮换池。
14. "立即轮换"按钮在轮换池不足 2 个可用账号时自动禁用。
15. 过期提醒：Codex 配置页加载档案后，面板顶部汇总“已过期 / 即将过期”数量；单个档案在状态标签旁显示“即将过期”或“已过期，请刷新后再轮换”，提醒字段只由 `AccessTokenExpiresAt` 与 `Status` 计算，不写入额外持久化字段。
16. 429 自动热轮换：Codex 配置页加载成功后，后台监控 `%USERPROFILE%\.codex\logs_2.sqlite` 的 `logs` 表；首次只读取 `MAX(id)` 作为基线，之后每 20 秒只读增量最多 50 行，识别 `target = codex.rate_limits` 或等价 rate-limit 日志中的 `allowed=false` / `limit_reached=true`，提取 `reset_after_seconds` 后复用轮换池尝试切到下一个账号。自动路径只允许本地中转或 hot-token 热切换，禁止后台自动覆盖 `~/.codex` 或自动重启 Codex，避免打断正在进行的会话。
