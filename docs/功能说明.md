## 1. WireGuard 连接功能

### 功能概述
在 MyTools 中提供 WireGuard 连接管理，支持输入配置内容、生成基础配置，并控制连接与断开。

### 核心逻辑
- 使用 `WireGuardService` 查找本地或系统安装目录中的 `wireguard.exe`。
- 支持点击“导入配置”选择 `.conf` 文件，自动回填配置内容，并用文件名作为默认接口名。
- 连接时把配置写入程序目录下的 `Configs` 子目录，再调用 `/installtunnelservice`。
- 断开时调用 `/uninstalltunnelservice`。
- 通过网卡状态检测当前接口是否已连接。
- 页面顶部提供连接日志按钮，可展开最近 80 条导入、连接、断开和状态检查记录。
- 连接/断开会显示本次耗时；连接成功后显示最近连接时间，便于判断授权或网卡上线耗时。
- 页面会扫描程序同级 `Configs/*.conf`，展示已保存隧道列表；每条隧道支持加载、差异预览、导出、重命名和删除本地 `.conf` 文件。
- 差异预览会比较保存文件与当前编辑区配置的行数、大小和不同位置数量；导出会把单个 `.conf` 另存到用户指定位置。
- 导入配置或连接成功后会刷新隧道列表，保持当前配置与落盘配置一致。

### 涉及文件
- `src/MyTools/Services/WireGuardService.cs`
- `src/MyTools/ViewModels/MainViewModel.cs`
- `src/MyTools/MainWindow.xaml`

## 2. 系统托盘与最小化到托盘

### 功能概述
点击窗口关闭按钮时，程序不直接退出，而是隐藏到系统托盘，方便后台驻留。

### 核心逻辑
- 使用 `Hardcodet.NotifyIcon.Wpf` 提供托盘图标和右键菜单。
- 重写 `MainWindow.OnClosing`，只有在明确退出时才真正关闭程序。
- 托盘支持双击恢复主窗口，以及“显示窗口 / 退出程序”菜单项。

### 涉及文件
- `src/MyTools/MainWindow.xaml`
- `src/MyTools/MainWindow.xaml.cs`
- `src/MyTools/ViewModels/MainViewModel.cs`

## 3. 启动稳定性修复

### 问题根因
托盘图标最初使用 `DrawingImage`。`Hardcodet.NotifyIcon.Wpf` 在启动解析 XAML 时会尝试把该对象转换为托盘 `Icon`，从而触发 `System.UriFormatException`，最终包装成 `XamlParseException`，导致程序启动后立即退出。

### 修复方案
- 托盘图标改为使用内置位图资源 `Resources/AppIcon.png`。
- `App.xaml` 去掉 `StartupUri`，改由 `App.xaml.cs` 显式创建 `MainWindow`。
- 启动链路增加全局异常处理和启动日志，避免再次出现“闪退但没有提示”。

### 诊断方式
- 启动失败时，在程序同目录生成 `MyTools.startup.log`。
- 同时弹出错误提示框，向用户展示异常类型和日志位置。

- `src/MyTools/App.xaml`
- `src/MyTools/App.xaml.cs`

## 4. SQL Server 表导出 Excel

### 功能概述
在 MyTools 中新增 SQL 导出模块，支持通过 SQL Server 账号密码连接局域网中的任意 SQL Server 实例，选择可访问的数据库和用户表，并将整张表导出为 `.xlsx` 文件。

### 核心逻辑
- 使用 `System.Data.SqlClient` 进行异步连接与查询，仅支持 SQL Server 身份验证。
- 连接成功后读取当前账号可访问的数据库列表；若旧版 SQL Server 不支持 `sys.databases`，自动降级使用 `sp_databases` 枚举，再按所选数据库加载 `schema.table` 形式的用户表列表。
- 服务器地址、用户名和密码支持本地历史记录，下次打开自动回填最后一次成功连接信息；密码使用 Windows 当前用户 DPAPI 加密后保存。
- 数据表选择框支持输入关键字即时筛选，输入 `w` 时仅展示表名或架构名中包含 `w` 的候选表。
- 数据库名、架构名和表名全部来自程序加载出的白名单列表，导出时统一使用安全的方括号转义，不执行用户自定义 SQL。
- 导出前先读取总行数；若超过 Excel 单工作表上限 `1,048,576` 行，则阻止导出并提示用户。
- 通过内置的轻量 `.xlsx` 写入器直接生成 OpenXML 工作簿，不依赖本机安装 Office，也不额外引入重量级 Excel 组件。
- 导出、连接、读取元数据等关键步骤都会写入应用日志，但不会记录密码或完整连接字符串。

## 5. 截图快捷键与长期运行稳定性修复

### 功能概述
修复全局截图快捷键设置后按键无响应的问题，并降低程序长期驻留后对系统流畅度的影响。

### 核心逻辑
- 截图在后台线程完成后冻结 `BitmapSource`，允许安全回到 UI 线程写入剪贴板或打开编辑器。
- 截图失败时恢复主窗口并弹窗提示，避免窗口被隐藏后无法找回。
- 截图编辑器关闭时释放大图引用、标注集合与事件订阅，减少多次截图后的内存占用。
- 截图编辑器默认按工作区自动居中适配显示（等比缩放），并提供 `10%~300%` 缩放滑块和鼠标滚轮缩放；手动缩放时以当前视口中心为基准扩展，显示缩放不影响最终导出分辨率。
- “编辑剪贴板截图”读取剪贴板图片时带短重试与异常兜底，遇到无效剪贴板数据会提示重新复制，不再触发全局崩溃弹窗。
- 单实例激活监听改为事件等待，避免后台线程固定轮询。
- 主窗口关闭时解除热键 Hook、注销全局热键并释放托盘图标资源。

## 6. Codex 配置文件夹应用

### 功能概述
支持把包含 `config.toml` 和 `auth.json` 的文件夹拖入主窗口，自动生成 Codex 配置记录，并可一键应用到当前用户的 `%userprofile%\.codex` 目录。

### 核心逻辑
- 主窗口接收文件夹拖拽，按文件夹名称生成一条记录。
- 记录名称默认取文件夹名；备注和标签可在列表中修改，标签用于按账号、代理或模型用途归类。
- 导入或拖入后会用 DPAPI 保存 `config.toml` 与 `auth.json` 内容，来源目录仅作为提示与回退。
- 点击“差异”可预览该记录与当前 `%userprofile%\.codex` 目录中两份配置文件的存在状态、大小和行级差异数量。
- 点击“应用”后，将记录内容覆盖写入 `%userprofile%\.codex\config.toml` 和 `%userprofile%\.codex\auth.json`；目标目录或目标文件不存在时自动创建。
- 应用成功后记录最近应用时间，配置列表按最近应用优先显示。
- 配置记录保存在程序同目录的 `MyTools.settings.json` 中，敏感文件内容以 DPAPI 加密后的 Base64 存储。

### 涉及文件
- `src/MyTools/Services/AppSettingsService.cs`
- `src/MyTools/Services/CodexConfigProfileService.cs`
- `src/MyTools/ViewModels/MainViewModel.cs`
- `src/MyTools/MainWindow.xaml`

## 7. 自动优化与报告

### 功能概述
在“系统优化与增强”面板新增自动优化卡片，按白名单顺序执行临时文件清理、DNS 刷新、字体缓存重置、Windows Update 缓存清理、系统盘 TRIM/碎片整理、回收站清空等操作，并生成本地优化报告。

### 操作步骤
- 点击“开始自动优化”，按提示决定是否允许临时重启资源管理器以清理缩略图缓存。
- 等待进度文字完成；完成后报告会插入报告列表。
- 在报告列表中勾选条目后点击“删除选中”，确认后会同步删除磁盘报告 JSON 与索引。

### 白名单与限制
- 只执行说明书列出的 10 项优化步骤；不会运行 `sfc`、`DISM RestoreHealth`、`chkdsk /f` 等耗时或重启类命令。
- 需要管理员权限的步骤通过临时 PowerShell 脚本 + UAC 执行；用户取消 UAC 时对应步骤标记失败，不会反复弹窗。
- 报告保存在 `%LOCALAPPDATA%\MyTools\OptimizationReports\`。

## 8. 垃圾清理

### 功能概述
垃圾清理卡片会扫描预定义白名单路径，展示候选项、类别和体积，用户确认后才执行删除，并把结果写入优化报告列表。

### 白名单范围
- 用户临时目录、系统临时目录、回收站、Edge/Chrome 默认缓存、缩略图缓存、30 天前 Prefetch、Windows Update 下载缓存、Delivery Optimization 缓存、`Package Cache` 空目录。
- 删除前会使用完整路径白名单校验，禁止进入 `Documents`、`Desktop`、`Pictures`、`Downloads`、`Program Files*`、`System32`、`WinSxS` 等目录。
- 扫描结果表格展示大小、风险和建议，帮助用户判断是否需要关闭浏览器、授权管理员权限或先确认回收站内容。
- 可在执行清理前导出 `.txt` 预检报告，报告包含已选择项、预计释放空间、风险分布、建议和完整路径。
- 普通文件优先发送到回收站；系统缓存仍经过白名单校验和管理员授权流程。

## 8a. 程序卸载

### 功能概述
“程序卸载”模块列出 Windows 注册表中提供卸载命令的程序，并允许用户从列表中启动对应软件自带的卸载程序。

### 核心逻辑
- 读取 `HKCU/HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Uninstall` 与 `HKLM\SOFTWARE\WOW6432Node\Microsoft\Windows\CurrentVersion\Uninstall`。
- 仅显示同时具有 `DisplayName` 与 `UninstallString` 的条目，过滤系统组件与明确禁止移除的条目。
- 列表展示程序名、版本、发布者、安装日期、估算大小、来源与安装位置。
- 顶部搜索框支持按程序名、发布者、版本、安装路径和来源实时筛选，并显示筛选数量。
- 顶部下拉框支持按名称、安装日期、估算大小和发布者排序；支持按未知大小、小于 100 MB、100 MB - 1 GB、大于 1 GB 过滤，也支持按未知日期、最近 30 天、最近 90 天、最近 1 年过滤。
- 列表支持勾选多个程序，可一键选择当前筛选结果、清除选择，并导出已选择程序清单；未勾选时导出当前筛选结果。
- 点击卸载前弹出确认框，展示发布者、版本、安装位置、来源、权限提示和完整卸载命令；确认后仅启动原软件提供的卸载命令，不静默删除任何目录或注册表项。
- 对 `msiexec /I ...` 卸载命令自动转换为交互式 `msiexec /X ...`。
- 列表会检测静默卸载候选：优先识别注册表 `QuietUninstallString`，也会标记 MSI 或已带常见静默参数的卸载命令。
- 静默候选仅作为人工判断信息展示和导出，默认仍只启动软件自带的交互卸载向导，不做批量自动静默卸载。

### 涉及文件
- `src/MyTools/Services/InstalledProgramService.cs`
- `src/MyTools/ViewModels/MainViewModel.cs`
- `src/MyTools/MainWindow.xaml`

## 8b. 启动项管理

### 功能概述
“启动项管理”模块列出 Windows 开机启动项，支持查看、搜索、启用、禁用和删除。

### 核心逻辑
- 读取当前用户与所有用户的 `Run` 注册表项，并读取 MyTools 自己保存的禁用启动项备份项。
- 列表展示启动项名称、发布者、识别出的可执行路径、原始命令、来源分类、启用状态、文件存在性和数字签名状态。
- 来源分类会区分 `注册表 Run` 与 `MyTools 禁用备份`，并同时显示当前用户或所有用户范围。
- 启动命令会保守解析常见 `.exe/.bat/.cmd/.com/.ps1` 路径，读取文件版本信息中的公司名作为发布者；文件缺失时保留疑似路径并显示“文件不存在”，解析不到时显示“未知发布者/未识别路径”。
- 文件存在时会读取 Authenticode 签名证书，显示“已签名/未签名”；已签名项的悬浮提示会显示证书主体。
- 已签名文件会使用 `X509Chain` 做本机证书链可信校验，并在启动项卡片中显示“证书链可信 / 不可信或已过期 / 未校验”。
- 搜索框支持按名称、发布者、可执行路径、命令、来源分类、位置、文件状态、签名状态和证书链状态实时筛选；空状态会提示清空搜索或重新刷新。
- 禁用启动项时将原值移动到备份项，启用时移动回 `Run`；删除操作会从当前所在注册表项删除。

### 涉及文件
- `src/MyTools/Services/StartupService.cs`
- `src/MyTools/ViewModels/MainViewModel.cs`
- `src/MyTools/MainWindow.xaml`

## 9. 微信清理

### 功能概述
微信清理卡片按“开始日期 ~ 结束日期”和类别扫描微信文件数据，只按文件 `LastWriteTime` 过滤，不读取消息数据库。

### 操作步骤
- 选择微信账号、日期范围和类别后点击“扫描”。
- 扫描列表展示类别、时间、大小、风险、建议和路径；图像、视频、语音、文件类会提示“按日期确认，建议先备份”。
- 检查列表中的候选文件，点击“开始清理”并二次确认。

### 限制
- 不自动结束微信进程；建议先关闭微信再清理。
- 禁止触碰 `Msg*.db`、`MicroMsg.db`、`MMKV/`、`config/`、`Login.dat`、`SafeStorage*` 等登录态或消息库文件。

## 10. 微信备份与恢复

### 微信备份
- 在微信备份卡片选择账号、日期、类别和保存目录后点击“开始备份”。
- 输出单个 `WeChatBackup_yyyyMMdd-HHmmss_start_end.zip`，内部包含 `WeChatBackup/manifest.json` 和 `files/` 文件目录。
- `manifest.json` 记录相对路径、大小、修改时间和 SHA256；不会记录聊天文本或文件内容。
- 备份完成后会保存到最近备份列表，最多保留 6 条，记录备份文件路径、最近使用时间、文件数和总大小。

### 微信恢复
- 选择备份 ZIP 后自动解析 `manifest.json` 并展示版本、wxId、日期范围、类别、条目数和总大小。
- 新备份的 `manifest.json` 会在每个条目记录类别；旧备份未记录类别时会按相对路径尽量推断图像、视频、语音、文件、缓存或文字。
- 恢复区展示最近备份快捷入口，点击后会自动套用 ZIP 并解析 manifest，便于快速恢复刚生成或最近使用的备份。
- 恢复前可勾选文字、图像、视频、语音、其它文件和缓存，未勾选类别会跳过，不写入目标目录。
- 可恢复到原微信目录，也可选择自定义目录。
- 同名文件不会覆盖，会改名为 `.restored-{ticks}`；恢复时防护 zip slip，并再次阻止写入消息库/登录态相关路径。

## 11. Codex 配置导入/导出

### 入口
- 左侧导航进入“Codex 配置”面板。
- 顶部提供“导入”按钮；每条记录右侧提供“差异 / config.toml / auth.json / 应用 / 导出 / 删除”按钮。

### 操作步骤
- 导入：点击“导入”并同时选择同一目录下的 `config.toml` 与 `auth.json`，输入记录名后保存。
- 导入保存前会显示脱敏摘要：`config.toml` 只展示常用键与已脱敏的敏感值，`auth.json` 使用 JSON 结构读取后只展示字段路径和类型，不显示 token、key、secret 等明文。
- 导出：在目标记录点击“导出”，选择父目录后自动创建子目录并写出 `config.toml`、`auth.json`。
- 编辑：点击 `config.toml` 或 `auth.json` 可直接查看和修改该记录内嵌内容。
- 差异：点击“差异”可查看记录内容与当前用户 `.codex` 目录的差异摘要。
- 应用：点击“应用”将记录内容写入 `%USERPROFILE%\\.codex`。

### 依赖
- 本地文件系统读写。
- Windows DPAPI（用于记录内嵌内容的加密存储）。

### 限制
- 导入时必须同时选择两个文件，且必须来自同一文件夹。
- 仅导出已成功保存内嵌内容的记录；缺少内容会提示并终止。
- 标签、备注和最近应用时间随本地设置保存。

## 12. SQL 导出多数据库支持

### 入口
- 左侧导航进入“SQL 多数据库工具”面板。
- 顶部可选择数据库类型：`SQL Server / PostgreSQL / MySQL`。

### 操作步骤
- 选择数据库类型并填写地址、端口、用户名、密码，点击“测试连接”。
- 测试连接成功后会保存最近连接组合；后续可点击“最近连接”卡片快速回填服务器、端口、用户名和密码，再重新测试连接。
- 连接成功后选择数据库和数据表，点击“导出为 Excel”。
- 在“SQL 查询”页执行查询后可导出结果为 `.xlsx` 或 `.csv`，也可复制选中单元格/行；未选择时复制全部查询结果。

## 13. 截图区域录像

### 入口
- 左侧导航进入“截图工具”面板，点击“开启录像”。

### 操作步骤
- 首次使用会要求选择录像保存目录（仅首设）。
- 截图工具页会显示当前录像保存目录，可随时点击“更改”重新选择。
- 主窗口隐藏后弹出可拖拽/可调大小的录制区域窗口。
- 点击右上角圆形按钮后先显示 3 秒倒计时，倒计时结束后开始录像。
- 录像中区域窗口右上角显示“录制中 mm:ss / h:mm:ss”，再次点击停止并保存为 `.mp4`。
- 可在“截图行为”卡片切换 GIF 录制模式；GIF 模式输出 `.gif`，不录声音，适合短操作演示。
- “截图行为”卡片可选择录像帧率（15/30/60 FPS）和 MP4 画质（体积优先/均衡/高清）；GIF 模式会使用不超过 15 FPS 的帧率以控制体积。
- 停止后会校验目标 `.mp4` 是否真实存在且大于 0 字节；保存成功后自动打开资源管理器并定位该文件。

### 依赖
- 优先使用程序目录下的 `NativeBinaries\\ffmpeg\\ffmpeg.exe`；也支持系统 PATH 中的 `ffmpeg.exe`。
- `ffmpeg.exe` 需要手动放置或手动安装，不自动下载。
- 倒计时发生在真正启动 ffmpeg 之前，倒计时期间关闭区域窗口不会产生空录像文件。
- 画面由 ffmpeg `gdigrab` 录制为 H.264；系统声音由程序内置 WASAPI Loopback 采集为临时 WAV，停止后自动合成为 `H.264 + AAC + MP4`。
- GIF 模式使用 `gdigrab + palettegen/paletteuse` 输出动图，不启动 WASAPI 音频采集。
- 启动后会短暂探测 ffmpeg 是否立即退出，避免把启动失败误显示为“录像中”。
- 录制区域宽高会在启动前自动向下修正为偶数像素，避免 `libx264 + yuv420p` 因奇数尺寸启动失败。

### 限制
- 不依赖 `virtual-audio-capturer`、`Stereo Mix`、`立体声混音` 或麦克风设备；需要 Windows 默认播放设备可用。
- 如果 WASAPI 系统声音采集不可用、采集为空或合成失败，录像仍会保存画面，并在保存提示中标明“仅画面”。
- 录像与录音互斥，同一时刻只允许一个 ffmpeg 任务运行。

## 17. 文件哈希校验

### 功能概述
在截图工具页与文件验证页提供文件哈希校验，选择文件或拖入文件后异步计算 MD5、SHA-1、SHA-256、CRC32，结果以等宽字体展示，点击可复制到剪贴板。文件验证页支持一次选择或拖入多个文件生成批量校验表，可导出 `.txt` 校验清单，也可导入 MyTools 或常见格式校验清单进行批量比对。用户可粘贴官方下载页提供的校验值，程序会自动识别 CRC32 / MD5 / SHA-1 / SHA-256 并显示匹配或不匹配。

### 核心逻辑
- `FileHashService.ComputeAsync` 单遍读取文件，同时更新 MD5、SHA-1、SHA-256 与 CRC32，支持 `IProgress<string>` 进度回调和 `CancellationToken`。
- 文件通过 1 MB 缓冲区流式读取，每读取 16 MB 报告一次进度，支持大文件。
- 截图工具页与文件验证页共用同一份结果格式化逻辑，结果格式化为 `文件名（大小）\nMD5\nSHA-1\nSHA-256\nCRC32`；文件验证页额外显示完整路径。
- 文件验证页多选文件时逐个计算并写入批量结果表；可按 MD5 / SHA-1 / SHA-256 / CRC32 一键复制“文件名 + 校验值”列，也可导出 UTF-8 校验清单保存完整路径与四种校验值。
- 支持导入 MyTools 导出的校验清单，以及常见 `hash 文件名` / `文件名 hash` 文本行；导入后会对当前批量结果标注匹配、不匹配或未找到。
- `MainViewModel.ExpectedFileHash` 接收用户粘贴的官方校验值，支持粘贴 `SHA256: xxxxx`、纯哈希、带空格/换行的文本；仅接受 8/32/40/64 位十六进制值，避免误判。

## 17a. 格式转换

### 功能概述
格式转换模块提供图片格式转换与音视频格式转换：图片转换使用本地 `System.Drawing`，音视频转换调用 `ffmpeg.exe`。

### 核心逻辑
- 页面改为左右双列紧凑布局：左侧图片转换，右侧音视频转换；转换结果在底部单独显示。

- 批量转换会生成队列表格，逐项展示类型、文件名、状态、输出路径和错误消息。
- 队列表格支持逐项打开输出位置、复制消息、重试、移除、上移、下移，并可在转换空闲时拖拽排序或一键清空；批量转换会按当前队列顺序执行。

- 转换输出文件命名为 `{原文件名}_converted.{扩展名}`；若同名文件已存在，自动改为 `{原文件名}_converted_2.{扩展名}` 等，避免覆盖已有文件。
- `ffmpeg -version` 探测与实际转换均会排空 stdout/stderr，降低外部进程输出阻塞风险；转换超时或取消时会尝试结束子进程。
- 转换完成后汇总成功/失败数量；单文件成功时“打开位置”会直接选中新文件，多文件成功时会打开输出目录。

## 19. 安装程序打包

### 功能概述
通过仓库内置的 .NET Framework 4.8 安装器工程生成单个 `MyToolsSetup.exe`，安装程序内嵌 Release 产物与卸载器，不依赖 Inno Setup、NSIS 或 WiX 等外部打包工具。

### 核心逻辑
- `scripts/Build-Installer.ps1` 先构建主程序与卸载器，再按白名单复制发布文件到临时 payload 目录，压缩为 `MyToolsPayload.zip` 后嵌入安装程序。
- 默认安装路径为 `%ProgramFiles%\AjunTools\MyTools`，安装时写入 `HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Uninstall\MyTools`，用于 Windows“程序和功能”卸载入口。
- 安装前检查旧版：优先扫描 HKLM/HKCU 的 32/64 位卸载注册表视图；如果发现 `MyTools` 或“阿君的工具”卸载项，则先静默运行旧卸载程序，退出码为 0 后才继续安装。
- 如果目标目录已有旧版卸载器但注册表缺失，也会先调用该卸载器；如果是更早期的手工复制版本，则停止正在运行的 `MyTools.exe` 并清理已知程序文件后再覆盖安装。
- 卸载器只删除程序文件、卸载注册表项和开始菜单快捷方式；默认保留安装目录中的用户配置、日志与历史数据。只有显式传入 `/purge-data` 才删除整个安装目录。
- 打包脚本对主程序、卸载器、安装器三次 `dotnet build` 均检查退出码，任一步失败立即停止，不继续压缩或复制旧产物。
- 安装完成前可选择将常见音视频扩展名关联到 MyTools；静默安装可传入 `/associate-media` 强制关联全部，也可传入 `/associate-video` 或 `/associate-audio` 只关联视频或音频。
- 程序内“系统设置”页显示视频/音频当前关联状态，可刷新检测当前默认打开数量和 OpenWith 注册数量。
- 程序内“系统设置”页提供“视频 / 音频 / 全部”三个关联按钮，可在安装后按范围重新写入当前用户文件关联。
- 程序内“系统设置”页提供“恢复默认”按钮，会移除当前用户下 MyTools 写入的音视频关联；Windows 可能恢复原默认程序，无法判断时会在下次打开文件时提示选择默认应用。
- 程序内“系统设置”页提供“默认应用”按钮：Win10/11 打开 `ms-settings:defaultapps`，Win7/8 打开控制面板默认程序入口。
- 卸载时会清理 MyTools 写入的音视频文件关联、应用能力注册与 OpenWithProgids。

- 保存前会执行硬约束校验：每日实际休息必须等于总休目标，任一人员连续上班不得超过 5 天；不满足时阻止保存并列出问题。
- “开始设置休息日”只写入“白”和“休”，尊重手动格子，并在自动优化后继续校验每日精确人数和连续上班上限。
