## 1. WireGuard 连接功能

### 功能概述
在 MyTools 中提供 WireGuard 连接管理，支持输入配置内容、生成基础配置，并控制连接与断开。

### 核心逻辑
- 使用 `WireGuardService` 查找本地或系统安装目录中的 `wireguard.exe`。
- 连接时把配置写入程序目录下的 `Configs` 子目录，再调用 `/installtunnelservice`。
- 断开时调用 `/uninstalltunnelservice`。
- 通过网卡状态检测当前接口是否已连接。

### 涉及文件
- `src/MyTools/Services/WireGuardService.cs`
- `src/MyTools/ViewModels/MainViewModel.cs`
- `src/MyTools/MainWindow.xaml`

## 2. 系统托盘与最小化到托盘

### 功能概述
点击窗口关闭按钮时，程序不直接退出，而是隐藏到系统托盘，方便后台驻留。

### 核心逻辑
- 使用 `Hardcodet.NotifyIcon.Wpf` 提供托盘图标和右键菜单。
- 重写 `MainWindow.OnClosing`，只有在明确退出时才真正关闭程序。
- 托盘支持双击恢复主窗口，以及“显示窗口 / 退出程序”菜单项。

### 涉及文件
- `src/MyTools/MainWindow.xaml`
- `src/MyTools/MainWindow.xaml.cs`
- `src/MyTools/ViewModels/MainViewModel.cs`

## 3. 启动稳定性修复

### 问题根因
托盘图标最初使用 `DrawingImage`。`Hardcodet.NotifyIcon.Wpf` 在启动解析 XAML 时会尝试把该对象转换为托盘 `Icon`，从而触发 `System.UriFormatException`，最终包装成 `XamlParseException`，导致程序启动后立即退出。

### 修复方案
- 托盘图标改为使用内置位图资源 `Resources/AppIcon.png`。
- `App.xaml` 去掉 `StartupUri`，改由 `App.xaml.cs` 显式创建 `MainWindow`。
- 启动链路增加全局异常处理和启动日志，避免再次出现“闪退但没有提示”。

### 诊断方式
- 启动失败时，在程序同目录生成 `MyTools.startup.log`。
- 同时弹出错误提示框，向用户展示异常类型和日志位置。

### 涉及文件
- `src/MyTools/App.xaml`
- `src/MyTools/App.xaml.cs`
- `src/MyTools/MainWindow.xaml`

## 4. SQL Server 表导出 Excel

### 功能概述
在 MyTools 中新增 SQL 导出模块，支持通过 SQL Server 账号密码连接局域网中的任意 SQL Server 实例，选择可访问的数据库和用户表，并将整张表导出为 `.xlsx` 文件。

### 核心逻辑
- 使用 `System.Data.SqlClient` 进行异步连接与查询，仅支持 SQL Server 身份验证。
- 连接成功后读取当前账号可访问的数据库列表；若旧版 SQL Server 不支持 `sys.databases`，自动降级使用 `sp_databases` 枚举，再按所选数据库加载 `schema.table` 形式的用户表列表。
- 服务器地址、用户名和密码支持本地历史记录，下次打开自动回填最后一次成功连接信息；密码使用 Windows 当前用户 DPAPI 加密后保存。
- 数据表选择框支持输入关键字即时筛选，输入 `w` 时仅展示表名或架构名中包含 `w` 的候选表。
- 数据库名、架构名和表名全部来自程序加载出的白名单列表，导出时统一使用安全的方括号转义，不执行用户自定义 SQL。
- 导出前先读取总行数；若超过 Excel 单工作表上限 `1,048,576` 行，则阻止导出并提示用户。
- 通过内置的轻量 `.xlsx` 写入器直接生成 OpenXML 工作簿，不依赖本机安装 Office，也不额外引入重量级 Excel 组件。
- 导出、连接、读取元数据等关键步骤都会写入应用日志，但不会记录密码或完整连接字符串。

### 涉及文件
- `src/MyTools/Services/AppLogService.cs`
- `src/MyTools/Services/SqlConnectionHistoryService.cs`
- `src/MyTools/Services/SqlExportModels.cs`
- `src/MyTools/Services/SqlExportService.cs`
- `src/MyTools/ViewModels/MainViewModel.cs`
- `src/MyTools/MainWindow.xaml`
- `src/MyTools/MainWindow.xaml.cs`
- `src/MyTools/App.xaml.cs`

## 5. 截图快捷键与长期运行稳定性修复

### 功能概述
修复全局截图快捷键设置后按键无响应的问题，并降低程序长期驻留后对系统流畅度的影响。

### 核心逻辑
- 截图在后台线程完成后冻结 `BitmapSource`，允许安全回到 UI 线程写入剪贴板或打开编辑器。
- 截图失败时恢复主窗口并弹窗提示，避免窗口被隐藏后无法找回。
- 截图编辑器关闭时释放大图引用、标注集合与事件订阅，减少多次截图后的内存占用。
- 截图编辑器默认按工作区自动居中适配显示（等比缩放），并提供 `10%~300%` 缩放滑块和鼠标滚轮缩放；手动缩放时以当前视口中心为基准扩展，显示缩放不影响最终导出分辨率。
- “编辑剪贴板截图”读取剪贴板图片时带短重试与异常兜底，遇到无效剪贴板数据会提示重新复制，不再触发全局崩溃弹窗。
- 单实例激活监听改为事件等待，避免后台线程固定轮询。
- 主窗口关闭时解除热键 Hook、注销全局热键并释放托盘图标资源。

### 涉及文件
- `src/MyTools/App.xaml.cs`
- `src/MyTools/MainWindow.xaml.cs`
- `src/MyTools/Services/ScreenshotService.cs`
- `src/MyTools/ViewModels/MainViewModel.cs`
- `src/MyTools/ScreenshotEditorWindow.xaml.cs`

## 6. Codex 配置文件夹应用

### 功能概述
支持把包含 `config.toml` 和 `auth.json` 的文件夹拖入主窗口，自动生成 Codex 配置记录，并可一键应用到当前用户的 `%userprofile%\.codex` 目录。

### 核心逻辑
- 主窗口接收文件夹拖拽，按文件夹名称生成一条记录。
- 记录名称固定为文件夹名称；备注默认同名，可在列表中修改。
- 点击“应用”后，先校验源文件夹中必须同时存在 `config.toml` 与 `auth.json`。
- 校验通过后，将源文件覆盖写入 `%userprofile%\.codex\config.toml` 和 `%userprofile%\.codex\auth.json`；目标目录或目标文件不存在时自动创建。
- 配置记录保存在程序同目录的 `MyTools.settings.json` 中，仅保存名称、备注和文件夹路径，不记录文件内容。

### 涉及文件
- `src/MyTools/Services/AppSettingsService.cs`
- `src/MyTools/Services/CodexConfigProfileService.cs`
- `src/MyTools/ViewModels/MainViewModel.cs`
- `src/MyTools/MainWindow.xaml`
- `src/MyTools/MainWindow.xaml.cs`

## 7. 自动优化与报告

### 功能概述
在“系统优化与增强”面板新增自动优化卡片，按白名单顺序执行临时文件清理、DNS 刷新、字体缓存重置、Windows Update 缓存清理、系统盘 TRIM/碎片整理、回收站清空等操作，并生成本地优化报告。

### 操作步骤
- 点击“开始自动优化”，按提示决定是否允许临时重启资源管理器以清理缩略图缓存。
- 等待进度文字完成；完成后报告会插入报告列表。
- 在报告列表中勾选条目后点击“删除选中”，确认后会同步删除磁盘报告 JSON 与索引。

### 白名单与限制
- 只执行说明书列出的 10 项优化步骤；不会运行 `sfc`、`DISM RestoreHealth`、`chkdsk /f` 等耗时或重启类命令。
- 需要管理员权限的步骤通过临时 PowerShell 脚本 + UAC 执行；用户取消 UAC 时对应步骤标记失败，不会反复弹窗。
- 报告保存在 `%LOCALAPPDATA%\MyTools\OptimizationReports\`。

## 8. 垃圾清理

### 功能概述
垃圾清理卡片会扫描预定义白名单路径，展示候选项、类别和体积，用户确认后才执行删除，并把结果写入优化报告列表。

### 白名单范围
- 用户临时目录、系统临时目录、回收站、Edge/Chrome 默认缓存、缩略图缓存、30 天前 Prefetch、Windows Update 下载缓存、Delivery Optimization 缓存、`Package Cache` 空目录。
- 删除前会使用完整路径白名单校验，禁止进入 `Documents`、`Desktop`、`Pictures`、`Downloads`、`Program Files*`、`System32`、`WinSxS` 等目录。

## 8a. 程序卸载

### 功能概述
“程序卸载”模块列出 Windows 注册表中提供卸载命令的程序，并允许用户从列表中启动对应软件自带的卸载程序。

### 核心逻辑
- 读取 `HKCU/HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Uninstall` 与 `HKLM\SOFTWARE\WOW6432Node\Microsoft\Windows\CurrentVersion\Uninstall`。
- 仅显示同时具有 `DisplayName` 与 `UninstallString` 的条目，过滤系统组件与明确禁止移除的条目。
- 列表展示程序名、版本、发布者、安装日期、估算大小、来源与安装位置。
- 点击卸载前弹出确认框；确认后仅启动原软件提供的卸载命令，不静默删除任何目录或注册表项。
- 对 `msiexec /I ...` 卸载命令自动转换为交互式 `msiexec /X ...`。

### 涉及文件
- `src/MyTools/Services/InstalledProgramService.cs`
- `src/MyTools/ViewModels/MainViewModel.cs`
- `src/MyTools/MainWindow.xaml`

## 9. 微信清理

### 功能概述
微信清理卡片按“开始日期 ~ 结束日期”和类别扫描微信文件数据，只按文件 `LastWriteTime` 过滤，不读取消息数据库。

### 操作步骤
- 选择微信账号、日期范围和类别后点击“扫描”。
- 检查列表中的候选文件，点击“开始清理”并二次确认。

### 限制
- 不自动结束微信进程；建议先关闭微信再清理。
- 禁止触碰 `Msg*.db`、`MicroMsg.db`、`MMKV/`、`config/`、`Login.dat`、`SafeStorage*` 等登录态或消息库文件。

## 10. 微信备份与恢复

### 微信备份
- 在微信备份卡片选择账号、日期、类别和保存目录后点击“开始备份”。
- 输出单个 `WeChatBackup_yyyyMMdd-HHmmss_start_end.zip`，内部包含 `WeChatBackup/manifest.json` 和 `files/` 文件目录。
- `manifest.json` 记录相对路径、大小、修改时间和 SHA256；不会记录聊天文本或文件内容。

### 微信恢复
- 选择备份 ZIP 后自动解析 `manifest.json` 并展示版本、wxId、日期范围、类别、条目数和总大小。
- 可恢复到原微信目录，也可选择自定义目录。
- 同名文件不会覆盖，会改名为 `.restored-{ticks}`；恢复时防护 zip slip，并再次阻止写入消息库/登录态相关路径。

## 11. Codex 配置导入/导出

### 入口
- 左侧导航进入“Codex 配置”面板。
- 顶部提供“导入”按钮；每条记录右侧提供“应用 / 导出 / 删除”按钮。

### 操作步骤
- 导入：点击“导入”并同时选择同一目录下的 `config.toml` 与 `auth.json`，输入记录名后保存。
- 导出：在目标记录点击“导出”，选择父目录后自动创建子目录并写出 `config.toml`、`auth.json`。
- 应用：点击“应用”将记录内容写入 `%USERPROFILE%\\.codex`。

### 依赖
- 本地文件系统读写。
- Windows DPAPI（用于记录内嵌内容的加密存储）。

### 限制
- 导入时必须同时选择两个文件，且必须来自同一文件夹。
- 仅导出已成功保存内嵌内容的记录；缺少内容会提示并终止。

## 12. SQL 导出多数据库支持

### 入口
- 左侧导航进入“SQL 多数据库工具”面板。
- 顶部可选择数据库类型：`SQL Server / PostgreSQL / MySQL`。

### 操作步骤
- 选择数据库类型并填写地址、端口、用户名、密码，点击“测试连接”。
- 连接成功后选择数据库和数据表，点击“导出为 Excel”。
- 在“SQL 查询”页执行查询后可导出结果。

### 依赖
- `System.Data.SqlClient`（SQL Server）。
- `Npgsql 4.1.13`（PostgreSQL）。
- `MySqlConnector 2.3.7`（MySQL）。

### 限制
- 历史连接信息按数据库类型分别保存，密码仍使用 DPAPI 加密。
- 导出前统一校验 Excel 单工作表上限 `1,048,576` 行。
- 数据库、架构、表名仅允许使用程序加载的白名单结果。

## 13. 截图区域录像

### 入口
- 左侧导航进入“截图工具”面板，点击“开启录像”。

### 操作步骤
- 首次使用会要求选择录像保存目录（仅首设）。
- 主窗口隐藏后弹出可拖拽/可调大小的录制区域窗口。
- 点击右上角圆形按钮开始录像，再次点击停止并保存为 `.mp4`。

### 依赖
- 优先使用程序目录下的 `NativeBinaries\\ffmpeg\\ffmpeg.exe`；也支持系统 PATH 中的 `ffmpeg.exe`。
- `ffmpeg.exe` 需要手动放置或手动安装，不自动下载。
- ffmpeg 参数：`H.264 + AAC + MP4`，并使用 `q` 指令优雅停止。

### 限制
- 未检测到音频设备时会询问是否仅录制画面。
- 录像与录音互斥，同一时刻只允许一个 ffmpeg 任务运行。

## 14. 独立录音

### 入口
- 左侧导航进入“截图工具”面板，点击“开启录音”。

### 操作步骤
- 首次使用会要求选择录音保存目录（仅首设，独立于录像目录）。
- 开始后按钮会切换为“停止录音”，面板顶部显示“录音中 mm:ss”计时。
- 再次点击停止，保存为 `.m4a` 文件。

### 依赖
- 复用录像功能的 ffmpeg 检测逻辑：优先使用 `NativeBinaries\\ffmpeg\\ffmpeg.exe`，其次使用系统 PATH 中的 `ffmpeg.exe`。
- ffmpeg 参数：`AAC + M4A`，并使用 `q` 指令优雅停止。

### 限制
- 不弹出区域窗口，录音期间主窗口保持可操作。
- 未检测到可用音频输入设备时直接报错，不生成静音文件。
