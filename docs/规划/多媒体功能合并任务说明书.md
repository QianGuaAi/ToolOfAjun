# 多媒体功能合并任务说明书

## 【角色定义】

你是一个专门负责 WPF 桌面工具模块重构、多媒体浏览界面设计、媒体播放与格式转换整合的助手。你需要在 `MyTools` 项目中，把现有“图片查看”“音视频播放”“格式转换”三个独立入口合并为一个新功能“多媒体”，并保持项目兼容 `.NET Framework 4.8` 与 Windows 7 SP1 及以上系统。

## 【任务目标】

交付一个名为“多媒体”的统一功能模块：进入该模块后，程序主体呈现资源管理器式窗口，左侧显示文件夹树与可调整大小的预览区，右侧只显示当前选中文件夹内的图片、视频、音频文件，单击文件在预览区预览，双击文件进入沉浸式查看或播放，右键文件可打开格式转换弹窗并设置转换参数，右上角提供“退出多媒体”按钮返回正常工具界面。

82. 用户点击 `取消` 时，必须关闭弹窗，并且不启动转换。

83. 用户点击 `确定` 时，必须校验输出格式和输出目录。

## 【边界与限制】

1. 如果某个文件夹没有访问权限，则在右侧状态栏显示 `无权限访问该文件夹`，并保持程序可操作。

2. 如果某个媒体文件损坏或无法解码，则预览区显示 `无法预览该文件`，并提供 `外部打开` 按钮。

3. 如果 `MediaElement` 无法播放某种格式，但扩展名在支持列表内，则保留文件列表显示，并在预览失败时显示失败提示。

4. 如果 `ffmpeg.exe` 不存在，则音视频转换弹窗必须显示 FFmpeg 缺失提示，并禁用 `确定` 按钮。

5. 如果右键目标不是图片、音频、视频文件，则右键菜单禁止显示 `格式转换` 项。

6. 如果勾选目标中包含非媒体文件，则转换前必须过滤非媒体文件，并在弹窗中显示 `已忽略 N 个非媒体文件`。

7. 如果转换目标数量为 0，则禁止打开格式转换弹窗，并在状态栏显示 `没有可转换的媒体文件`。

8. 如果迁移旧图片编辑命令会导致本次改动超过 8 个核心文件，则先保留旧命令入口为兼容方法，并在 `docs/开发记录.txt` 标注 `[待确认]` 与原因。

9. 如果 `MainWindow.xaml` 单个面板超过 800 行，则必须使用 `UserControl` 拆分；本任务默认使用 `MultimediaPage.xaml` 拆分。

10. 如果无法判断某个旧功能是否必须迁移，则在代码中不删除该旧功能，并在 `docs/开发记录.txt` 标注 `[待确认]`，说明具体命令名或控件名。

11. 如果构建失败，则不得声明完成任务；必须记录第一个编译错误的文件路径、行号、错误码。
