# 启动性能基线 - 2026-05-22

## 本次问题定位

- Release 启动实测中，`MainViewModel` 构造约 14-23 ms，不是启动慢主因。
- `MainWindow.InitializeComponent()` 曾耗时 14,735 ms，原因是主窗口 XAML 一次性创建托盘图标、首页和大量非首页模块控件。
- 将非首页模块迁出主窗口后，仍发现 XAML 托盘图标会阻塞首帧；改为窗口显示后延迟创建。

## 修改后本机基线

- 测试日期：2026-05-22
- 构建配置：Release / net48
- 运行环境：Windows 11 (10.0.26200) / .NET Framework 4.8
- `MainViewModel constructed`：14 ms
- `MainWindow InitializeComponent completed`：2,665-4,866 ms
- `MainWindow Show returned`：501-565 ms
- 外部 `Process.MainWindowHandle` 观测：约 6,791-9,532 ms，此指标包含 WPF 首次消息循环、延迟首页/托盘加载与系统窗口句柄刷新，不等同于 `Show()` 返回时间。

## 已采取措施

- `MainWindow.xaml` 保留顶部菜单、状态栏、轻量宿主。
- 首页迁出为 `Views/HomeView.xaml`，窗口显示后延迟加载。
- 非首页模块迁出为 `Views/MainModulesView.xaml`，首次切换到对应模块时加载。
- `Hardcodet.NotifyIcon.Wpf` 托盘图标改为窗口显示后延迟创建。
- `ReadAutoStartStatus()` 注册表读取移出 `MainViewModel` 构造函数，延后到 `ApplicationIdle`。

## 未达 500 ms 的原因

- 当前仍使用 `MetroWindow`、MaterialDesign、MahApps 与全局资源字典，首次加载 WPF 主题和窗口资源存在固定成本。
- 未移除全局异常处理、DPAPI、SQL 白名单、日志等安全与健壮性机制。

## 2026-05-22 二次优化记录

- 外部 `Process.MainWindowHandle` 冷启动观测：约 6,410-7,305 ms；同一 exe 热启动观测：约 5,201-5,754 ms。
- `MyTools.exe` 体积由约 27.9 MB 降至约 21.2 MB。
- Costura 改为 `LoadAtModuleInit=false`，启动首帧前不再自动初始化第三方依赖解析。
- 移除当前未使用的 `System.Data.SQLite`、`Stub.System.Data.SQLite.Core.NetFramework`、`Dapper`、`FluentWPF` 依赖，SQLite 结构化存储需要启用时再恢复。
- `App.xaml` 只保留轻量 `ShellTheme.xaml`；MahApps、MaterialDesign 和完整主题移到 `DeferredAppResources.xaml`，由重 UI 模块按需加载。
- 主窗口首屏改为轻量原生 WPF shell，顶部菜单和 4 个常用入口先显示；完整 HomeView 不再参与首帧。
- 托盘初始化延后，托盘图标改为直接读取 `Resources/AppIcon.ico`，避免从单 exe 扫描提取图标。
- Serilog 初始化移出首帧路径；启动指标改写入轻量 `MyTools.startup.log`。

## 设置菜单资源修复验证
- 修改时间：2026-05-22。
- 问题原因：二次启动优化将 MahApps、MaterialDesign 与完整主题资源改为延迟加载，但点击“设置(P)”时先切换 `CurrentModule`，视图开始渲染后才补充资源，导致 `MaterialDesignTabControl` / `MaterialDesignRaisedButton` 等样式查找失败。
- 修复动作：`DeferredUiResourceService` 改为按顺序直接合并第三方主题字典与本项目主题字典；`SwitchModule` 在进入非首页模块前先加载延迟资源。
- Release 启动验证：`MyTools.startup.log` 最新记录为 `OnStartup=334 ms`、`InitializeComponent=118 ms`、`Show=214 ms`；UI Automation 点击“设置(P)”后进入“系统 / 系统设置”，未出现运行错误对话框。
