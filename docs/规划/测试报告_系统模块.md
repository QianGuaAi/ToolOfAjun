# MyTools 系统模块测试分析报告

> 分析日期：2026-05-31
> 分析范围：NetworkView、StartupView、UninstallView、SystemInfoView、BenchmarkView 及对应 Service 层

## 一、网络模块（NetworkView）

### 1.1 功能描述

网络模块用于实时查看本机所有网卡（排除回环接口）的网络配置信息，包括：

| 显示字段 | 数据来源 |
|---------|---------|
| 网卡名称 (Name) | `NetworkInterface.Name` |
| 描述 (Description) | `NetworkInterface.Description` |
| IP 地址 (IPv4/IPv6) | `GetIPProperties().UnicastAddresses` |
| 网关 | `GetIPProperties().GatewayAddresses` |
| DNS | `GetIPProperties().DnsAddresses` |
| MAC 地址 | `GetPhysicalAddress()` |
| 速率 | `NetworkInterface.Speed` |
| 类型 | `NetworkInterface.NetworkInterfaceType` |

### 1.2 交互点

| 交互元素 | 类型 | 功能 |
|---------|------|------|
| 刷新按钮（标题栏） | IconButton | 触发 `RefreshCommand`，重新加载网卡列表 |
| 刷新按钮（空列表页） | GhostActionButton | 同上 |
| NetworkListControl | ItemsControl | 数据展示，无直接交互 |

### 1.3 数据流

```
NetworkService.GetAllNetworkDetails()
  └─ NetworkInterface.GetAllNetworkInterfaces()
       └─ 过滤 Loopback
            └─ 格式化输出（MAC/IP/网关/DNS/速率）
```

### 1.4 已知问题与潜在 Bug

| 严重度 | 问题描述 | 位置 | 说明 |
|-------|---------|------|------|
| ⚠️ 中 | **静默吞异常** | `NetworkService.cs` L56 `catch { }` | 所有异常被空catch捕获，失败时不返回任何数据，也无日志。应当使用 Serilog 记录错误 |
| ⚠️ 中 | **多IP地址换行显示可能导致布局问题** | `NetworkData.IpAddress` 使用 `\n` 拼接多行 IP | XAML TextBlock 的 TextWrapping=Wrap 在某些布局下可能显示异常 |
| ⚠️ 低 | **状态颜色转换器依赖外部定义** | XAML `StatusToColorConverter` | 若 Converter 未注册或 Key 错误，编译不报错但运行显示异常 |
| ⚠️ 低 | **空网络时刷新按钮逻辑** | NetworkListControl 的 HasItems DataTrigger | 空列表时仅隐藏主列表，未禁用刷新按钮 |

### 1.5 需人工验证的关键点

- [ ] 在有多个 IP 地址（IPv4 + IPv6）的网卡上，IP 地址换行显示是否美观
- [ ] 在无网卡或全部被过滤的情况下（理论上不会），空列表提示是否正常显示
- [ ] 网卡状态（Up/Down）对应的颜色转换是否符合预期
- [ ] 刷新操作是否会短暂阻塞 UI 线程（当前为同步调用）

## 二、启动管理模块（StartupView）

### 2.1 功能描述

管理 Windows 开机启动项，支持查看、搜索、启用/禁用、永久删除启动项，并显示数字签名信息。

### 2.2 读取的注册表/启动位置

| 来源 | 路径 | 范围 | 用途 |
|------|------|------|------|
| 注册表 Run（启用项） | `HKCU\SOFTWARE\Microsoft\Windows\CurrentVersion\Run` | 当前用户 | 读取用户级启用启动项 |
| 注册表 Run（启用项） | `HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Run` | 所有用户 | 读取系统级启用启动项（需管理员） |
| 注册表备份（禁用项） | `HKCU\SOFTWARE\AJunTools\DisabledRun` | 当前用户 | 存储 MyTools 禁用的用户启动项 |
| 注册表备份（禁用项） | `HKLM\SOFTWARE\AJunTools\DisabledRun` | 所有用户 | 存储 MyTools 禁用的系统启动项（需管理员） |

### 2.3 额外检测能力

- **可执行文件路径提取**：支持带引号路径、已知扩展名提取、PATH 环境变量解析
- **数字签名检测**：`X509Certificate.CreateFromSignedFile` + `X509Chain` 验证证书链可信性
- **发布者信息**：`FileVersionInfo.CompanyName`
- **文件存在性**：`File.Exists()`

### 2.4 交互点

| 交互元素 | 类型 | 功能 |
|---------|------|------|
| 刷新按钮 | IconButton | `RefreshCommand` — 重新扫描所有启动项 |
| 搜索框 | TextBox | `StartupSearchText` — 按名称/发布者/命令/位置/来源过滤 |
| 禁用/启用 切换按钮 | GhostActionButton | `ToggleStartupCommand` — 移动注册表值实现切换 |
| 删除按钮 | IconButton | `DeleteStartupCommand` — 永久删除启动项 |
| FilteredStartupView | ItemsControl | 过滤后的启动项列表展示 |

### 2.5 已知问题与潜在 Bug

| 严重度 | 问题描述 | 位置 | 说明 |
|-------|---------|------|------|
| ⚠️ 中 | **UnauthorizedAccessException 未被完全捕获** | `StartupService.cs` L131-138 | 错误处理仅捕获 `UnauthorizedAccessException`，其他异常（如注册表不存在、安全策略限制）会直接抛出 |
| ⚠️ 中 | **删除操作无二次确认** | View 层仅提示 ToolTip | 永久删除注册表值是不可逆操作，应有确认对话框 |
| ⚠️ 低 | **禁用后再次禁用会报错** | `ToggleStartupItem` | 如果启动项已在禁用备份中，再次切换会尝试从备份移回，若备份中已有同名项则可能覆盖 |
| ⚠️ 低 | **PATH 解析不含 SystemDirectory 检查顺序** | `ResolveFromPath` | 先检查 SystemDirectory/Windows，再检查 PATH 环境变量，与 Windows 实际加载顺序不同 |
| ⚠️ 低 | **证书链校验禁用吊销检查** | `IsCertificateChainTrusted` L355 | `X509RevocationMode.NoCheck` 可能漏检已吊销证书 |
| ✅ 良好 | **UI 显示丰富** | 颜色区分启用/禁用/不存在/签名状态 | 设计考虑周全 |

### 2.6 需人工验证的关键点

- [ ] 以普通用户身份运行时，禁用系统级启动项是否弹出权限不足提示
- [ ] 搜索框输入特殊字符（如正则元字符 `.`、`*`）是否导致异常
- [ ] 大量启动项（如 >100 个）时列表滚动是否流畅
- [ ] 数字签名显示"证书链不可信"的项是否确实不可信（如自签名证书）
- [ ] 禁用后再启用，功能是否完全恢复

## 三、程序卸载模块（UninstallView）

### 3.1 功能描述

读取 Windows 注册表中已安装程序列表，支持搜索、排序、筛选、批量选择和卸载。

### 3.2 数据来源（注册表）

| 路径 | 范围 | 来源标识 |
|------|------|---------|
| `HKCU\SOFTWARE\Microsoft\Windows\CurrentVersion\Uninstall` | 当前用户 | "当前用户" |
| `HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Uninstall` | 所有用户 64 位 | "所有用户 64 位" |
| `HKLM\SOFTWARE\WOW6432Node\Microsoft\Windows\CurrentVersion\Uninstall` | 所有用户 32 位 | "所有用户 32 位" |

### 3.3 读取的注册表字段

`DisplayName`、`DisplayVersion`、`Publisher`、`InstallLocation`、`InstallDate`（yyyyMMdd 格式）、`EstimatedSize`（KB）、`UninstallString`、`QuietUninstallString`、`SystemComponent`、`NoRemove`、`WindowsInstaller`

### 3.4 静默卸载检测逻辑

1. 优先使用 `QuietUninstallString`
2. 若含 `msiexec`，追加 `/qn /norestart`
3. 检测常见静默参数：`/quiet`、`/qn`、`/s`、`/silent`、`/verysilent`

### 3.5 交互点

| 交互元素 | 类型 | 功能 |
|---------|------|------|
| 刷新按钮 | IconButton | `RefreshInstalledProgramsCommand` |
| 搜索框 | TextBox | 按程序名/发布者/路径过滤 |
| 排序下拉 | ComboBox | 按名称/发布者/安装日期/大小排序 |
| 大小筛选 | ComboBox | 按大小范围筛选 |
| 日期筛选 | ComboBox | 按安装日期筛选 |
| 全选筛选 | Button | `SelectFilteredInstalledProgramsCommand` |
| 清除选择 | Button | `ClearInstalledProgramSelectionCommand` |
| 导出清单 | Button | `ExportInstalledProgramListCommand` |
| 卸载按钮 | IconButton | `UninstallProgramCommand` — 启动程序自带卸载向导 |
| 程序列表 | DataGrid | 支持多选 CheckBox |

### 3.6 已知问题与潜在 Bug

| 严重度 | 问题描述 | 位置 | 说明 |
|-------|---------|------|------|
| ⚠️ 高 | **卸载后不刷新列表** | `UninstallView.xaml.cs` 无特殊处理 | 启动卸载进程后，程序可能仍在列表中显示，需要手动刷新 |
| ⚠️ 中 | **卸载进程状态未跟踪** | `StartUninstall` 只返回 Process | 未实现监控，卸载完成后列表不会自动刷新 |
| ⚠️ 中 | **MSI 卸载参数转换不完整** | `NormalizeMsiArguments` L410 | `/I{ProductCode}` 只替换了首字符，未处理 `-I` 或其他大小写变体 |
| ⚠️ 低 | **去重逻辑可能丢失同名的不同版本** | `BuildDedupeKey` | 使用 DisplayName + Version + Publisher + UninstallString 联合去重，同名不同版本可保留，但 UninstallString 不同会被视为不同程序 |
| ⚠️ 低 | **估计大小可能为 0** | `EstimatedSize` | 注册表中的 EstimatedSize 单位是 KB，但有些程序注册为字节，与注释不一致 |
| ⚠️ 低 | **导出清单功能未实现** | `ExportInstalledProgramListCommand` | 需确认此命令是否有实际绑定 |
| ✅ 良好 | **SystemComponent/NoRemove/WindowsInstaller 过滤** | 避免误显示系统组件 | 设计完善 |

### 3.7 需人工验证的关键点

- [ ] 点击卸载按钮后，程序列表是否在合理时间内刷新（或提示用户手动刷新）
- [ ] 大小筛选和日期筛选是否正确工作
- [ ] 导出的清单文件格式是否符合预期
- [ ] 在 32 位程序列表中，64 位程序是否正确排除
- [ ] 某些程序的 UninstallString 包含变量（如 `%ProgramFiles%）是否正确展开

## 四、系统信息模块（SystemInfoView）

### 4.1 功能描述

展示系统硬件概览（CPU/内存/显卡/存储/网络适配器/显示器）和实时传感器数据（温度/风扇/电压/负载）。

### 4.2 读取的系统信息

#### 硬件概览（HardwareInfoService）

| 信息类别 | WMI 查询 | 说明 |
|---------|---------|------|
| OS 信息 | `Win32_OperatingSystem` | Caption, Version, OSArchitecture, LastBootUpTime |
| 计算机信息 | `Win32_ComputerSystem` | Manufacturer, Model |
| BIOS | `Win32_BIOS` | SMBIOSBIOSVersion, ReleaseDate |
| 主板 | `Win32_BaseBoard` | Manufacturer, Product |
| CPU | `Win32_Processor` | Name, Cores, LogicalProcessors, MaxClockSpeed, L2/L3 Cache |
| 显卡 | `Win32_VideoController` | Name, DriverVersion, DriverDate, AdapterRAM |
| 内存模块 | `Win32_PhysicalMemory` | BankLabel, Capacity, Speed, Manufacturer, PartNumber, Type |
| 磁盘 | `Win32_DiskDrive` | Model, InterfaceType, Size, MediaType, SerialNumber |
| 网络适配器 | `Win32_NetworkAdapter` | PhysicalAdapter=True, MACAddress, Speed |
| 显示器 | `Win32_DesktopMonitor` | Name, MonitorManufacturer, ScreenWidth, ScreenHeight |

#### 实时传感器（HardwareSensorService）

使用 **LibreHardwareMonitorLib** 读取：
- CPU 温度 / 显卡温度 / 主板温度
- 风扇转速
- CPU 占用率
- 电压、功率、时钟频率等

#### 快照信息（SystemInfoService）

- 系统运行时间（`GetTickCount64`）
- 操作系统名称
- .NET 版本
- 系统盘使用情况
- 内存使用率

### 4.3 交互点

| 交互元素 | 类型 | 功能 |
|---------|------|------|
| 刷新硬件 | GhostActionButton | `LoadSystemInfoCommand` |
| 以管理员重启 | GhostActionButton | `RestartAsAdminCommand`（仅非管理员时显示） |
| TabItem：硬件概览 | TabControl | 展示静态硬件信息 |
| TabItem：实时传感器 | TabControl | 展示实时传感器数据 |
| 刷新频率 | ComboBox | `SensorRefreshModes` |
| 刷新 | Button | `RefreshSensorsOnceCommand` |
| 停止采集 | Button | `ToggleHardwareSensorsCommand` |

### 4.4 已知问题与潜在 Bug

| 严重度 | 问题描述 | 位置 | 说明 |
|-------|---------|------|------|
| ⚠️ 中 | **显示器信息可能为空** | `Win32_DesktopMonitor` | 笔记本、某些一体机、远程桌面环境下 WMI 查询可能无结果 |
| ⚠️ 中 | **传感器服务需管理员权限** | HardwareSensorService | 提示信息正确，但未强制阻止非管理员启动 |
| ⚠️ 中 | **LibreHardwareMonitor 可能不可用** | `HardwareSensorService.TryStart` | 依赖独立库，若未嵌入或版本不匹配会返回 null |
| ⚠️ 低 | **主板运行时间计算可能为负** | `HardwareInfoService` L138 | 若 WMI 返回的 LastBootUpTime 格式异常，`DateTime.Now - dt` 可能异常 |
| ⚠️ 低 | **内存类型翻译不完整** | `TranslateMemoryType` | 仅处理了 DDR 系列，LPDDR 系列有部分覆盖，未知类型显示 "类型 N" |
| ⚠️ 低 | **显卡厂商显示不准确** | `AdapterCompatibility` | 使用 AdapterCompatibility 而非实际厂商名称，可能显示为 "NVIDIA" 而非 "NVIDIA Corporation" |
| ⚠️ 低 | **运行时间双重来源** | SystemInfoService vs HardwareInfoService | 前者用 GetTickCount64，后者用 WMI LastBootUpTime，两者应一致但实现不同 |

### 4.5 需人工验证的关键点

- [ ] 在虚拟机环境中，传感器数据是否显示"不可用"或默认值
- [ ] 以管理员/非管理员分别运行，传感器可用性差异
- [ ] 显示器列表为空时，UI 是否优雅降级
- [ ] 运行时间显示是否与任务管理器一致
- [ ] 在不同硬件平台（Intel/AMD/NVIDIA/AMD GPU）上传感器数据是否正常

## 五、性能测试模块（BenchmarkView）

### 5.1 功能描述

执行轻量级性能基准测试，包括 CPU 单线程/多线程、内存带宽、内存延迟、GPU 信息读取。

### 5.2 测试逻辑

| 测试项 | 方法 | 迭代次数 | 指标 |
|-------|------|---------|------|
| CPU 单线程 | SHA-256 哈希迭代 | 200,000 次 | ops/s |
| CPU 多线程 | 同上，分 N 线程并行 | 200,000 × 线程数 | ops/s（总） |
| 内存带宽 | 顺序写入 + 读取 256 MB | 1 次 | GB/s |
| 内存延迟 | 指针追逐（4M 随机链） | 10,000,000 步 | ns/次 |
| GPU 信息 | WMI Win32_VideoController | — | 名称/显存/驱动版本 |

### 5.3 交互点

| 交互元素 | 类型 | 功能 |
|---------|------|------|
| 运行全部测试 | PrimaryActionButton | `RunAllBenchmarksCommand` |
| CPU 单线程 | GhostActionButton | `RunSingleBenchmarkCommand` 参数 "CpuSingle" |
| CPU 多线程 | GhostActionButton | `RunSingleBenchmarkCommand` 参数 "CpuMulti" |
| 内存带宽 | GhostActionButton | `RunSingleBenchmarkCommand` 参数 "MemBandwidth" |
| 内存延迟 | GhostActionButton | `RunSingleBenchmarkCommand` 参数 "MemLatency" |
| GPU 信息 | GhostActionButton | `RunSingleBenchmarkCommand` 参数 "GpuInfo" |
| 复制 | GhostActionButton | `CopyBenchmarkResultsCommand` |
| 导出 | GhostActionButton | `ExportBenchmarkResultsCommand` |
| 测试结果列表 | DataGrid | 只读，结果展示 |

### 5.4 已知问题与潜在 Bug

| 严重度 | 问题描述 | 位置 | 说明 |
|-------|---------|------|------|
| ⚠️ 高 | **CPU 多线程测试缺少 .ConfigureAwait(false)** | `BenchmarkService.cs` L85 `Task.WaitAll(tasks)` | 内部 Task.Run 返回后用 WaitAll 而非 await，可能阻塞调用线程上下文 |
| ⚠️ 中 | **SHA256CryptoServiceProvider 已废弃** | `BenchmarkService.cs` L33, L74 | 应使用 `SHA256.Create()` 或 `SHA256Managed`，但对测试结果无影响 |
| ⚠️ 中 | **256 MB 内存测试在 32 位进程可能失败** | `RunMemoryBandwidthAsync` | 32 位进程地址空间限制可能导致 OutOfMemoryException |
| ⚠️ 低 | **GPU 信息测试返回格式不够结构化** | `RunGpuInfoAsync` Score 字段 | GPU 名称放在 Score，显存和驱动放在 Detail，数据结构不统一 |
| ⚠️ 低 | **CancelToken 在 Task.Run 外部传递** | 多处 `ct.ThrowIfCancellationRequested()` 在 Task.Run 内部 | 正确做法是 Task.Run 时传入 ct，但当前实现在进入 Task.Run 前无法取消 |
| ⚠️ 低 | **测试过程中 UI 可能无进度反馈** | 取决于 Progress 报告频率 | 单个测试完成后才报告进度，测试运行中（数秒）无中间反馈 |
| ✅ 良好 | **所有测试均可取消** | CancellationToken | 实现了标准的取消机制 |
| ✅ 良好 | **测试后主动 GC** | `RunMemoryBandwidthAsync` L143 | 释放大内存缓冲区 |

### 5.5 需人工验证的关键点

- [ ] 在多核 CPU 上，多线程测试的加速比是否符合预期（应接近核心数）
- [ ] 内存带宽测试的 GB/s 数据是否与工具软件（如 AIDA64）接近
- [ ] 内存延迟测试的 ns 数据是否在合理范围内（DDR4 约 60-100 ns）
- [ ] 在低内存（<8GB）系统上，256 MB 缓冲区测试是否稳定
- [ ] GPU 信息测试在无独显（仅核显）的平台上是否显示"无 GPU"

## 六、跨模块共性问题

| 问题 | 影响范围 | 建议 |
|------|---------|------|
| **启动期 WMI 调用** | SystemInfoView、SystemInfoService | 若在 MainWindow 构造函数中初始化，需按 AGENTS.md 9.1 节延迟到 ApplicationIdle |
| **空 catch 块** | NetworkService | 应使用 Serilog 记录异常，避免静默失败 |
| **缺乏单元测试** | 所有模块 | 核心 Service 层（如 StartupService、InstalledProgramService）建议补充单元测试 |
| **资源未释放** | ManagementObjectSearcher | HardwareInfoService 和 SystemInfoService 中的 WMI 查询已有 Dispose，但仍需确认所有路径均覆盖 |
