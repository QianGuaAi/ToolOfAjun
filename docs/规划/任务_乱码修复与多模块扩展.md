# 任务执行说明书：MyTools 乱码修复 + Codex 导入导出 + 截图 NRE 修复 + 多数据库支持 + 录像 + 独立录音

## 【角色定义】

你是一个专门负责为 MyTools（基于 .NET Framework 4.8 / WPF / MVVM 的 Windows 桌面工具）逐项修复 Bug 与新增功能的助手。你只在仓库 `c:\ToolOfAjun` 中工作，禁止改变项目原有的技术栈与分发方式（必须保持单一 `MyTools.exe` 的 Costura 打包产物）。

## 【任务目标】

在不破坏既有功能的前提下，按本说明书 7 个交付项依次完成：
1. 修复"SQL 导出"面板"状态"显示乱码。
2. 修复"Codex 配置"面板的乱码（含初始状态文案与卡片中的文件夹/状态文字）。
3. 在"Codex 配置"面板新增"导出"和"导入"功能。
4. 修复"截图工具"模块按下快捷键或点击"立即截图"后弹出 `未将对象引用设置到对象的实例` 的崩溃，恢复截图可用。
5. 让"SQL 导出"模块支持 PostgreSQL 与 MySQL（在原 SQL Server 之外新增两种数据库）。
6. 在"截图工具"模块新增"录像（含同步录音）"功能：可拖动调整大小的录制框、首次设置保存文件夹、开始/停止按钮（含状态图标切换）、采用 H.264 + AAC + MP4 编码。
7. 在"截图工具"模块新增"独立录音"功能（仿录像设计，但只录音不录屏）：开始/停止按钮（话筒红 ↔ 停止灰）、首次设置音频保存文件夹、采用 AAC + M4A 容器（体积小、兼容好）。

每完成一项立即在 `docs\开发记录.txt` 末尾按 `## [YYYY-MM-DD] 标题` 格式追加一条记录；功能项还需更新 `docs\功能说明.md`。

### 步骤 8 — 录像（含录音）功能（任务目标 6）

8.1 编码与依赖：使用 `ffmpeg.exe`（GPL 静态构建，x64，约 60MB），通过 `Process` 调用。**禁止**引入 NuGet（如 FFMpegCore 等），因为我们要保持单 exe；`ffmpeg.exe` 体积较大，**不嵌入 exe**，而是放在 `NativeBinaries\ffmpeg\ffmpeg.exe`，在 csproj 已有 `<None Update="NativeBinaries\**\*.*"><CopyToOutputDirectory>PreserveNewest</CopyToOutputDirectory></None>` 规则下随产物分发。把"如何获取 ffmpeg.exe"的说明写入 `docs\功能说明.md`（要求用户首次使用时手动放入）。如果该文件不存在，应用启动并不报错；只有在用户点击"开始录像"时才检查并提示 `请将 ffmpeg.exe 放到 {路径} 后再试。`。
8.2 区域选择窗口 `RecordRegionWindow.xaml`：无边框、`AllowsTransparency=true`、`Background="#01000000"`、`Topmost=true`、`ResizeMode=CanResizeWithGrip`，中间空心 4px 红色边框 `#FFE53935`，四角与四边各放 8x8 的拖拽手柄；窗口可被鼠标拖动（按下 `MouseLeftButtonDown` 调 `DragMove()`）。窗口右上角放置一个独立浮层"开始录像"按钮（圆形，48x48），**未录像时**图标为 `PackIcon Kind="RecordRec"` 红色实心；**录像中**变为 `PackIcon Kind="StopCircle"` 灰色（仍是录像图标族但表示"正在录像/再次点击停止"）。
8.3 录像服务 `Services\RecordingService.cs`：
- 启动 ffmpeg：`-y -f gdigrab -framerate 30 -offset_x {X} -offset_y {Y} -video_size {W}x{H} -i desktop -f dshow -i audio="{audioDevice}" -c:v libx264 -preset veryfast -crf 23 -pix_fmt yuv420p -c:a aac -b:a 128k -movflags +faststart "{outputPath}"`。
- 音频设备解析顺序：先尝试 `virtual-audio-capturer`；若不存在，再用 `ffmpeg -list_devices true -f dshow -i dummy` 解析并使用第一个 audio 设备名。两者皆失败时，弹出提示 `未检测到可用音频设备，将仅录制画面，是否继续？(是/否)`；用户选"是"则去掉 `-f dshow -i audio=...` 与 `-c:a aac -b:a 128k` 后重启。
- 停止录像：向 ffmpeg `StandardInput` 写入 `q\n` 优雅退出（不可直接 `Kill`，否则 mp4 moov 损坏）。等待最多 5 秒；超时再 `Kill`。
- 输出文件：`{保存目录}\录像_{yyyyMMdd_HHmmss}.mp4`。
8.4 首次设置保存文件夹：在 `AppSettingsService` 增加属性 `RecordingOutputFolder`（持久化到 JSON）。点击"开始录像"按钮时若该值为空或目录不存在：弹 `FolderBrowserDialog` `请选择录像保存的文件夹（仅本次首设）`。用户取消则取消本次录像；写入设置后继续启动 ffmpeg。
8.5 截图面板增加"开启录像"按钮（在"立即截图"按钮右侧）。点击后：隐藏主窗口（不退出），打开 `RecordRegionWindow`；用户在该窗口上点击"开始录像"按钮即开始录制；再次点击同一按钮则停止录制并 `MessageBox` 显示 `录像已保存到 {路径}`，关闭区域窗口，恢复主窗口。
8.6 ffmpeg 子进程必须 `RedirectStandardInput=true`、`RedirectStandardError=true`、`UseShellExecute=false`、`CreateNoWindow=true`；stderr 异步逐行写入 Serilog（INFO 级，但行内含 `error`/`Error` 时升级为 ERROR）。**禁止** stdin 同步阻塞 UI。

### 步骤 8b — 独立录音功能（任务目标 7）

本步骤完全仿照步骤 8 的设计与约束（依赖 ffmpeg.exe、Process 调用、stdin `q\n` 优雅退出、DPAPI 与日志规范），**唯一区别**是不录屏、不弹区域窗口、产物为纯音频。

8b.1 复用步骤 8.1 的 `ffmpeg.exe`（**禁止**为录音单独再嵌入或下载第二份）。`RecordingService` 内新增公开方法 `Task StartAudioOnlyAsync(string outputPath, CancellationToken ct)` 与 `Task StopAudioOnlyAsync()`，与录像方法互斥（同一时刻最多一路 ffmpeg；尝试同时启动时第二个调用必须返回 `InvalidOperationException("当前已有录像/录音任务在进行，请先停止。")`）。
8b.2 录音 ffmpeg 命令模板：`-y -f dshow -i audio="{设备名}" -c:a aac -b:a 128k -ar 44100 -ac 2 "{outputPath}"`。
  - 设备名解析顺序：先 `virtual-audio-capturer`（系统内录），再使用 `ffmpeg -list_devices true -f dshow -i dummy` 解析出的第一个 audio 设备（麦克风）。**禁止**硬编码中文设备名 "麦克风"。
  - 两者都不可用时弹出 `MessageBox.Show("未检测到任何音频输入设备，无法录音。", "录音失败", MessageBoxButton.OK, MessageBoxImage.Error)` 并 `return`，**不得**降级为静音文件。
8b.3 输出文件：`{录音保存目录}\录音_{yyyyMMdd_HHmmss}.m4a`。容器采用 `.m4a`（fragmented MP4 + AAC），不要使用 `.mp3`（需要额外编码器，且体积更大）。
8b.4 首次设置保存文件夹：在 `AppSettingsService` 增加属性 `AudioOutputFolder`（与 `RecordingOutputFolder` 互不复用，避免用户希望分目录管理）。点击"开启录音"按钮时若该值为空或目录不存在，弹 `FolderBrowserDialog`，提示文本 `请选择录音保存的文件夹（仅本次首设）`；用户取消即取消本次录音。
8b.5 截图面板按钮顺序固定为：`立即截图` → `开启录像` → `开启录音`，三按钮同高同 padding。"开启录音"按钮**未录音时**显示 `PackIcon Kind="Microphone"` 红色；**录音中**变为 `PackIcon Kind="StopCircle"` 灰色，文案由 `开启录音` 切换为 `停止录音`。
8b.6 录音过程中：
  - **不**隐藏主窗口（区别于录像）；用户可以继续在主窗口操作其他模块。
  - 在主窗口标题栏右侧或截图面板顶部加一个红色圆点 + `录音中 {mm:ss}` 计时（`DispatcherTimer` 1 秒刷新），停止后立即清空。
  - 不需要区域选择窗口，也不需要快捷键（本次不绑定全局热键，避免与截图热键冲突）。
8b.7 停止录音：与录像一致，向 ffmpeg `StandardInput` 写入 `q\n` 并最多等待 5 秒；超时则 `Kill`，并弹出 `MessageBox.Show("录音文件可能未正确写入，请检查 {路径}。", "录音", MessageBoxButton.OK, MessageBoxImage.Warning)`。正常完成后弹出 `录音已保存到 {路径}`。
8b.8 日志规范：`AppLogService.Information("Audio recording started: {Path}", outputPath)`、`...stopped: duration {Seconds}s, size {Bytes}B`；**禁止**记录设备的硬件 ID 之外的隐私信息，**禁止**记录任何音频内容字节。

## 【边界与限制】

- 如果遇到 `dotnet build` 报错且错误明确指向你新增的代码，必须修复后再继续；如果错误指向预先存在的代码与你的改动无关，则在 `构建基线日志.txt` 中记录 `[待确认] 与本次改动无关的既有错误：<错误>` 并停止后续步骤。
- 如果 `Npgsql` 4.1.13 因 `System.Threading.Tasks.Extensions` 等传递依赖与 .NET Framework 4.8 / Costura 冲突，**先尝试** 在 csproj 添加 `<PackageReference Include="System.Threading.Tasks.Extensions" Version="4.5.4" />`。仍失败，则降级使用 `Npgsql 4.0.14`，再失败则在 `待确认.txt` 中标 `[待确认]`，并临时注释 PostgreSQL 相关 UI 选项（保留 MySQL 与 SQL Server）。
- 如果当前用户的 `MyTools.codexprofiles.json` 中已有乱码，**禁止**自动改写其内容。仅在 UI 中正确显示用户重新保存后的新值；老数据由用户手动删除或重新拖入。
- 截图 NRE 修复中，如果 4 个候选位置全部无法复现 NRE，停止猜测，新增完整 try/catch 写日志后让用户复跑并提交日志，**不要**为"看起来像可能为 null 的地方"全部加 `?.`。仅修复确认是根因的那一处。
- 录像功能未提供 `ffmpeg.exe` 时，**只能**给出错误提示，**禁止**自动从网络下载（违反 §4.2 依赖管理 与 §一、本地优先 原则）。
