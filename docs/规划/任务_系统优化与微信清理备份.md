# 任务执行说明书：MyTools 系统优化扩展（自动优化 / 垃圾清理 / 微信清理 / 微信备份 / 微信恢复）

## 【角色定义】

你是一个专门负责为 MyTools（基于 .NET Framework 4.8 / WPF / MVVM 的 Windows 桌面工具）在"系统优化"模块新增 5 项系统级清理与备份功能的助手。你只在仓库 `c:\ToolOfAjun` 中工作，必须严格遵守 `AGENTS.md` 的全部约束（单 exe Costura 打包、MVVM、async/await、DPAPI、白名单、本地优先）。

## 【任务目标】

在"系统优化"面板（XAML 中已有的"系统优化与增强"`Grid`，绑定 `CurrentModule == "System"`）中**追加**以下 5 个独立子卡片，**不得改动** Defender / 自动更新两张已有卡片：

1. **自动优化**：点击"开始自动优化"按钮 → 自动扫描系统盘 → 顺序执行一组**白名单内**的安全优化操作 → 生成《优化报告》→ 保存为一条本地记录；用户可在报告列表中单选/多选，按"删除"按钮删除选中条目。
2. **垃圾清理**：点击"开始扫描"按钮 → 扫描系统中**预定义白名单路径** → 列出待清理项与体积 → 用户点击"立即清理"后**自动删除**这些**确认对用户和系统无害**的项目，并把本次清理结果追加到优化报告列表。
3. **微信清理**：按"开始日期 ~ 结束日期"+ 类别（文字/语音/图像/视频/其他文件）勾选清理微信对应数据，仅按文件修改时间过滤，**禁止**触碰消息数据库主文件。
4. **微信备份**：按"开始日期 ~ 结束日期"+ 类别勾选备份微信数据，输出**单个 .zip** 文件（含 `manifest.json`）。
5. **微信恢复**：选择某个备份 .zip → 读取 `manifest.json` → 还原到原路径（若同名存在则改名 `*.restored-{ticks}{ext}`）；用户也可指定目标根目录。

### 步骤 1 — 自动优化（任务目标 1）

1.1 在 `SystemOptimizationService.cs` 实现 `Task<OptimizationReportItem> RunAsync(IProgress<string> progress, CancellationToken ct)`。报告项结构：
```csharp
public class OptimizationReportItem {
    public string Id { get; set; }                // GUID8
    public DateTime StartedAt { get; set; }
    public DateTime FinishedAt { get; set; }
    public string ReportType { get; set; }        // "AutoOptimize" | "JunkCleanup"
    public List<OptimizationStep> Steps { get; set; }
    public long TotalBytesFreed { get; set; }
    public string Summary { get; set; }
}
public class OptimizationStep {
    public string Name { get; set; }
    public string Status { get; set; }            // "OK" | "Skipped" | "Failed"
    public string Detail { get; set; }
    public long BytesFreed { get; set; }
    public TimeSpan Duration { get; set; }
}
```

1.2 自动优化只允许执行下面这张**白名单**内的步骤，按顺序执行，每步独立 `try/catch`，单步失败标 `Failed` 但**不中止**整体流程：

| # | 步骤名 | 实现方式 | 是否需要管理员 |
|---|--------|----------|----------------|
| 1 | 清空当前用户 `%TEMP%` 中 ≥ 24 小时未修改的文件 | C# 直接遍历删除 | 否 |
| 2 | 清空 `C:\Windows\Temp` 中 ≥ 7 天未修改的文件 | `RunElevatedScriptAsync` | 是 |
| 3 | 清空缩略图缓存 `%LOCALAPPDATA%\Microsoft\Windows\Explorer\thumbcache_*.db` | C# 直接删除（删除前 `taskkill /im explorer.exe /f` 与 `start explorer.exe`，但**只在用户同意**：先 `MessageBox` 询问，拒绝则跳过本步标 Skipped） | 否 |
| 4 | 刷新 DNS 解析缓存 | `ipconfig /flushdns` | 否 |
| 5 | 重置 Windows 字体缓存（`FontCache` / `FontCache3.0.0.0`）| `RunElevatedScriptAsync`：停服务、删 `%WinDir%\ServiceProfiles\LocalService\AppData\Local\FontCache\*.dat`、起服务 | 是 |
| 6 | 清理 Windows 更新缓存 `C:\Windows\SoftwareDistribution\Download\` | `RunElevatedScriptAsync`：`Stop-Service wuauserv`、删除子内容、`Start-Service wuauserv` | 是 |
| 7 | 触发系统盘 TRIM/碎片整理（**仅当系统盘是 SSD 走 TRIM；HDD 才整理**）| `Optimize-Volume -DriveLetter C -ReTrim -Verbose`（SSD）/ `-Defrag`（HDD），通过 `Get-PhysicalDisk` 判断 MediaType | 是 |
| 8 | 清空回收站 | `Shell32` `SHEmptyRecycleBin(IntPtr.Zero, null, SHERB_NOCONFIRMATION \| SHERB_NOPROGRESSUI \| SHERB_NOSOUND)` | 否 |
| 9 | 清理事件日志（**仅** `Application` / `System` / `Security`，单条日志体积 > 500MB 才执行）| `RunElevatedScriptAsync`：先 `Get-WinEvent -ListLog`，超阈值才 `wevtutil cl <name>` | 是 |
| 10 | 内存压缩生效（`Optimize-Volume` 完成后调用 `EmptyWorkingSet`）| 调用 `psapi.dll` `EmptyWorkingSet(currentProcess)` 仅作用于自身进程，**禁止**遍历杀其它进程内存 | 否 |

**禁止**自行扩展白名单。**禁止**执行 `sfc /scannow`、`DISM /Online /Cleanup-Image /RestoreHealth`（耗时过长且非纯优化）、`chkdsk /f`（重启）、关闭/卸载系统功能。

1.3 每步开始前 `progress.Report($"[{i}/10] {stepName}...")`，在 UI 卡片中绑定显示。

1.4 完成后调用 `OptimizationReportService.SaveAsync(report)`：
- 序列化报告对象到 `report-...json`（UTF-8 BOM）。
- 在 `index.json` 中追加 `{ Id, StartedAt, FinishedAt, ReportType, TotalBytesFreed, Summary }` 一行；保持按 `StartedAt` 倒序排列。
- 同步 `OptimizationReports.Insert(0, item)`。

1.5 UI 卡片"自动优化"包含：
- 标题 + 简介。
- "开始自动优化"按钮（`MaterialDesignRaisedButton`，绑定 `StartAutoOptimizeCommand`）。
- 进度文字（绑定 `AutoOptimizeStatusMessage`）。
- 报告列表 `DataGrid` 或 `ListView`，列：`选择`(CheckBox)、`时间`(`StartedAt`)、`类型`、`释放空间`(`TotalBytesFreed` 自动转 KB/MB/GB)、`摘要`、`查看详情`(按钮，弹 `MessageBox` 显示 `Steps` 多行文本，**不要**新建窗口)。

### 步骤 2 — 垃圾清理（任务目标 2）

2.1 `JunkCleanupService.ScanAsync(IProgress<string>, CancellationToken)` 返回 `List<JunkCandidate>`，每项含 `Path`、`Category`（枚举：`UserTemp`、`SystemTemp`、`RecycleBin`、`BrowserCache`、`ThumbnailCache`、`PrefetchAged`、`WindowsUpdateCache`、`DeliveryOptimization`、`InstallerLeftover`）、`Bytes`、`Reason`。

2.2 **白名单**（**禁止**自行扩展）：

| 类别 | 路径或来源 | 删除条件 |
|------|-----------|---------|
| UserTemp | `%TEMP%`、`%LOCALAPPDATA%\Temp` | 文件 LastWriteTime ≥ 24 小时前；目录为空才递归删除 |
| SystemTemp | `C:\Windows\Temp` | 同上，且 ≥ 7 天 |
| RecycleBin | `Shell32 SHQueryRecycleBin` 大小，调用 `SHEmptyRecycleBin` | 用户勾选 |
| BrowserCache | `%LOCALAPPDATA%\Microsoft\Edge\User Data\Default\Cache\Cache_Data\`、`%LOCALAPPDATA%\Google\Chrome\User Data\Default\Cache\Cache_Data\` | 浏览器进程未运行（`Process.GetProcessesByName("msedge"/"chrome")` 为空）；否则 `Skipped` |
| ThumbnailCache | `%LOCALAPPDATA%\Microsoft\Windows\Explorer\thumbcache_*.db` | 用户勾选 |
| PrefetchAged | `C:\Windows\Prefetch\*.pf` | LastWriteTime ≥ 30 天前 |
| WindowsUpdateCache | `C:\Windows\SoftwareDistribution\Download\` | Stop wuauserv 成功后才能删 |
| DeliveryOptimization | `C:\Windows\ServiceProfiles\NetworkService\AppData\Local\Microsoft\Windows\DeliveryOptimization\Cache\` | Stop dosvc 成功后才能删 |
| InstallerLeftover | `%LOCALAPPDATA%\Package Cache\` 中 **空** 子目录 | 仅删空目录，**禁止**删除任何 .msi/.msp |

**严格禁止**进入：`C:\Windows\System32`、`C:\Windows\WinSxS`、`C:\Program Files*`、`C:\Users\<u>\Documents`、`C:\Users\<u>\Desktop`、`C:\Users\<u>\Pictures`、`C:\Users\<u>\Downloads`、任何挂载的网络盘（`DriveType != Fixed`）。任何路径在删除前必须经过 `IsPathInsideAny(safeRoots)` 校验，不在白名单内一律抛 `InvalidOperationException`。

2.3 UI 卡片"垃圾清理"包含：
- "开始扫描"按钮 → 扫描后展示 `ItemsControl`，每行：CheckBox（默认勾选除浏览器外）、类别图标、路径、体积；底部"立即清理"按钮（默认禁用，扫描完成才启用）。
- 清理执行后弹 `MessageBox` "已清理 {count} 项，释放空间 {size}"。
- 同步把本次结果作为一条 `JunkCleanup` 报告追加到 `OptimizationReports`，复用步骤 1.4 的保存逻辑。

2.4 第二次确认：点击"立即清理"按钮时弹出 `MessageBox.Show($"将删除 {count} 项，约 {size}，操作不可撤销。是否继续？", "确认清理", MessageBoxButton.YesNo, MessageBoxImage.Warning)`，"否"则取消。

### 步骤 3 — 微信数据定位（步骤 4 / 5 / 6 共用）

3.1 `WeChatDataLocator.LocateRoots()` 返回 `IReadOnlyList<WeChatRoot>`，每项含 `WxIdOrUserName`、`RootPath`、`Variant`（枚举 `LegacyWeChat`、`XWechat`）：
- **旧版 PC 微信**：`%USERPROFILE%\Documents\WeChat Files\` 下每个 `wxid_*` 子目录。注意"Documents"路径要使用 `Environment.GetFolderPath(SpecialFolder.MyDocuments)` 而**不是**硬编码。
- **新版 xwechat**：`%APPDATA%\Tencent\xwechat_files\` 下每个 `wxid_*` 或 `<手机号>_xxx` 子目录。
- 若用户曾在微信里改过保存目录，`Win32` 注册表 `HKCU\Software\Tencent\WeChat` 的 `FileSavePath` 优先（若存在且非 `MyDocument:`）。
- 找不到任何根 → 返回空列表，UI 显示"未检测到本机微信数据"。

3.2 在每个 `WeChatRoot` 下识别**子类目**（**禁止**触碰其它子目录，尤其 `Msg/*.db`、`MMKV/`、`config/`）：

| 类别 | 旧版子目录 | 新版子目录 |
|------|-----------|-----------|
| Image（图像）| `FileStorage\Image\<yyyy-MM>\` | `msg\attach\<chatHash>\<yyyy-MM>\Img\` |
| Video（视频）| `FileStorage\Video\<yyyy-MM>\` | `msg\video\<yyyy-MM>\` |
| Voice（语音）| `FileStorage\Voice2\<yyyy-MM>\*.amr` | `msg\audio\<yyyy-MM>\` |
| File（其它文件）| `FileStorage\File\<yyyy-MM>\` | `msg\file\<yyyy-MM>\` |
| Cache（缓存）| `FileStorage\Cache\` 全量 | `temp\` 全量 |

> 类别"文字"指**消息文本缓存**，但消息文本保存在 SQLite `MSG*.db`，**禁止**触碰这些 .db。本任务的"文字清理"含义为：清理 `FileStorage\CustomEmotion\`（自定义表情）+ `FileStorage\MsgTemp\` 等明确临时文本缓存。如不能确定，**跳过该类别**并在 UI 标注 `[待确认] 文字类别在新版尚未识别`。

3.3 时间过滤：以**文件 LastWriteTime** 为准（**不**读取消息数据库）。`<yyyy-MM>` 子目录命名只用作快速跳过整月，最终判定一律以单个文件 `LastWriteTime` 在 `[startDate 00:00, endDate 23:59:59.999]` 内为准。

### 步骤 5 — 微信备份（任务目标 4）

5.1 UI 卡片"微信备份"：
- 同样的日期 + 类别筛选控件。
- "选择保存目录"按钮（`FolderBrowserDialog`）。
- "开始备份"按钮：异步执行；右侧进度文字 `备份中：{当前文件名}（{i}/{total}）`。

5.2 备份文件 = 一个 zip：内部布局：
```
WeChatBackup/
  manifest.json
  files/<wxid>/<相对原路径>/<原文件名>
```
- `manifest.json` 结构：
```json
{
  "schemaVersion": 1,
  "createdAt": "2026-05-10T14:00:00+08:00",
  "machine": "PC-NAME",
  "wechatVariant": "XWechat",
  "wxId": "wxid_xxx",
  "wechatRoot": "C:\\Users\\u\\AppData\\Roaming\\Tencent\\xwechat_files\\wxid_xxx",
  "dateRange": { "start": "2025-01-01", "end": "2025-12-31" },
  "categories": ["Image", "Video", "Voice", "File"],
  "entries": [
    { "rel": "msg/attach/.../Img/abc.dat", "size": 12345, "lastWriteTime": "2025-06-12T10:11:12+08:00", "sha256": "..." }
  ]
}
```
- 使用 `System.IO.Compression.ZipArchive` 流式写入；压缩等级 `CompressionLevel.Optimal`。
- 单文件 SHA256 用 `SHA256.Create()` 计算，**仅哈希**，不保存内容明文。

5.3 进度通过 `IProgress<(int i, int total, string fileName)>` 回报；`fileName` 仅显示**相对路径**（保护用户隐私），日志记录同样仅相对路径。

5.4 备份成功后弹 `MessageBox.Show($"已备份 {count} 个文件（{size}）到 {zipPath}。", "备份完成")`，**不**追加到优化报告（备份与优化是两类记录）。

### 步骤 6 — 微信恢复（任务目标 5）

6.1 UI 卡片"微信恢复"：
- "选择备份文件"按钮（`OpenFileDialog`，`Filter = "微信备份 (*.zip)|*.zip"`）。
- 选定后立即解析 `manifest.json` 并展示：`微信版本 / wxId / 时间范围 / 类别 / 条目数 / 总大小`。
- 还原模式 `RadioButton`：`恢复到原微信目录`（默认）/ `恢复到自定义目录…`（点击启用 `FolderBrowserDialog`）。
- "开始恢复"按钮。

6.2 还原规则：
- 还原到原目录时：先校验 `manifest.wechatRoot` 当前是否仍存在；不存在则提示用户改用自定义目录。
- 同名冲突：在原文件名末尾插入 `.restored-{ticks}`，**禁止覆盖**任何已存在文件。
- 还原后比对 SHA256 校验；不一致则把该条记入 `restoreErrors` 列表，最终弹窗汇总。

6.3 还原过程中**禁止**触碰 `Msg/*.db`、`MMKV/`、`config/`，即使备份内不应包含它们也不容许写入这些目录的祖先以下任何文件名匹配 `^Msg.*\.db$` / `^MicroMsg.db$` 之类。

6.4 完成后弹 `MessageBox.Show($"恢复完成：成功 {ok}，失败 {fail}（详见日志）。", "微信恢复")`。

### 步骤 7 — UI 整体规范

## 【边界与限制】

- 当系统盘不是 C 盘时（罕见），`Optimize-Volume` 改读 `Environment.GetEnvironmentVariable("SystemDrive")`。无法读出则跳过该步并标 `Skipped`。
- 当用户没有管理员权限且 UAC 取消时，对应步骤标 `Failed`，`Detail` 写 `用户取消了 UAC 授权`，**不要**反复弹 UAC。
- 当 `Get-PhysicalDisk` 返回 MediaType 既不是 SSD 也不是 HDD（例如 `Unspecified`），`Optimize-Volume` 一律跳过并标 `Skipped`，**不要**默认按 HDD 强制 Defrag。
- 当微信数据根目录 > 20GB，扫描必须用 `EnumerateFiles` 流式处理，**禁止** `Directory.GetFiles` 一次性读取（会触发巨大 GC）。
- 当 zip 解压时遇到 `..` 或绝对路径条目（zip slip），必须立即终止恢复并 `MessageBox` 报错，**禁止**忽略。
- 当备份目标磁盘空闲空间 < 备份预估大小 × 1.1，提前用 `MessageBox.Show("目标磁盘空间不足，请更换位置后重试。")` 退出，**不要**写到一半失败。
- 如果遇到本说明书未列出的微信子目录但匹配类别命名规律，**不要**自行加入清理/备份范围；记录到 `[待确认]` 写入 `docs\规划\待确认微信目录.txt`。
- 如果 `report-...json` 反序列化失败，跳过该条并记日志，**不**让整个列表加载失败。
- 如果删除某个垃圾文件被占用 (`IOException`)，标记 `Skipped` 并在报告 `Detail` 中说明 `被进程占用`，**不要**重试 5 次以上。

## 【示例】

**正例 1（路径白名单校验）**：
```csharp
private static bool IsPathInsideAny(string fullPath, IEnumerable<string> roots) {
    var p = Path.GetFullPath(fullPath).TrimEnd('\\');
    foreach (var r in roots) {
        var rr = Path.GetFullPath(r).TrimEnd('\\');
        if (p.Equals(rr, StringComparison.OrdinalIgnoreCase)) return true;
        if (p.StartsWith(rr + "\\", StringComparison.OrdinalIgnoreCase)) return true;
    }
    return false;
}
```

**反例 1**：`if (path.Contains("Temp")) Delete(path);` —— 用 `Contains` 判定路径会误删 `C:\MyProject\TemplateFiles\` 之类目录，**严禁**。

**正例 2（微信视频清理）**：用户选 2025-01-01 ~ 2025-06-30，类别勾选"视频"，扫描结果只来自 `xwechat_files\<wxid>\msg\video\<yyyy-MM>\` 下且 `LastWriteTime` 落在该区间的 `*.mp4`/`*.dat`。

**反例 2**：把 `xwechat_files\<wxid>\Msg\Multi\MSG0.db` 当作"其它文件"删除 —— 触碰消息数据库，**严禁**。

**正例 3（自动优化白名单）**：执行 `Optimize-Volume -DriveLetter C -ReTrim`（系统盘 SSD）。

**反例 3**：执行 `cleanmgr /sagerun:1` 弹出系统磁盘清理对话框 —— 与"无人值守自动优化"的 UX 期望冲突，**不要使用**。

**正例 4（zip slip 防护）**：解压前 `var dest = Path.GetFullPath(Path.Combine(targetRoot, entry.FullName)); if (!dest.StartsWith(targetRootFull, OrdinalIgnoreCase)) throw;`。

**反例 4**：直接 `entry.ExtractToFile(Path.Combine(targetRoot, entry.FullName));` —— 可能写到 `C:\Windows\` 任何位置。

**正例 5（报告删除）**：用户在 DataGrid 勾选 3 条，点"删除选中"，`MessageBox.YesNo`，确认后逐个 `File.Delete(report-Id.json)` 并刷新 `index.json`、`OptimizationReports`。

**反例 5**：删除时只从 `OptimizationReports` 移除内存对象，未删磁盘 JSON —— 下次启动会复活，**禁止**。
