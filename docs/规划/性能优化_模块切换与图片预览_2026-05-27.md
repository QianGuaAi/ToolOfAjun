# 性能优化基线与计划（2026-05-27）

## 触发原因
用户反馈“项目速度目前有些慢”，重点场景：
- 切换模块卡顿（尤其是进入多媒体）
- 照片文件夹 100+ 张或单张 >5MB 时明显

## 当前已识别瓶颈（已部分修复）
1. **MainModulesView.xaml = 4378 行 / ~418KB**（最大问题）
   - 包含 System 7 个子分区 + SqlExport / Screenshot / ImageViewer / Codex / FileVerify / Convert / Benchmark 等全部内联 DataTemplate。
   - 每次首次进入非 Home 模块都会触发大量 XAML 解析 + 模板实例化。
   - 违反 AGENTS.md 9.3 “单个面板 XAML 行数超过 800 行时，必须抽出”规则。

2. **Multimedia 大图预览**（已修复）
   - LoadBitmap 全分辨率解码 → 内存尖峰 + 解码时间。
   - 修复：预览 960px、沉浸 1920px DecodePixelWidth。

3. **Schedule 自定义虚拟化网格**
   - Rebuild() 为全部员工创建 RowDefinition + 完整 cell 数组（_cellButtons[emp, day] 等）。
   - 即使有 overscan 渲染，结构仍重。
   - 大型排班（50+ 人）切换/编辑/缩放时成本高。

4. **其他**
   - 微信/垃圾扫描等文件遍历（IO 密集，已有后台 + 取消 token）。
   - 两处 sync Dispatcher.Invoke(MessageBox)（已改为 BeginInvoke）。

## 已执行的安全改进（2026-05-27 持续更新）
- Multimedia 图片降采样（预览 960px / 沉浸 1920px）。
- 两处 Invoke 改为 BeginInvoke。
- Multimedia 列表新增“预览”列 + 160px 懒加载 Thumbnail（MediaFileItem），针对大照片文件夹列表性能。
- Schedule overscan 提升至 12。
- XAML 拆分启动（SystemOptimizationView 骨架，安全策略避免破损）。
- 多次 Release 构建验证。
- 开发记录 + 本规划文档更新。
- 未修改任何启动期（App / MainWindow / MainViewModel ctor）代码，严格遵守黄金 500ms 规则。

## 后续优化计划（按优先级，需用户确认后执行）
1. **XAML 拆分（最高优先，最大收益）**
   - 目标：把 MainModulesView.xaml 降到 < 1500 行。
   - 第一步：提取 `SystemOptimizationView.xaml`（含电源常亮、自动优化、垃圾、微信清理/备份完整内容）。
   - 后续：NetworkView、StartupView、UninstallView、SystemInfoView、BenchmarkView、FileVerifyView 等。
   - 拆分后首次模块切换 XAML 成本预计下降 50%+。

2. **Multimedia 进一步优化**
   - 列表缩略图也加 DecodePixel（当前列表可能也全尺寸）。
   - 考虑虚拟化文件夹列表（如果单文件夹 >500 文件）。

3. **Schedule 网格强化**
   - 当前 overscan 已较好，但可考虑把员工行完全改用 VirtualizingStackPanel + 轻量 DataTemplate（降低 Grid 本身开销）。
   - 或者在员工数 >40 时自动降低渲染精度。

4. **其他**
   - 视频波形生成后台化 + 缓存。
   - Codex 大档案列表虚拟化（当前 ObservableCollection + ListBox）。
   - 可能的话把更多 DeferredTemplate 真正做成按需加载的 UserControl。

## 安全 XAML 拆分执行计划（避免重复 parse error）
1. 保持主文件可构建状态（使用 git checkout 作为最后恢复手段）。
2. 逐步将每个 TabItem 的内容从 DataTemplate 迁移到 SystemOptimizationView.xaml （一次一个 Tab 或小块）。
3. 每次迁移后，用小字符串 replace 将对应部分从主文件的 DataTemplate 中注释掉或移除。
4. 最终将整个 OptimizationHost 替换为 <views:SystemOptimizationView /> 。
5. 对其他大块（SqlExportDeferredTemplate 等）重复此过程，一次一个大模板。
6. 目标：主文件降至 <1500 行，同时保持 UI 和 DataContext 完全一致。
7. 每步后立即 `dotnet build -c Release` 验证。
