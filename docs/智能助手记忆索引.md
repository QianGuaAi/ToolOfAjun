# 智能助手记忆索引

本文件只负责给智能助手指路，不重复各规则文件的细节。执行 Inspect 阶段时，先按任务类型选择最少必要文档，再读取真实代码；不要把已归档规划当作当前事实来源。

## 一、优先读取顺序

1. 根 `AGENTS.md`：项目原则、技术栈、Loop Engineering 总规则、性能红线、禁令和变更日志。
2. 本索引：判断还需要读取哪些功能、逻辑、场景或规划文档。
3. 任务直接相关的文档、源码文件、构建脚本和验证脚本。
4. `docs\规划\已经执行\` 仅作历史证据，默认不作为后续实现入口。

## 二、任务到记忆位置

| 任务类型 | 优先读取 |
| --- | --- |
| Loop Engineering 记忆沉淀、失败复用、过期记忆清理 | `docs\LoopEngineering记忆沉淀.md`、`.agents\skills\mytools-loop-engineering\SKILL.md`、`.codex\agents\mytools-reviewer.toml`、`scripts\codex-eval.ps1` |
| 用户可见功能、入口、使用说明 | `docs\功能说明.md` |
| 模块行为、Service/ViewModel/View 逻辑 | `docs\程序逻辑.md`、相关 `src\MyTools\**` |
| 可见控件、场景流程、操作核查 | `docs\场景驱动开发\场景驱动开发范式.md`、`业务流程清单.md`、`场景实现核查台账.md`、`控件交互逻辑说明.md` |
| 启动性能、内存、IO、GC、面板可见性 | `AGENTS.md` 第九章，必要时补充 `docs\规划\` 下的启动基线记录 |
| 安装包、单 exe 分发、payload 验证 | `scripts\Build-Installer.ps1`、`scripts\codex-eval.ps1`、`AGENTS.md` 第五章 |
| C/C++ Native 重写、原生壳、CMake、Win32/Direct2D/DirectWrite | `AGENTS.md`、`docs\规划\C++原生重写总体规划.md`、`src\MyTools.Native\**`、`scripts\native-eval.ps1`、`scripts\codex-eval.ps1` |
| 构建验证、回归检查 | `scripts\codex-eval.ps1` |
| 给其他智能助手的任务说明 | `docs\规划\` 下能反映主题的中文文件名 |
| 历次修改点 | `docs\开发记录.txt`，只追加用户可见变更、验证命令和必要版本信息 |

## 三、维护要求

- 新增或改名长期规则文档时，同步更新本索引。
- 如果某条记忆已经被测试或 `scripts\codex-eval.ps1` 稳定覆盖，可以在文档中保留简短规则和验证入口，不再展开重复过程。
- 如果索引引用的路径、函数、组件或命令不存在，优先修正索引或对应规则，禁止继续把不存在的引用当作当前事实。
