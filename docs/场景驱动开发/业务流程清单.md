# 业务流程清单

> 文档定位：本文是场景驱动开发范式自动生成并持续维护的业务事实清单。它记录真实岗位、真实入口、真实步骤、前后置条件、异常路径和待确认业务规则。
> 本文件使用新项目推荐文件名；请按项目实际业务补齐角色、入口、场景和待确认项。
> 本文只回答“业务应该怎么做”，不记录代码实现状态；实现状态写入 `场景实现核查台账.md` 或当前项目对应的实现核查文件，控件事实写入 `控件交互逻辑说明.md` 或当前项目对应的控件说明文件。

## 一、维护规则

1. 用户输入 `开qg` 并确认执行后，若场景涉及业务步骤、岗位角色、入口位置、前后置条件、异常路径或业务规则变化，必须同步维护本文。
2. 首次启用场景驱动开发时，可以根据用户说明、旧文档、菜单、路由、测试和代码入口生成初稿。
3. 无法从用户、代码、运行结果或既有文档确认的信息，必须标注 `[待确认]`。
4. 本文不得记录未经确认的业务规则，不得把实现状态写成业务事实。
5. 每次只修改发生变化的章节；除非用户明确要求重建模板，不得整文件重写。

## 八、与其它活文档的同步

1. 本文新增或调整场景后，必须在实现核查台账中补充或更新对应条目。
2. 本文涉及页面、弹框、控件、按钮、筛选项、表格列、提示文案、禁用状态、校验规则、跳转逻辑或权限展示变化时，必须同步控件交互逻辑说明。
3. 实现核查发现代码行为与本文不一致时，必须判断是代码缺口、文档过期还是业务规则未确认；不能直接把不一致写成已完成。
