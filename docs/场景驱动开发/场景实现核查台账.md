# 场景实现核查台账

> 文档定位：本文是场景驱动开发范式自动生成并持续维护的实现状态账本。它记录每个业务场景当前在代码、界面、接口、数据、权限和验证中的落地程度。
> 本文件使用新项目推荐文件名；请按项目实际代码、运行结果和验证证据补齐每个场景的实现状态。
> 本文只回答“代码现在实现到什么程度”，不重新描述完整业务流程；业务步骤写入业务流程清单，控件事实写入控件交互逻辑说明。

## 一、维护规则

1. 用户输入 `开qg` 并确认执行后，必须为本轮场景更新或新增核查条目。
2. 每个条目必须有证据，证据可以是源码文件、接口、页面、测试、构建、截图、日志或实际运行结果。
3. 没有证据时，不得标为 `已实现`。
4. 发现旧结论与当前代码不一致时，必须更新状态并写明新证据。
5. 每次只修改相关场景条目；除非用户明确要求重建模板，不得整文件重写。

## 二、状态口径

| 状态 | 判定标准 |
|---|---|
| 未核查 | 业务流程清单已有场景，但尚未检查代码和运行行为。 |
| 未实现 | 没有可用入口、接口、服务或数据闭环。 |
| 部分实现 | 有部分入口或能力，但主路径、异常路径、权限、数据一致性、控件或验证存在缺口。 |
| 已实现 | 主路径和必要异常路径可用，有代码证据，并通过与风险匹配的验证。 |
| 已阻断 | 已检查到明确阻塞，需用户确认业务规则、环境、凭据、第三方系统或高风险操作口径后才能继续。 |
