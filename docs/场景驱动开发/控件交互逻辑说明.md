# 控件交互逻辑说明

> 文档定位：本文是场景驱动开发范式自动生成并持续维护的用户界面事实说明书。它记录用户可见页面、弹框、控件、按钮、筛选项、表格列、提示文案、禁用状态、校验规则、跳转逻辑和权限展示。
> 本文件使用新项目推荐文件名；请按项目实际页面、弹框、控件和权限展示补齐界面事实。
> 本文只回答“用户看得见、点得到、会收到什么反馈”，不记录完整业务流程或实现状态。

## 一、维护规则

1. 用户输入 `开qg` 并确认执行后，若本轮新增、删除或编辑任何用户可见控件，必须同步维护本文。
2. 控件说明必须来自源码、运行界面、截图、测试或用户确认，禁止凭空补写不存在的控件。
3. 删除控件时，必须同步删除或标注对应说明，避免留下孤儿控件说明。
4. 控件权限、禁用状态、校验规则和跳转逻辑必须和真实代码行为一致。
5. 每次只修改相关页面或控件条目；除非用户明确要求重建模板，不得整文件重写。

4.1.1实时传感器标签页

页面功能描述：系统信息页的"实时传感器"标签展示刷新模式、刷新按钮、停止/启动采集按钮、状态标签和 CPU/显卡/主板/风扇/CPU 占用摘要。

4.1.1.1"实时传感器采集控件组"控件类型为下拉框 + 图标按钮 + 文本按钮 + 状态标签，功能是控制和反馈传感器采集。

控件编号：4.1.1.1
控件名称：实时传感器采集控件组
控件类型：下拉框 + 图标按钮 + 文本按钮 + 状态标签
所在页面或弹框：系统信息页 / 实时传感器标签
可见条件：进入"系统信息"模块后，切换到"实时传感器"标签时可见。
启用条件：刷新模式下拉框始终可选择"手动 / 2 秒 / 5 秒"；"刷新"按钮在 `_sensorService != null` 时可点击；"停止采集"按钮始终绑定 `ToggleHardwareSensorsCommand`，传感器未启动时点击会异步启动采集，已启动时点击会停止并释放采集服务。
点击或输入行为：进入"系统信息"模块时异步加载硬件摘要，并通过 `StartSensorsBackgroundAsync()` 在后台启动传感器；用户点击"刷新"时通过后台线程执行一次 `ReadAll()`；用户选择"手动"时停止自动计时刷新，选择"2 秒"或"5 秒"时按对应间隔刷新；用户点击"停止采集"时停止定时器、解绑 Tick、清空传感器读数并释放服务。
成功反馈：状态标签显示"正在启动传感器..."、"已启用 · N 项 · X刷新"、"已刷新 · N 项 · 手动"或"已刷新 · N 项 · 每 X"；CPU 温度、显卡温度、主板温度、风扇转速和 CPU 占用摘要随读数刷新；首页温度风险摘要同步更新为正常或异常提示。
失败反馈：启动失败时显示"传感器启动失败：..."；非管理员或硬件不支持时显示"当前为非管理员模式..."或"未读取到传感器数据..."；读取异常时状态摘要显示"传感器读取失败：..."。
校验规则：启动和读取均不得在 UI 线程同步探测硬件；重复启动通过 `_isSensorStarting`、`_sensorService` 和 `_isSensorsRunning` 防重；重复刷新通过 `_isSensorRefreshing` 防重；温度不低于 85 或负载不低于 95 时生成异常提示。
跳转逻辑：无跨页面跳转；离开系统信息页时暂停传感器计时刷新，再进入时恢复或重新按需启动。
权限边界：本地桌面功能，无角色权限；温度、风扇、电压等读数依赖 LibreHardwareMonitor 驱动权限，非管理员模式通常只能读取有限数据。
关联接口或命令：`ShowSystemInfoCommand`、`SwitchModule("SystemInfo")`、`StartSensorsBackgroundAsync()`、`ToggleHardwareSensorsCommand`、`RefreshSensorsOnceCommand`、`RefreshSensorsAsync()`。
关联业务场景：启动后按需查看硬件传感器
证据来源：`src/MyTools/Views/SystemInfoView.xaml`、`src/MyTools/ViewModels/MainViewModel.cs`、`docs/规划/启动基线-启动后菜单响应-2026-06-24.md`

### 5. Codex 账号切换器

5.1本地中转模块

模块功能描述：管理 Codex 账号档案、本地 relay 启停、通过本地中转切换上游，以及为 Cursor / OpenAI-compatible 客户端提供模型列表和 Chat Completions 兼容兜底。

5.1.1本地中转控制区

页面功能描述：Codex 账号切换器顶部展示本地中转状态圆点、状态文本、启动本地中转、停止使用本地中转和重启 Codex 使用中转按钮；档案列表中的切换按钮在本地中转模式下显示为"本地切换"。

5.1.1.1"本地中转控制区"控件类型为状态标签 + 文本按钮组，功能是启停本地中转并切换 Codex 档案到本地中转上游。

控件编号：5.1.1.1
控件名称：本地中转控制区
控件类型：状态标签 + 文本按钮组
所在页面或弹框：Codex 账号切换器顶部控制区
可见条件：进入"Codex 账号切换器"模块后常驻可见。
启用条件："启动本地中转"始终可点击；"停止使用本地中转"仅 `CanDisableCodexLocalRelay` 为 true 时可点击；"重启 Codex 使用中转"仅本地中转状态为绿色且不在检测中时可点击；档案行按钮在本地中转已启用时显示"本地切换"。
点击或输入行为：点击"启动本地中转"会从当前 Codex 配置生成本地 relay 设置，启动 relay 并通过 relay 测试当前 NewAPI；点击"停止使用本地中转"会停用 MyTools 本地 relay 设置并把档案按钮恢复为普通"切换"；点击"重启 Codex 使用中转"会把 Codex 配置固定到本地 relay 后重启 Codex App；点击档案行"本地切换"会先测试目标 NewAPI，测试通过后只切换本地中转上游，不覆盖当前 `~/.codex`。
成功反馈：状态圆点按未知/测试/成功/失败显示不同颜色；状态文本显示"本地中转：..."和检查时间；启动成功后状态消息提示当前本地固定连接与测试结果；本地切换成功后弹窗提示 Codex 固定连接、当前上游和是否需要重启 Codex。
失败反馈：启动、停用、配置固定或目标上游测试失败时，状态圆点转失败色，状态文本和 `CodexProfilesStatusMessage` 显示失败原因，并弹出对应错误或警告提示。
校验规则：本地中转请求需要本地 token 授权；日志只记录主机、路径、状态码和错误类型，不记录上游 key、本地 relay token、请求体或响应正文；OpenAI-compatible 客户端访问 `/v1/models` 时可返回本地模型列表，访问 `/v1/chat/completions` 且上游拒绝或返回非 OpenAI 内容类型时可转换为 `/v1/responses` 并把 JSON 或 SSE 结果转回 Chat Completions 格式。
跳转逻辑：无跨页面跳转；"重启 Codex 使用中转"会关闭并重新打开 Codex App；本地切换成功后当前 Codex 后续请求使用新的上游。
权限边界：本地桌面功能，无角色权限；会读取和写入当前用户 `~/.codex` 配置及 MyTools 本地 relay 设置，敏感配置内容按既有 DPAPI 保护规则保存。
关联接口或命令：`EnableCodexLocalRelayCommand`、`DisableCodexLocalRelayCommand`、`RestartCodexWithLocalRelayCommand`、`SwitchCodexProfileCommand`、`CodexLocalRelayService`、`CodexLocalRelayCompatibility`。
关联业务场景：本地中转接入 Cursor 与 OpenAI-compatible 客户端
证据来源：`src/MyTools/Views/MainModulesView.xaml`、`src/MyTools/ViewModels/MainViewModel.cs`、`src/MyTools/Services/CodexLocalRelayService.cs`、`src/MyTools/Services/CodexLocalRelayCompatibility.cs`
