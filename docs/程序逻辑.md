# MyTools 程序逻辑

---

## 一、排班管理

### 1.1 表格结构

每月排班表采用 **3 行表头 + 人员数据行 + 1 行实际汇总**：

| 行号 | 内容 | 说明 |
|---|---|---|
| 第 1 行 | 星期 | 周一 ~ 周日循环显示 |
| 第 2 行 | 日期 | 当月 1 ~ 28 / 29 / 30 / 31 |
| 第 3 行 | **实休** | 该列实际休息人员合计（只读，自动汇总） |
| 第 4 行 | **总休** | 该列**目标休息人数上限**（硬约束，可手工编辑） |
| 第 5 行起 | 人员行 | 每行一名员工，列对应日期 |

> **实休 > 总休** 时两行同时标红，提示越界。**实休 < (总休-0.5)** 时两行同时标红，提示越界。优化器会尽力把实休贴近总休。

### 1.2 手工指定

点击单元格弹出下拉菜单，可选下列标识：

| 标识 | 含义 | 计入上班 | 计入休息 |
|---|---|---|---|
| **白** | 白班 | 1 | 0 |
| **卡** | 卡班 | 1 | 0 |
| **副** | 副小 | 1 | 0 |
| **感** | 感染科 | 1 | 0 |
| **大** | 大夜 | 1 | 0 |
| **小** | 小夜 | 1 | 0 |
| **休** | 休息 | 0 | 1 |
| **公** | 公休 | 0 | 1 |
| **午** | 下午休 | 0 | 0.5 |

> 「夜」与「大」指向同一含义（大夜），统一以 **「大」** 为最终显示字符与统计键。

#### 1.2.1 夜班快捷设置（自动联动）

| 快捷 | 当天 | 前一天 | 后续 | 序列 |
|---|---|---|---|---|
| **大1** | 大 | 小 | 后两天 = 休 | 小 → 大 → 休 → 休 |
| **大2** | 大 | 小 | 后一天 = 休 | 小 → 大 → 休 |

- 通过快捷写入的 **小 / 大 / 休** 同样视为**手工锁定**，参与"手工最高优先级"。
- 若用户单独选「大」（不走快捷），只写当前格，不自动派生小夜和后休。

### 1.3 自动设置休息日

点击 **「开始设置休息日」**。系统在尊重手工锁定的前提下，对剩余未指定单元格做智能优化。

#### 1.3.1 基本规则

- 自动生成**只填「白」与「休」**两种值，不会自动派出卡 / 副 / 感 / 大 / 小 / 公 / 午。
- 再次点击时，**之前自动生成的休息格**默认会**全部清空重算**；只有前端通过 `preserved_cells` 显式标记的格子才会保留。
- 自动生成开始前会获取当月排班表锁，**避免并发生成互相覆盖**。
- 依赖**广西法定节假日**配置；目标年份配置缺失时直接报错。
- 节假日集合 = **周六 ∪ 周日 ∪ 法定节假日**；周末双休专门关注 (Sat, Sun) **整对**。

#### 1.3.2 优化优先级（高 → 低）

| 级别 | 规则 | 类型 |
|---|---|---|
| **H1** | 每天**（总休-0.5）≤ 实休 ≤ 总休** | **硬约束** |
| **H2** | 任何人连续上班天数 ≤ **5 天** | **硬约束** |
| **H3** | 每个人月休息天数 ≥ 9 天 | **硬约束** |
| S1 | 周末（周六 + 周日）连续休息 2 天，并尽量均衡 | 软目标 |
| S2 | 休息日尽量落在节假日（含周末 + 法定节假日），并尽量均衡 | 软目标 |
| S3 | 每人节假日休息 ≥ **4 天**，并尽量均衡 | 软目标 |
| S4 | 每人月度总休天数尽量均衡 | 软目标 |
| S5 | 尽量让人上班时间和休息时间连续 | 软目标 |
| S6 | 尽量让每个人在月内有连续休息≥2天的次数≥3 | 软目标 |

> 半天精度：仅「午」计 0.5 天休息，其余休息标识均计 1 天。所有统计（上班 / 休息 / 连上）必须**实时准确**，支持 **0.5 天精度**。

#### 1.3.3 拒绝生成的硬性场景

| # | 场景 | 行为 |
|---|---|---|
| 1 | 法定节假日配置缺失 | 报错并提示补充配置 |
| 2 | 总休 − 锁定休息后，剩余为**奇数个半天** | 拒绝（自动休息只能补整天） |
| 3 | 当日因 H2 需强制休息的人数 > 当日剩余休息名额 | 报错并指出冲突 |
| 4 | 写回前逐日校验出现**实休 > 总休** | 拒绝写回 |

#### 1.3.4 节假日容量警告（非阻断）

若受总休上限与手工锁定格约束，导致部分人员节假日休 < 4 天目标，Service 返回**警告**（非错误），结果仍写入。

#### 1.3.5 多方案与重复点击

- 生成器跑**多轮候选**，按评分挑最优：周末双休均衡 → 节假日均衡 → 月休 / 两日连休 / 低于目标。
- 每次执行使用新的随机种子，使**重复点击「开始设置休息日」**能得到不同但都合规的方案，便于挑选。
- 「无警告再显示」复选框打勾时，只显示零警告的方案；当前候选若有警告，自动进入下一轮随机生成，直至得到完全合规（零警告）的结果。若所有候选均含警告，停止并显示警告数最少的方案，提示"无法生成零警告方案"。

### 1.4 手工最高优先级与跨月

- **手工锁定（含夜班联动派生）的格子永远不会被自动覆盖**，是所有自动流程的输入而非输出。
- 跨月夜班按**实际归属月份**分别计入两个月的统计。
- 自动生成成功后更新 `generated_time` 字段，作为「本月已生成」的判据。

### 1.5 表格初始化

点击 **「新建」**：

1. 按所选年月生成空白排班表。
2. 自动复制上月**人员名单**（仅姓名，本月格子从空白开始）。
3. 上月每日休息人数**不直接套用**到本月。

**第 4 行 总休 默认值：**

| 周次 | 默认人数 |
|---|---|
| 周一 ~ 周五 | 6 |
| 周六 | 8 |
| 周日 | 9 |

> 第一个月没有上月可继承时，从导入表或手工添加开始。

### 1.6 保存与版本

- **保存校验**：年月、人员行、每日休息人数数组长度、0.5 步进。
- **空姓名行**：视为占位行，不参与自动生成。
- 普通保存会保留前端提交的 `preserved_cells`；**生成排班前保存**不保留旧自动休息，避免锁死旧结果。
- 旧人员行与旧单元格按保存结果**整体重建**。
- 新建时需输入版本名称；已存在同名版本则**直接覆盖**。
- 每个月支持保存多个版本，**版本列表显示在左侧**。

### 1.7 Excel 导出

- 仅当本月**已生成过排班**（`generated_time` 非空）时允许导出，未完成表会被拒绝。
- 导出范围严格限定在排班数据本身，不串入其它业务模块。

## 二、SQL Server 导出

### 2.1 连接与认证

- **仅支持 SQL 身份验证**，不支持 Windows 身份验证。
- 连接历史（服务器/用户名/密码）本地保存，密码使用 **Windows DPAPI（当前用户范围）** 加密后落盘。
- 连接超时固定为 **10 秒**。

### 2.2 数据库与表枚举

- 优先查询 `sys.databases`（筛选 state=0 且 HAS_DBACCESS=1）；若触发 208 错误（无权限）则**降级为 `sp_databases`** 存储过程。
- 所有库名/架构名/表名均来自程序加载的**白名单**，使用方括号转义，**禁止拼接用户自定义 SQL**。
- 表名枚举来自 `INFORMATION_SCHEMA.TABLES`。

### 2.3 导出格式

#### 2.3.1 Excel 导出（OpenXML）

- **自写 `.xlsx`**，无需安装 Office，依赖 `DocumentFormat.OpenXml`。
- 超过 `1,048,575` 行时自动分 Sheet（每 Sheet 最多 `1,048,575` 数据行 + 1 行表头）。
- 日期/时间类型使用独立的 style index。

#### 2.3.2 CSV 导出

- UTF-8 (No BOM)。
- 字段含逗号/引号/换行者自动加双引号转义。

### 2.4 日志安全

日志中**不记录**完整连接字符串、密码；仅记录服务器名、用户名、操作步骤等非敏感摘要。

## 三、FRP 内网穿透

- 默认 frps 服务器为 `47.120.63.249:7000`；仅在用户本地 FRP 配置为空时作为兜底值，已有保存地址不覆盖。

### 3.1 frpc.exe 生命周期

- `frpc.exe` 以 GZip 嵌入程序集 `MyTools.NativeBinaries.frpc.exe.gz`；运行时解压到 `%TEMP%\MyTools\frpc.exe`。
- 或直接嵌入非压缩版本 `MyTools.NativeBinaries.frpc.exe`。

### 3.2 Token 安全

- 明文 Token 经 `ProtectedData.Protect(DPAPI, CurrentUser)` 加密后存 JSON。
- 日志中自动将 Token 脱敏为 `***`。

### 3.3 进程管理

- **启动判定**：捕获 `login to server success` / `start proxy success` 等关键字确认成功；**5 秒内未确认**则降级为仅判断进程 Running。
- **停止**：先 `CloseMainWindow`，等待 1.5 秒，最后 `Kill`。
- `frpc.ini` 临时存放于 `%TEMP%\MyTools\frpc.ini`。

### 3.4 规则生成

- 仅支持 **TCP** 隧道规则。
- 代理名由 `{machine}_{clientId}_{localPort}_{remotePort}` 组成，并做名称清理（仅保留字母数字下划线）。

## 四、Codex 账号管理

### 4.1 存储结构

- 档案库：`%LOCALAPPDATA%\MyTools\Codex\profiles.json`（DPAPI 加密）。
- 当前激活：`active.json`。
- 切换前自动备份：`~/.codex/` → `%LOCALAPPDATA%\MyTools\Codex\Backups\{name}_{yyyyMMdd_HHmmss}.bak.dpapi`。
- 进入 Codex 配置页时会确保触发档案库加载；如果页面已进入但列表为空、且本地 `profiles.json` 存在，同时此前未成功完成加载，则允许再次触发加载，避免切页或初始化竞态导致档案库显示为空。
- Codex 配置页的列表区域由 `CodexProfiles` 集合单独驱动；列表为空时显示 Codex 专属空态，不复用文件验证或其他模块的拖放区域。档案卡片的轮换设置固定在卡片第二行，避免未指定 Grid 行列导致控件叠压；操作按钮使用 Codex 面板局部紧凑样式，避免按钮过多时挤出卡片宽度。

### 4.2 档案复制

- 入口：在某条 Codex 档案上点击“复制”。
- 复制时先解析原档案中保存的 `config.toml` 与 `auth.json`；若任一文件内容不可用，则提示用户先刷新或重新导入，不创建新记录。
- 新档案名称使用“原名_复制”作为基础名，并通过 `EnsureUniqueCodexDisplayName()` 生成唯一别名。
- 新档案使用当前 Windows 用户 DPAPI 重新加密 `config.toml` 与 `auth.json`，重新解析邮箱、Access 过期时间和 `Status`。
- 新档案 `IsActive=false`、`LastAppliedAt=null`、`RelayTestStatus=未知`、`EnableRotation=false`；复制动作只保存档案库，不写 `active.json`，也不覆盖当前 `~/.codex`。

### 4.3 config.toml 模板同步

- 入口：在某条 Codex 档案上点击“应用到所有”。
- 同步前校验模板档案的 `config.toml` 必须存在 `base_url = ...` 行。
- 确认后先把当前档案库快照写入 `%LOCALAPPDATA%\MyTools\Codex\Backups\profiles_config_sync_<模板名>_<yyyyMMdd_HHmmss>.profiles.dpapi`。
- 对每个非模板目标档案：解密目标 `config.toml` → 找到目标自身的 `base_url = ...` 行 → 用模板 `config.toml` 替换目标配置 → 将目标原有 `base_url = ...` 行写回对应位置 → DPAPI 重新加密保存。
- 如果目标没有 `base_url = ...` 行，或模板与目标的 `base_url` 行数量不一致，则跳过该目标并在结果弹窗中列出原因。
- 该操作只更新档案库中的 `config.toml`，不修改 `auth.json`、别名、备注、轮换设置，也不直接写入当前 `~/.codex`。

### 4.4 账号轮换

- 从 `EnableRotation=true` 且状态**非「已过期」**的档案中，按 `RotationPriority` 升序、`LastAppliedAt` 升序选择下一个。
- 点击“全选轮换”时，将当前档案库全部档案的 `EnableRotation` 置为 `true`，并一次性保存档案库。
- 点击“反选轮换”时，逐条取反当前档案库全部档案的 `EnableRotation`，并一次性保存档案库。
- 点击“立即轮换”后，先对即将轮到的目标档案执行一次中转测试。测试不通过时停止轮换，仅更新目标档案的中转灯号和失败摘要，不备份、不覆盖当前 `~/.codex`。
- 测试通过后，若本地中转未启用，则执行普通切换：备份 → 写入 `~/.codex/config.toml` + `auth.json` → 询问是否温和重启 Codex Desktop。
- 测试通过后，若本地中转已启用，则只更新本地中转上游：把目标档案 token 与测试实际命中的有效 `base_url` 写入 `%LOCALAPPDATA%\MyTools\Codex\LocalRelay\local-relay.json`，token 使用 DPAPI 当前用户范围加密；本机 loopback 上游（如 Ollama `127.0.0.1:11434`）允许 token 为空，转发时不向上游发送 `Authorization`；如果档案原始 `base_url` 需要自动回退到 `/v1/...` 才可用，则保存回退后的上游基址，避免真实请求继续打到根路径 `/responses`；正常情况下不覆盖 `~/.codex/config.toml` / `auth.json`，也不提示重启；如果当前 Codex 配置已被手动还原、不再指向 `mytools_local_relay`、仍关闭 `disable_response_storage`，或本地 provider 的 `wire_api` / auth helper 不完整，则备份并修复固定本地 provider、response storage 与本地 token helper 设置，提示重启 Codex Desktop。
- “导入 Ollama 模型”只在用户点击时请求 `http://127.0.0.1:11434/api/tags`，按模型 digest 去重，并在短别名存在时过滤同类原始 HuggingFace 名称，随后为每个模型生成本地档案：`model_provider = "mytools_local_ollama"`，`base_url = "http://127.0.0.1:11434/v1"`，`wire_api = "responses"`，`auth.json` 保存为空 JSON；重复导入时按 `model:<模型名>` 标签更新同一条档案，不重复堆叠。
- 档案行主按钮根据本地中转模式动态显示：未启用本地中转时显示“切换”，已启用本地中转时显示“本地切换”；两者复用同一个命令，命令内部仍以 `CodexLocalRelayService.IsEnabledAsync()` 为准分流。
- 当前 Windows Codex Desktop 运行中的 app-server 不提供稳定的 auth/config 热加载入口；本机 `codex app-server daemon` 生命周期命令仍返回仅支持 Unix。
- “启动本地中转”基于当前 `~/.codex` 或已保存的 `%LOCALAPPDATA%\MyTools\Codex\LocalRelay\local-relay.json` 解析真实上游 `base_url` 与 token，使用 DPAPI 当前用户范围保存上游 key，拉起隐藏后台 relay，并通过 `http://127.0.0.1:<port>/v1` 对当前 NewAPI 做 `stream=true` 最小探测；该动作只更新面板 relay 状态灯，不修改当前 `~/.codex/config.toml`。
- “停止使用本地中转”把 `%LOCALAPPDATA%\MyTools\Codex\LocalRelay\local-relay.json` 标记为 `Enabled=false`，向隐藏 relay 发送本地停止请求，并把 `IsCodexLocalRelaySwitchMode=false`；所有档案行主按钮立即恢复为“切换”，后续手动档案切换重新走备份并覆盖 `~/.codex` 的普通流程。
- “重启 Codex 使用中转”只在 relay 状态灯为绿色时可用；点击后才生成 `[model_providers.mytools_local_relay]` 与 `[model_providers.mytools_local_relay.auth]`，把 Codex `base_url` 固定到 `http://127.0.0.1:<port>/v1`，把根级 `disable_response_storage` 固定为 `false`，生成 PowerShell helper 供 Codex `auth.command` 读取本地 relay token，并温和重启 Codex Desktop。重启流程会在关闭请求后反复重新扫描 Codex 进程，确认残留进程在短时间内稳定清空后才启动新实例，避免旧后台进程未退出时叠加打开新 Codex。若当前 Codex 已固定到 relay，则启动检测会优先使用 MyTools 自身保存的 DPAPI 上游配置，不要求当前 `~/.codex` 仍保留上游 key；固定配置判定会同时核对根级 provider、`disable_response_storage=false`、本地 `base_url`、`wire_api`、auth command、脚本路径、token 文件路径、超时和刷新间隔，任一缺失或不一致都会备份并重写。
- 本地中转由 `CodexLocalRelayService` 在模块延迟加载或用户点击“启动本地中转”时拉起 `MyTools.exe --codex-local-relay` 隐藏后台进程，使用 `TcpListener` 仅监听 `127.0.0.1`；启动逻辑以 `/health` 最终可达作为成功条件，健康检查会读取完整 HTTP 响应而不是只读首个 TCP 分片，即使并发启动的另一个后台进程因端口已被占用而退出，只要现有 relay 健康就不报错；后台进程每次请求前读取最新 `local-relay.json`，正在流式输出的请求继续走旧上游，下一次请求使用新上游；上游返回非 2xx 且保存的上游基址未包含 `/v1` 时，会在同主机同端口下自动补 `/v1` 重试一次，重试成功后把有效上游基址写回 `local-relay.json`；上游仍失败或本地转发异常时，仅向程序同目录 `MyTools.log` 写入方法、上游 host、路径、状态码或异常类型，禁止记录 token、请求体和响应正文。
- 本地中转启用后，如果目标档案解析不到 token 且不是本机 loopback provider，或 `wire_api` 与当前本地 provider 不一致，则停止轮换，避免让 Codex 使用不兼容路径；loopback provider 允许无上游 token。
- 过期提醒只基于已加载档案的 `AccessTokenExpiresAt` 和 `Status` 计算：顶部显示已过期 / 即将过期数量，档案卡片状态旁显示提醒标签；提醒属性不写入 `profiles.json`。
- 429 自动轮换在 Codex 档案库加载成功后启动：`CodexRateLimitLogMonitorService` 只读打开 `%USERPROFILE%\.codex\logs_2.sqlite`，首次读取 `MAX(id)` 作为基线，之后每 20 秒查询 `id > lastSeenId` 的最多 50 行；仅在 `codex.rate_limits` / rate-limit 日志解析到 `allowed=false` 或 `limit_reached=true` 时触发。
- 429 自动路径复用 `CodexRotationService.RotateToNextAsync(..., allowFullConfigSwitch: false)`，因此只允许本地中转或 hot-token 方式热切换；如果需要覆盖 `~/.codex` 或重启 Codex Desktop，则只更新面板状态，不自动执行，避免打断当前对话或命令。

### 4.5 JWT Token 状态判定

- 从 `auth.json` 中尝试多个路径提取 `access_token` / `id_token`。
- 解析 payload 中 `exp` 字段计算状态：
  - **正常**：剩余有效期 > 7 天
  - **即将过期**：剩余有效期 ≤ 7 天
  - **已过期**：`exp < now`

### 4.6 导出加密包（.codexbox）

- 密码经 **PBKDF2**（SHA256，200,000 次迭代）+ 16 字节 salt 生成 64 字节密钥。
- **AES-256-CBC** 加密内容。
- **HMAC-SHA256** 对 `[Header+Salt+IV+Ciphertext]` 做完整性验证。
- 文件格式：`Header(CDXB) + SchemaVersion + Salt + Iterations + IV + CiphertextLength + Ciphertext + MAC`

## 五、微信数据管理

### 5.1 目录定位

- 从 `Documents\WeChat Files`、`Documents\Tencent Files`、`Documents\xwechat_files`、`Documents\xwechat_files\all_users`、`%APPDATA%\Tencent\xwechat_files` 和微信注册表 `FileSavePath` 中定位账号目录。

### 5.2 扫描阶段

- 旧版微信枚举 `FileStorage` 下的 Image / Video / Voice2 / File / Cache / CustomEmotion / MsgTemp。
- 新版微信枚举 `msg\attach`、`msg\video`、`msg\file`、`cache`、`temp`、`resource`、表情缩略图与收藏临时目录。
- 按 `LastWriteTime` 过滤日期范围。

### 5.3 安全红线

- **禁止删除** `Msg*.db` 和 `MicroMsg.db`（核心聊天数据库）。
- 备份恢复禁止写入 `MMKV`、`config`、`db_storage`、`Msg*.db`、`MicroMsg.db`、`Login.dat` 和 `SafeStorage*` 等数据库、配置和登录态路径；新版 `xwechat_files` 的 `msg\attach`、`msg\video`、`msg\file` 媒体目录不按整目录禁止。
- 文件送到**回收站**（`RecycleOption.SendToRecycleBin`），不做永久删除。

### 5.4 备份格式

- ZIP 包，内含 `manifest.json`（描述来源、时间范围、类别）。
- 文件按相对路径存储。
- 备份前必须至少选择 1 个类别；恢复旧备份缺少 `category` 字段时，按缓存目录、媒体扩展名和目录段推断类别。

### 5.5 界面组织

| 微信恢复 | 读取备份 ZIP；选择原目录或自定义目录；按类别恢复；最近备份快捷入口 | `SelectWeChatRestoreZipCommand` / `StartWeChatRestoreCommand` |

卡片负责界面组织，微信定位、清理、备份、恢复服务仍分别在对应 Service 中执行。

## 六、系统优化

### 6.0 系统维护卡片

“系统优化”页面顶部页签中的“系统维护”使用单张卡片承载 3 段功能：

| 分段 | 功能 | 状态 |
|---|---|---|
| 系统锁定 | 读取当前 Windows 10/11 产品名与功能版本，写入目标版本锁定策略；应用常亮电源策略 | `SystemStatusMessage` / `PowerPolicyStatusMessage` |
| 安全防护 | 关闭/恢复 Windows Defender 实时防护；刷新状态；执行后读回实际状态，避免篡改保护拦截时误报成功 | `IsDefenderEnabled` 徽章 |
| 自动更新 | 停止/恢复 Windows 自动更新；处理 Win10/Win11 常见更新服务；立即触发更新 | `IsAutoUpdateEnabled` 徽章 |

卡片右侧操作区使用固定宽度操作列，按钮组在列内左对齐。`LockWin10Command` 保留历史绑定名，实际执行逻辑已改为按当前 Windows 10/11 版本锁定。

### 6.1 自动优化两步流程

“自动优化”页签分为两个动作：

| 阶段 | 触发 | 行为 |
|---|---|---|
| 扫描 | `ScanAutoOptimizeCommand` | 调用 `SystemOptimizationService.ScanAsync`，只读取系统状态并填充 `AutoOptimizePlanItems` |
| 优化 | `StartAutoOptimizeCommand` | 读取本次扫描结果中 `CanOptimize=true` 的步骤键，调用 `SystemOptimizationService.RunAsync(..., enabledStepKeys)` 执行实际优化 |

- 扫描阶段不会删除文件、清空回收站、重启 Explorer、启停服务、执行 UAC 提权脚本或写入系统设置。
- 扫描列表展示状态、项目、类型、预计释放空间、是否需要提权和说明。
- “优化”按钮仅在本次扫描结果中存在可优化项时可用；优化完成后清空本次扫描结果，用户再次优化前必须重新扫描。
- 历史报告仍写入 `OptimizationReports`，并可通过“查看”显示步骤明细。

### 6.1.1 10 步自动优化流水线

| 步骤 | 内容 | 权限 |
|---|---|---|
| 1 | 清空当前用户 Temp（24 小时前） | 普通 |
| 2 | 清空 Windows Temp（7 天前） | **UAC 提权** |
| 3 | 清理缩略图缓存（需要重启 Explorer） | **UAC 提权** |
| 4 | 刷新 DNS 缓存 (`ipconfig /flushdns`) | 普通 |
| 5 | 重置字体缓存（FontCache 服务） | **UAC 提权** |
| 6 | 清理 Windows Update 缓存 | **UAC 提权** |
| 7 | 系统盘 TRIM（SSD）/ 碎片整理（HDD） | **UAC 提权** |
| 8 | 清空回收站 | 普通 |
| 9 | 清理事件日志（Application/System/Security > 500MB） | **UAC 提权** |
| 10 | 压缩当前进程工作集（`EmptyWorkingSet`） | 普通 |

- 提权操作通过 PowerShell 脚本 + `runas` verb 实现，用户取消 UAC 则步骤标记为 Failed。
- 磁盘类型通过 `Get-Disk.MediaType` 检测是否为 SSD。

### 6.2 垃圾清理扫描范围

- 用户临时目录（24 小时前）
- 系统临时目录（7 天前）
- 回收站总容量
- Edge / Chrome 浏览器缓存
- 缩略图缓存（`thumbcache_*.db`）
- Prefetch（30 天前）

**安全白名单**：以下目录**永远不在扫描范围内**：`System32`、`WinSxS`、用户文档/桌面/图片/Downloads、`Program Files` 等。

## 七、截图与录屏

### 7.1 截图

- 使用 `Graphics.CopyFromScreen` 捕获**虚拟屏幕**（全屏 + 多显示器）。
- 通过 `GetCursorInfo` + `DrawIconEx` 绘制鼠标光标。
- P/Invoke `GetSystemMetrics` 获取虚拟屏幕坐标。
- “划区域”截图先捕获整张虚拟屏幕，再用 `RegionSelectorWindow` 显示半透明蒙层；窗口创建后按 HWND DPI 与虚拟屏幕物理像素重新定位，选区转换为像素矩形时左上边界使用 floor、右下边界使用 ceiling，避免高 DPI 或边界四舍五入导致右侧缺失。
- 剪贴板写入使用 `ScreenshotService.SetClipboardCompatible()`，先复制为 32 位 BGRA 位图，再同时写入 WPF Image、32 位 DIB 和 PNG 数据，避免任意宽度区域截图在部分粘贴目标中被误读为缺少右侧像素。
- 截图编辑器窗口创建前按需加载延迟 UI 资源，避免快捷键直接截图时尚未进入截图模块，导致 MaterialDesign `StaticResource` 解析失败。

### 7.2 视频 / GIF 录制

- 依赖 `ffmpeg.exe`，查找顺序：`%ExecutableDir%\NativeBinaries\ffmpeg\ffmpeg.exe` → PATH。
- 支持指定帧率、画质、GIF 模式。
- 启动探测超时：**700ms**。

### 7.3 音频录制（扬声器内录）

- 使用 `MMDevice` API + `WasapiLoopbackAudioRecorder`，**不需要麦克风**。

### 7.4 OCR

- 基于 Tesseract 实现文字识别。

## 九、多媒体转换

- **图片**：JPG / PNG / BMP / GIF / TIFF 互转，支持缩放、压缩质量控制。
- **视频 / 音频**：基于 ffmpeg 转码。
- **字幕**：支持 SRT / VTT / ASS 加载，时间戳解析。

## 十一、启动项管理

### 11.1 枚举范围

- 当前版本枚举注册表 Run 启动项：
  - `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`
  - `HKLM\Software\Microsoft\Windows\CurrentVersion\Run`
- MyTools 自己禁用过的项目保存在同范围根下的 `Software\AJunTools\DisabledRun`。
- Windows 自身的启用/禁用状态读取 `Software\Microsoft\Windows\CurrentVersion\Explorer\StartupApproved\Run`。

### 11.2 禁用与恢复

- 点击“禁用”时，程序将原 Run 值写入 MyTools 备份，再写入 `StartupApproved\Run` 禁用标记，最后删除 Run 值。
- 如果第三方软件重新写回同名 Run 值，刷新列表时以 `StartupApproved\Run` 为准，显示为“注册表 Run（Windows 已禁用）”，避免误判为普通已启用项。
- 点击“启用”时，程序优先从 MyTools 备份恢复命令；备份不存在时使用现有 Run 值或当前列表命令兜底，同时写入 Windows 启用标记。
- 点击“永久删除”时，同时删除 Run、MyTools 备份和 `StartupApproved\Run` 同名值。

### 11.3 边界

- 系统级启动项需要管理员权限。
- 本模块不处理计划任务、服务、驱动、浏览器后台服务等非 Run 自启入口。
- 启动项扫描只在用户进入模块或点击刷新时执行，不进入 `App.OnStartup` 或 `MainWindow` 构造函数。

## 十二、基础设施规范

| 约束项 | 内容 |
|---|---|
| **启动性能** | `App.OnStartup` 与 `MainWindow` 构造函数禁止执行超过 **50ms** 的磁盘 IO / WMI；所有重型操作通过 `Dispatcher.BeginInvoke(DispatcherPriority.ApplicationIdle, ...)` 延后 |

| **日志** | Serilog `flushToDiskInterval` ≤ **2 秒**；日志不记录密码/完整连接字符串；单条日志 ≤ 1 KB |
| **安全** | 敏感凭据使用 **Windows DPAPI（当前用户范围）** 加密；SQL 白名单校验 |
| **GC** | `App.config` 保留 `<gcServer enabled="true" />` + `<gcConcurrent enabled="true" />` |
| **单文件发布** | Costura.Fody 合并全部 DLL，`SQLite.Interop.dll` 通过 `EmbeddedResource` 嵌入 |

## 十三、Codex 中转测试

- 入口：Codex 配置面板顶部“测试中转”按钮；面板 relay 状态灯由“启动本地中转”按钮单独更新。
- 执行时机：仅在用户点击“测试中转”按钮、点击“启动本地中转”测试当前 NewAPI、点击“立即轮换”触发目标档案轮换前检查，或本地中转已启用时点击普通手动“切换”触发目标上游检查时发起网络请求；启动、加载档案、刷新账号均不自动测试远程上游。
- 输入：逐条读取档案库中 DPAPI 加密保存的 `config.toml` 与 `auth.json`，解析 `base_url`、`model`、`wire_api`、`requires_openai_auth`、`env_key`、`api_key`、`OPENAI_API_KEY` 和 `access_token`；Ollama 档案的 `auth.json` 是空 JSON。
- 请求规则：如果存在 `model`，优先按 `wire_api` 向 `{base_url}/responses` 或 `{base_url}/chat/completions` 发送 `stream=true` 的 1 token 最小请求，并自动追加 `{base_url}/v1/...` 回退路径；测试结果携带实际成功命中的有效上游基址，供本地中转保存；如果缺少 `model`，只请求 `{base_url}/models` 做连通性检查；如果档案使用 `requires_openai_auth = true` 且没有普通 API key，则只验证中转网关可达与配置完整性；如果 `base_url` 是本机 loopback 地址，则允许无 API key 并直接测试本机 provider。
- 结果记录：每条档案保存 `RelayTestStatus`、`RelayTestedAt`、`RelayTestMessage`，状态值为“可用 / 不可用 / 未知 / 测试中”；UI 用绿灯、红灯、灰灯或黄色测试中标识展示。
- 安全限制：日志与档案只保存别名、状态和 160 字以内摘要，不保存 token、完整认证头、请求正文响应正文或完整连接凭据。
