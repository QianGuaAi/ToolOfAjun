## Native 重写轨道（C++ 原生壳与基础服务）

- `src/MyTools.Native/` 是 C/C++ 原生重写轨道，当前处于阶段 1/2/3：Native Shell、基础服务与 Codex Profiles 承载点；该目录与既有 `src/MyTools/` WPF 程序并行，不直接依赖 WPF 编译产物。
- Native 轨道使用 C++20、Win32、Direct2D、DirectWrite、CMake + MSVC，并允许小型底层能力使用 C ABI。`CMakeLists.txt` 通过 `configure_file` 生成资源脚本，图标继续复用 `src/MyTools/Resources/AppIcon.ico`，并链接 `ws2_32` 支持 TCP 探测。
- `app/main.cpp` 执行启动主流程：启用 Per-Monitor V2 DPI → 创建单实例 Mutex → 初始化 `AppContext` → 初始化程序同级目录日志 → 安装崩溃处理 → 执行 DPAPI smoke test → 创建 Win32 主窗口 → 进入消息循环。
- `AppContext` 只解析当前 exe 路径、程序目录、产品名和 Native Shell 版本，不在启动期扫描磁盘或读取大型配置。
- `Logger` 将 `MyToolsNative.log`、`MyToolsNative.startup.log` 和 `MyToolsNative.crash.log` 写入程序同级目录，使用 UTF-8 追加写入；单条日志仍必须保持脱敏和短文本。
- `SecretStoreDpapi` 使用 `CryptProtectData` / `CryptUnprotectData` 做当前用户范围 DPAPI 往返测试，用于验证 Native 后续可承接旧版敏感数据迁移；同时提供 UTF-8 明文保护为 Base64、Base64 解回 UTF-8 的封装。
- `FileSystem` 提供路径拼接、存在性判断、二进制读取、UTF-8 读取、递归创建目录、二进制原子写入和 UTF-8 原子写入；写入流程先生成 `.tmp` 文件、`FlushFileBuffers`，再通过 `MoveFileExW(..., MOVEFILE_REPLACE_EXISTING | MOVEFILE_WRITE_THROUGH)` 替换目标文件。
- `ConfigStore` 只读写包含 `schema_version` 的 JSON 文本，不在当前阶段引入完整 JSON 解析器；schema token 检查下沉到 `ccore/json/mt_json_schema.c`，作为 C 层边界示例。
- `FileScanner` 使用 `FindFirstFileW` / `FindNextFileW` 做可取消文件枚举，支持最大结果数限制，并跳过 `FILE_ATTRIBUTE_REPARSE_POINT` 目录，避免 junction/symlink 越界扫描。
- `TaskRunner` 使用单后台线程、`std::queue`、`std::mutex` 和 `std::condition_variable` 顺序执行投递任务；服务析构时会停止并 join 线程。
- `ProcessRunner` 封装 `CreateProcessW`、进程句柄 RAII、运行状态判断、等待和 `TerminateProcess`；用于后续 FRP、外置 FFmpeg 等外部进程生命周期。
- `NetworkService` 使用 WinSock `WSAStartup`、`GetAddrInfoW`、非阻塞 `connect` 和 `select` 做带超时 TCP 连通性探测；启动期不主动访问网络，后续只能由用户动作触发。
- `HotkeyService` 封装 `RegisterHotKey` / `UnregisterHotKey`，析构时统一退订，供后续截图、录屏、录音全局快捷键迁移使用。
- `SingleInstance` 使用 `Local\AJunTools.MyToolsNative.SingleInstance` Mutex；当前 Native Shell 与既有 WPF 程序互不抢占单实例锁。
- `module_registry` 提供 Native 模块信息结构；当前包含 Home 与 Codex Profiles 两个模块。Home 展示阶段 1/2 基线和不迁回功能清单。
- `SecretStoreDpapi` 除 smoke test 外，还提供 `UnprotectBase64ToUtf8()`，用于兼容 WPF 版 `ProtectedData.Protect(..., CurrentUser)` 后 Base64 存盘的外层档案库格式；解密后明文缓冲会在摘要扫描后清零。
- `CodexProfileModule` 是阶段 3 的第一层承载点，通过 `LOCALAPPDATA` 与 `USERPROFILE` 解析 `%LOCALAPPDATA%\MyTools\Codex\profiles.json`、`active.json` 以及 `~\.codex\config.toml`、`auth.json` 路径。文件存在状态通过 `FileSystem::Exists` 探测；`profiles.json` 存在时通过 `SecretStoreDpapi::UnprotectBase64ToUtf8()` 解开外层档案库 JSON，按 `items` 对象逐条只抽取 `DisplayName / Name / Status / LastImportedAt` 作为摘要，最多展示 5 条；`active.json` 存在时读取 `ActiveDisplayName` 并标记当前档案；JSON 字符串扫描会解析 `\uXXXX` 与代理对，避免中文档案名在摘要中退化成问号。模块同时记录第一条可读档案的显示名，作为当前 Native 菜单的首批显式动作目标。
- `CodexProfileModule::RunUiAction()` 是 Native Codex Profiles 菜单动作路由层。当前动作包括刷新摘要、查看第一条档案差异、备份当前 `.codex`、应用第一条档案、导入当前 `.codex` 为新档案、恢复最近备份、导出第一条档案普通文件、改名第一条档案、编辑第一条档案 note/remark/tags、导出 `.codexbox`、导入 `.codexbox`；该层只返回弹窗摘要，不把 config/auth 正文或 token 写入 UI/日志。应用、导入、恢复、普通文件导出、改名、note/remark/tags 编辑和 `.codexbox` 导入/导出属于写入类动作，必须先由 `MainWindow::ConfirmCodexProfileWrite()` 弹出确认框，确认后才进入 service；普通文件导出的文件夹选择、改名的新显示名采集、note/remark/tags 的 `PromptText` 文本采集、`.codexbox` 路径选择和密码采集由主窗口完成，具体读写仍在 action 路由后的 service 内。
- `CodexProfileBackupService` 是阶段 3 的切换前保护与回滚底座。`CreateCurrentFolderBackup()` 可由 `Backup current .codex folder` 菜单直接触发，也会在显式应用档案前被切换 service 调用：读取当前 `~\.codex\config.toml` 与 `auth.json` 的原始字节，分别 Base64 写入 `native-codex-current-folder-before-switch` JSON 备份包，再使用 `SecretStoreDpapi::ProtectUtf8ToBase64()` 加密为 DPAPI Base64 文本，最后通过 `FileSystem::WriteUtf8FileAtomic()` 写入 `%LOCALAPPDATA%\MyTools\Codex\Backups\native_switch_<name>_<timestamp>.bak.dpapi`。若当前目录没有这两个文件，结果标记为 skipped，不产生备份文件。`RestoreLatestBackup()` 由 `Restore latest backup...` 菜单确认后触发：通过 `FindFirstFileW` / `FindNextFileW` 枚举最新 `.bak.dpapi`，用 `SecretStoreDpapi::UnprotectBase64ToUtf8()` 解开备份包，再用 `CryptStringToBinaryA` 分别解码 `ConfigTomlBase64` 与 `AuthJsonBase64`，最后通过 `FileSystem::WriteFileBytesAtomic()` 写回 `~\.codex\config.toml` 与 `auth.json`。恢复 service 不解析 token、不联网、不启动进程、不记录 secret-bearing payload。
- `CodexProfileDiffService` 是阶段 3 的显式差异摘要底座。`BuildProfileDiffSummary()` 由 `Diff first profile` 菜单触发，读取并解开外层 `profiles.json`，按 `DisplayName / Name` 定位目标 item，提取 `ProtectedConfigTomlBase64` / `ProtectedAuthJsonBase64`，并兼容旧字段 `ConfigTomlContentProtected` / `AuthJsonContentProtected`；随后用当前用户 DPAPI 解出目标 `config.toml` 与 `auth.json`，通过 `FileSystem::ReadFileBytes()` 读取当前 `~\.codex` 对应文件，并只生成存在性、大小、行数、一致性和 SHA-256 指纹摘要。该 service 使用 `BCryptOpenAlgorithmProvider(BCRYPT_SHA256_ALGORITHM)` 计算摘要，使用 `FileSystem::Exists()` 区分空文件和缺失文件，不解析 `access_token` / `refresh_token`，不写文件，不联网，不启动进程，不记录 secret-bearing payload；页面导航本身不会自动生成差异。
- `CodexProfileEditService` 是阶段 3 的显式元数据编辑底座。`UpdateProfileMetadata()` 读取并解开外层 `profiles.json`，按 `DisplayName / Name` 定位目标 item；调用方可选择更新 `DisplayName / Name`、`Note`、`Remark`、`Tags`，未选择的字段保持原值。`Rename first profile...` 由主窗口确认后采集新显示名，并在进入 action 前执行 trim、非空、最长 120 字符、禁止控制字符校验；若目标档案等于 `active.json` 中的 `ActiveDisplayName`，service 会在 `profiles.json` 改名写回后继续用 `FileSystem::WriteUtf8FileAtomic()` 更新 `active.json` 的 `ActiveDisplayName`，并保留原有 `SwitchedAtUtc` 等其它字段。`Edit first profile note...`、`Edit first profile remark...`、`Edit first profile tags...` 由主窗口确认后通过 `PromptText` 采集文本，进入 action 前执行 trim，允许空值以清空字段，note/remark 最长 500 字符，tags 最长 200 字符，均拒绝 C0/C1 控制字符。改名时会用 `CompareStringOrdinal(..., TRUE)` 检查其它 item 是否已有同名显示名，避免后续切换、导出、差异流程按显示名定位时歧义；保存时只替换目标 item 的元数据字段，再重新 DPAPI 保护整个档案库并用 `FileSystem::WriteUtf8FileAtomic()` 原子写回。由于 `profiles.json` 与 `active.json` 是两个独立文件，active 同步写入失败时会返回“profiles 已改名但 active.json 未同步”的局部失败提示，并要求页面刷新摘要；该 service 不命名、不读取、不解密内嵌 config/auth 字段，不联网，不启动进程，不记录 secret-bearing payload，不覆盖当前 `~\.codex` 文件；页面导航本身不会自动调用。
- `CodexProfileImportService` 是阶段 3 的当前目录导入底座。`ImportCurrentFolderProfile()` 由 `Import current folder...` 菜单确认后触发，显示名由模块生成 `Native current yyyyMMdd_HHmmss`；执行时先确认 `config.toml` 与 `auth.json` 存在，通过 `FileSystem::ReadFileBytes()` 读取原始字节，再将文本内容分别使用 `SecretStoreDpapi::ProtectUtf8ToBase64()` 加密后写入 `ProtectedConfigTomlBase64` / `ProtectedAuthJsonBase64`，并同步写入旧兼容字段 `ConfigTomlContentProtected` / `AuthJsonContentProtected`。若 `%LOCALAPPDATA%\MyTools\Codex\profiles.json` 不存在或缺少 `items` 数组，会创建 `schemaVersion=2` 最小档案库；若存在，则先用 DPAPI 解开外层 JSON，再把新 item 追加到 `items` 数组，最后重新 DPAPI 保护并通过 `FileSystem::WriteUtf8FileAtomic()` 原子写回。该 service 不解析 token，不联网，不启动进程，不记录 secret-bearing payload，不覆盖当前 `~\.codex` 文件。
- `CodexProfileExportService` 是阶段 3 的显式普通文件导出底座。`ExportProfileByDisplayName()` 读取并解开外层 `profiles.json`，按 `DisplayName / Name` 定位目标 item，提取 `ProtectedConfigTomlBase64` / `ProtectedAuthJsonBase64`，并兼容旧字段 `ConfigTomlContentProtected` / `AuthJsonContentProtected`；随后用当前用户 DPAPI 解出目标 `config.toml` 与 `auth.json` 文本，并通过 `FileSystem::WriteUtf8FileAtomic()` 写入用户明确选择的输出目录。`Export first profile files...` 由主窗口确认后选择文件夹，禁止目标等于当前 Codex 目录 `~\.codex`，避免无备份覆盖当前账号文件；该 service 不解析 `access_token` / `refresh_token`，不联网，不启动进程，不记录 secret-bearing payload；页面导航本身不会自动调用。
- `CodexProfileBoxService` 是阶段 3 的 `.codexbox` 加密包底座。`ExportBox()` 读取并解开外层 `profiles.json`，逐条解开内嵌 `ProtectedConfigTomlBase64` / `ProtectedAuthJsonBase64`，把明文 config/auth 改写为便携载荷中的 `ConfigTomlBase64` / `AuthJsonBase64`，然后用 `BCryptDeriveKeyPBKDF2()` 按 PBKDF2-HMAC-SHA256 200000 次派生 64 字节密钥，前 32 字节用于 AES-256-CBC + PKCS7，后 32 字节用于 HMAC-SHA256，输出 WPF 兼容的 `CDXB` 文件头格式。`ImportBox()` 先读取 `CDXB` 头、schema、salt、迭代数、IV、ciphertext 和 MAC，使用 `ConstantTimeEquals()` 定时比较 HMAC，通过后才解密便携载荷；导入时把包内 config/auth 用当前 Windows 用户 DPAPI 重新保护后合并入本机档案库；旧包若仍包含 `ProtectedConfigTomlBase64` / `ProtectedAuthJsonBase64` 或旧字段，则只在当前 Windows 用户可解密时重保护入库，跨用户旧包仍需要源用户用新版重新导出。该 service 不解析 token，不联网，不启动进程，不记录 secret-bearing payload，不覆盖当前 `~\.codex` 文件；当前已由 `Export .codexbox...` / `Import .codexbox...` 显式菜单通过 `CodexProfileModule::RunUiAction()` 调用，导出路径和两次密码确认在主窗口层完成，导入路径、整包冲突策略（Rename / Skip / Replace）和一次密码输入在主窗口层完成，`CodexProfileModule` 将 `options.box_conflict_policy` 传给 `CodexProfileBoxImportRequest::conflict_policy`。
- `CodexProfileSwitchService` 是阶段 3 的显式切换底座。`ApplyProfileByDisplayName()` 由 `Apply first profile...` 菜单确认后触发，读取并解开外层 `profiles.json`，按 `DisplayName / Name` 定位当前摘要第一条可读目标 item，提取 `ProtectedConfigTomlBase64` / `ProtectedAuthJsonBase64`，并兼容旧字段 `ConfigTomlContentProtected` / `AuthJsonContentProtected`；随后用当前用户 DPAPI 解出目标 `config.toml` 与 `auth.json` 文本，先调用 `CodexProfileBackupService::CreateCurrentFolderBackup()`，备份成功后再用 `FileSystem::WriteUtf8FileAtomic()` 写入 `~\.codex\config.toml`、`~\.codex\auth.json` 和 `%LOCALAPPDATA%\MyTools\Codex\active.json`。该 service 不解析 `access_token` / `refresh_token`，不联网，不记录 secret-bearing payload；若写入阶段失败，结果会保留已创建的备份路径供后续回滚 UI 使用。
- Native Codex Profiles 页面当前不读取或展示 `ProtectedConfigTomlBase64`、`ProtectedAuthJsonBase64`、`access_token`、`refresh_token` 等敏感字段，不发起网络请求；页面导航本身不覆盖 `~\.codex`。备份、差异摘要、当前目录导入、显式切换、最近备份恢复、普通文件导出、首个档案改名、首个档案 note/remark/tags 编辑与 `.codexbox` 加密包导入导出已接入显式菜单动作，写入类动作必须确认；首个 active profile 改名已同步迁移 `active.json` 标记，`.codexbox` 导入冲突策略选择已接入，relay 测试仍未接入菜单。
- `MainWindow` 创建 Win32 主窗口、原生菜单栏、托盘图标和消息循环；点击关闭按钮默认隐藏到托盘，托盘右键提供 Show window / Exit，双击托盘恢复窗口。`Tools / Home` 会切换首页；`Tools / Codex Profiles` 子菜单提供 Overview、Refresh summaries、Diff first profile、Backup current .codex folder、Apply first profile...、Import current folder...、Restore latest backup...、Export first profile files...、Rename first profile...、Edit first profile note...、Edit first profile remark...、Edit first profile tags...、Export .codexbox...、Import .codexbox...。`Apply / Import / Restore / Export first profile files / Rename first profile / Edit first profile note / Edit first profile remark / Edit first profile tags / Export .codexbox / Import .codexbox` 通过 `ConfirmCodexProfileWrite()` 二次确认后才调用 `CodexProfileModule::RunUiAction()`；普通文件导出先弹文件夹选择且拒绝当前 Codex 目录，改名先弹文本输入并执行 120 字符和控制字符校验，note/remark/tags 先通过 `PromptText` 输入文本并执行 trim、长度和 C0/C1 控制字符校验，`.codexbox` 导出先弹保存路径与两次密码输入，导入先弹打开路径、Rename / Skip / Replace 冲突策略选择与一次密码输入；FRP 与 Screenshot 仍是灰置待迁移项。
- `RendererD2D` 初始化 Direct2D factory、DirectWrite factory、文本格式和画刷，按 `ModuleInfo` 绘制当前模块标题、副标题、状态和 bullet 列表；底部状态栏展示当前模块位置。
- `scripts/native-eval.ps1 -Quick` 只做 Native 源码结构和路线守卫，不要求 CMake；`-Build` 才执行 CMake configure/build。当前机器未安装 CMake/MSVC 时，`-Build` 会失败并提示安装工具链。
- `scripts/codex-eval.ps1 -Quick` 已加入 `native shell scaffold` 静态守卫，防止 Native 阶段 1/2/3 scaffold 关键文件、Direct2D/DirectWrite、DPAPI Base64 解密/保护、托盘、基础服务、C 层 schema helper、模块导航、Codex Profiles 摘要承载点、显式菜单动作、切换前备份 service、差异摘要 service、元数据编辑 service、当前目录导入 service、普通文件导出 service、`.codexbox` 加密包 service、最近备份恢复 service、显式切换 service 和 CMake 约束被误删；同时守卫当前 Native Codex Profiles UI 动作层不得暴露 protected config/auth 字段、token 字段、联网或直接执行低层文件写入，主窗口必须通过 `CodexProfileModule` 动作路由而不是直接调用 service，写入类动作必须保留确认弹框，note/remark/tags 文本必须由 `PromptText` 收集后 trim、限制 500/500/200 字符并拒绝 C0/C1 控制字符，`.codexbox` 导入必须由主窗口采集冲突策略并通过 options 传给 module，禁止回归硬编码 Rename；备份/差异/编辑/导入/导出/加密包/恢复/显式切换 service 不得解析 token、联网、启动进程或记录 secret payload，`.codexbox` 不得改成 ZIP 或 GCM 格式。
- Native 不迁回清单：SQL 导出/查询/连接历史、Codex 轮换池与 Ollama 自动导入、硬件实时传感器、内置 `ffmpeg.exe`。

## Codex 本地中转模型同步

- 本地中转设置 `local-relay.json` 保存当前目标档案解析出的 `model`，用于区分同一个本地上游里的不同 Ollama 模型。
- 当用户启用本地中转、从档案切换到本地中转上游，或 MyTools 修复当前 Codex 配置时，`CodexLocalRelayService` 会把 `~/.codex/config.toml` 根级 `model_provider` 固定为 `mytools_local_relay`，并在目标档案有模型名时同步根级 `model` 与 `review_model`。
- 固定配置校验同时核对 `model_provider`、`model`、`review_model`、`disable_response_storage=false`、本地 relay `base_url`、`wire_api`、PowerShell token helper、脚本路径、token 文件路径、超时和刷新间隔；任一字段缺失或不一致都会触发备份并重写。
- Ollama 本机档案继续使用 `model_provider = "mytools_local_ollama"`、`base_url = "http://127.0.0.1:11434/v1"` 和空 `auth.json`；MyTools relay 转发到 loopback 上游时不附加空 `Authorization`。

## 一、排班管理

### 1.1 表格结构

每月排班表采用 **4 行表头 + 人员数据行**：

| 行号 | 内容 | 说明 |
|---|---|---|
| 第 1 行 | 星期 | 周一 ~ 周日循环显示 |
| 第 2 行 | 日期 | 当月 1 ~ 28 / 29 / 30 / 31 |
| 第 3 行 | **实休** | 该列实际休息人员合计（只读，自动汇总） |
| 第 4 行 | **总休** | 该列**目标休息人数上限**（硬约束，可手工编辑） |
| 第 5 行起 | 人员行 | 每行一名员工，列对应日期 |

> **实休 > 总休** 时两行同时标红，提示越界。**实休 < (总休-0.5)** 时两行同时标红，提示越界。优化器会尽力把实休贴近总休。

人员行在日期列后显示 5 个只读汇总列：**上班**、**休息**、**连上**、**末休**、**可上**。其中“末休”统计当前月份内该人员在周六和周日休息的总天数，按 `ShiftCodes.RestDays()` 口径累计，“午”计 0.5 天，“休 / 公 / 产”计 1 天；“可上”统计当前行所有空白单元格与已经设置为上班班次的单元格合计，表示该人员最多可设置为上班的天数。

界面与 Excel 导出中，周六、周日以及 `HolidayService` 判定的其它节假日整列使用较深蓝色底色；“卡”使用绿色底色，“产”使用浅橙色底色，“公”和“午”使用相同浅黄色底色；“休 / 卡 / 副 / 感 / 大 / 小 / 公 / 产 / 午”等专用班次色优先于节假日列底色，空白格与不显示文字的“白”格继续使用节假日列底色。

### 1.2 手工指定

点击单元格弹出下拉菜单，可选下列标识：

> 新增或改班时弹出菜单隐藏「午」选项；已有数据中的「午」仍会显示、统计为 0.5 天休息，并在界面与 Excel 中使用与「公」相同的浅黄色底色。

| 标识 | 含义 | 计入上班 | 计入休息 |
|---|---|---|---|
| **白** | 白班 | 1 | 0 |
| **卡** | 卡班 | 1 | 0 |
| **副** | 副小 | 1 | 0 |
| **感** | 感染科 | 1 | 0 |
| **大** | 大夜 | 1 | 0 |
| **小** | 小夜 | 1 | 0 |
| **休** | 休息 | 0 | 1 |
| **公** | 公休 | 0 | 1 |
| **产** | 产假 | 0 | 1 |
| **午** | 下午休 | 0 | 0.5 |

> 「夜」与「大」指向同一含义（大夜），统一以 **「大」** 为最终显示字符与统计键。

#### 1.2.1 夜班快捷设置（自动联动）

| 快捷 | 当天 | 前一天 | 后续 | 序列 |
|---|---|---|---|---|
| **大1** | 大 | 小 | 后两天 = 休 | 小 → 大 → 休 → 休 |
| **大2** | 大 | 小 | 后一天 = 休 | 小 → 大 → 休 |

- 通过快捷写入的 **小 / 大 / 休** 同样视为**手工锁定**，参与"手工最高优先级"。
- 若用户单独选「大」（不走快捷），只写当前格，不自动派生小夜和后休。

#### 1.2.2 多选填充与选区清空

- 排班班次单元格的选区只存在于 `SchedulePage` 页面层，不写入排班 JSON。
- 单击单元格会设为当前选区和填充源；拖拽、`Shift` 扩选和 `Ctrl` 追加选择只改变页面选区。
- 点击工具栏「填充」时，`ScheduleViewModel.FillCellsFromSource()` 读取源格的 `Code`，批量写入选区内所有有效日期格；非空班次写入后统一标记 `IsManual=true`，空白源格填充后目标格为 `Code=""`、`IsManual=false`。
- 按 `Delete` 时，`ScheduleViewModel.ClearCells()` 只清空当前选区内的日期格，目标格统一变为 `Code=""`、`IsManual=false`；姓名、每日总休目标、人员行和其它未选中格不变。
- 批量写入后只触发 `ScheduleDataChanged`，沿用局部刷新路径更新单元格、统计、冲突和周休信息，不重建整张动态表格。

### 1.3 自动设置休息日

点击 **「开始设置休息日」**。系统在尊重手工锁定的前提下，对剩余未指定单元格做智能优化。

#### 1.3.1 基本规则

- 自动生成**只填「白」与「休」**两种值，不会自动派出卡 / 副 / 感 / 大 / 小 / 公 / 产 / 午。
- 再次点击时，**之前自动生成的休息格**默认会**全部清空重算**；只有前端通过 `preserved_cells` 显式标记的格子才会保留。
- 自动生成开始前会获取当月排班表锁，**避免并发生成互相覆盖**。
- 依赖**广西法定节假日**配置；目标年份配置缺失时直接报错。
- 节假日集合 = **周六 ∪ 周日 ∪ 法定节假日**；周末双休专门关注 (Sat, Sun) **整对**。

#### 1.3.2 优化优先级（高 → 低）

| 级别 | 规则 | 类型 |
|---|---|---|
| **H1** | 每天**（总休-0.5）≤ 实休 ≤ 总休** | **硬约束** |
| **H2** | 任何人连续上班天数 ≤ **5 天** | **硬约束** |
| **H3** | 每个人月休息天数 ≥ 9 天 | **硬约束** |
| S1 | 周末（周六 + 周日）连续休息 2 天，并尽量均衡 | 软目标 |
| S2 | 休息日尽量落在节假日（含周末 + 法定节假日），并尽量均衡 | 软目标 |
| S3 | 每人节假日休息 ≥ **4 天**，并尽量均衡 | 软目标 |
| S4 | 每人月度总休天数尽量均衡 | 软目标 |
| S5 | 尽量让人上班时间和休息时间连续 | 软目标 |
| S6 | 尽量让每个人在月内有连续休息≥2天的次数≥3 | 软目标 |

> 半天精度：仅「午」计 0.5 天休息，「休 / 公 / 产」均计 1 天休息。所有统计（上班 / 休息 / 连上 / 末休 / 可上）必须**实时准确**，其中休息与末休支持 **0.5 天精度**。

#### 1.3.3 拒绝生成的硬性场景

| # | 场景 | 行为 |
|---|---|---|
| 1 | 法定节假日配置缺失 | 报错并提示补充配置 |
| 2 | 总休 − 锁定休息后，剩余为**奇数个半天** | 拒绝（自动休息只能补整天） |
| 3 | 当日因 H2 需强制休息的人数 > 当日剩余休息名额 | 报错并指出冲突 |
| 4 | 写回前逐日校验出现**实休 > 总休** | 拒绝写回 |

#### 1.3.4 节假日容量警告（非阻断）

若受总休上限与手工锁定格约束，导致部分人员节假日休 < 4 天目标，Service 返回**警告**（非错误），结果仍写入。

#### 1.3.5 多方案与重复点击

- 生成器跑**多轮候选**，按评分挑最优：周末双休均衡 → 节假日均衡 → 月休 / 两日连休 / 低于目标。
- 每次执行使用新的随机种子，使**重复点击「开始设置休息日」**能得到不同但都合规的方案，便于挑选。
- 「无警告再显示」复选框打勾时，只显示零警告的方案；当前候选若有警告，自动进入下一轮随机生成，直至得到完全合规（零警告）的结果。若所有候选均含警告，停止并显示警告数最少的方案，提示"无法生成零警告方案"。

### 1.4 手工最高优先级与跨月

- **手工锁定（含夜班联动派生）的格子永远不会被自动覆盖**，是所有自动流程的输入而非输出。
- 跨月夜班按**实际归属月份**分别计入两个月的统计。
- 自动生成成功后更新 `generated_time` 字段，作为自动设置休息日完成时间记录。

### 1.5 表格初始化

点击 **「新建」**：

1. 按所选年月生成空白排班表。
2. 自动复制上月**人员名单**（仅姓名，本月格子从空白开始）。
3. 上月每日休息人数**不直接套用**到本月。

**第 4 行 总休 默认值：**

| 周次 | 默认人数 |
|---|---|
| 周一 ~ 周五 | 6 |
| 周六 | 8 |
| 周日 | 9 |

> 第一个月没有上月可继承时，从导入表或手工添加开始。

### 1.6 保存与版本

- **保存校验**：年月、人员行、每日休息人数数组长度、0.5 步进。
- **空姓名行**：视为占位行，不参与自动生成。
- 普通保存会保留前端提交的 `preserved_cells`；**生成排班前保存**不保留旧自动休息，避免锁死旧结果。
- 旧人员行与旧单元格按保存结果**整体重建**。
- 新建时需输入版本名称；已存在同名版本则**直接覆盖**。
- 每个月支持保存多个版本，**版本列表显示在左侧**。

### 1.7 Excel 导出

- 当前已加载排班版本时即可随时导出当前表格内容，不依赖 `generated_time` / `GeneratedAt`。
- `GeneratedAt` 仅记录自动设置休息日或 Excel 导入完成时间，不作为 Excel 导出权限判据。
- 导出范围严格限定在排班数据本身，不串入其它业务模块。
- 班次显示与界面保持一致；旧数据中的「夜」会先归一化为「大」，Excel 单元格导出为「大」。
- 人员汇总列顺序为“上班 / 休息 / 连上 / 末休 / 可上”；“末休”与界面一致，只统计当前月份内周六、周日发生的休息天数；“可上”按空白单元格 + 已设置上班单元格计算。

### 1.8 Excel 导入

- “导入排班”按钮读取 `.xlsx` 排班表，不依赖 Office 或 OpenXML SDK。
- 基础格式要求：A1 为“姓名”，A2 为“日期”，A4 为“总休”；B2 起必须是连续日期 `1..当月天数`，第 5 行起为人员行。
- 年月优先从文件名中的 `YYYY-MM` 识别；没有可识别年月时，若当前已加载排班且天数匹配，则使用当前排班年月兜底。
- 第 4 行日期列导入为 `DailyRestQuotas`，要求非负且符合 0.5 步进。
- 人员行按 A 列姓名导入；空姓名行跳过。班次只接受 `白/卡/副/感/大/小/休/公/产/午` 及兼容别名，其中旧“夜 / 夜班 / 大夜”归一化为“大”，“产假”归一化为“产”。
- 导出文件中“白”班显示为空白；导入时只有识别到右侧统计列表头为“上班”时，才按该统计把必要的空白日期格还原为 `白` 并标记为手动，避免导入后自动生成覆盖用户 Excel 内容；未识别到“上班”表头时保留空白并给出提示。
- 导入成功后替换当前表格内容，并写入 `GeneratedAt`，表示该 Excel 已作为完整导入版本进入可保存状态；Excel 导出始终按当前表格内容执行，不依赖该字段；用户可选择立即保存为本地排班版本，同名版本存在时会二次确认覆盖。

## 四、Codex 账号管理

### 4.1 存储结构

- 档案库：`%LOCALAPPDATA%\MyTools\Codex\profiles.json`（DPAPI 加密）。
- 当前激活：`active.json`。
- 切换前自动备份：`~/.codex/` → `%LOCALAPPDATA%\MyTools\Codex\Backups\{name}_{yyyyMMdd_HHmmss}.bak.dpapi`。
- 进入 Codex 配置页时会确保触发档案库加载；如果页面已进入但列表为空、且本地 `profiles.json` 存在，同时此前未成功完成加载，则允许再次触发加载，避免切页或初始化竞态导致档案库显示为空。
- Codex 配置页的列表区域由 `CodexProfiles` 集合单独驱动；列表为空时显示 Codex 专属空态，不复用文件验证或其他模块的拖放区域。档案卡片不再展示轮换设置行；操作按钮使用 Codex 面板局部紧凑样式，避免按钮过多时挤出卡片宽度。

### 4.2 档案复制

- 入口：在某条 Codex 档案上点击“复制”。
- 复制时先解析原档案中保存的 `config.toml` 与 `auth.json`；若任一文件内容不可用，则提示用户先刷新或重新导入，不创建新记录。
- 新档案名称使用“原名_复制”作为基础名，并通过 `EnsureUniqueCodexDisplayName()` 生成唯一别名。
- 新档案使用当前 Windows 用户 DPAPI 重新加密 `config.toml` 与 `auth.json`，重新解析邮箱、Access 过期时间和 `Status`。
- 新档案 `IsActive=false`、`LastAppliedAt=null`、`RelayTestStatus=未知`；复制动作只保存档案库，不写 `active.json`，也不覆盖当前 `~/.codex`。

### 4.3 config.toml 模板同步

- 入口：在某条 Codex 档案上点击“应用到所有”。
- 同步前校验模板档案的 `config.toml` 必须存在 `base_url = ...` 行。
- 确认后先把当前档案库快照写入 `%LOCALAPPDATA%\MyTools\Codex\Backups\profiles_config_sync_<模板名>_<yyyyMMdd_HHmmss>.profiles.dpapi`。
- 对每个非模板目标档案：解密目标 `config.toml` → 找到目标自身的 `base_url = ...` 行 → 用模板 `config.toml` 替换目标配置 → 将目标原有 `base_url = ...` 行写回对应位置 → DPAPI 重新加密保存。
- 如果目标没有 `base_url = ...` 行，或模板与目标的 `base_url` 行数量不一致，则跳过该目标并在结果弹窗中列出原因。
- 该操作只更新档案库中的 `config.toml`，不修改 `auth.json`、别名、备注或测试状态，也不直接写入当前 `~/.codex`。

### 4.4 已移除：账号轮换和本地模型导入

- Codex 配置页不再提供“立即轮换”“全选轮换”“反选轮换”“轮换后通知”“无可用轮换目标”“加入轮换 / 优先级”控件。
- `MainViewModel` 不再暴露 `RotateToNextCodexProfileCommand`、`SelectAllCodexRotationCommand`、`InvertCodexRotationCommand`、`CodexNextSwitchPreview`、`CodexRotationSettings` 或 `IsCodexRotationAvailable`。
- 轮换核心与 hot-token 兼容路径已删除：`CodexRotationService.cs`、`CodexHotTokenService.cs` 不再参与构建。
- “导入 Ollama 模型”按钮和自动读取本机模型列表能力已删除；`CodexOllamaProfileService.cs` 不再参与构建，程序不会请求 `http://127.0.0.1:11434/api/tags` 生成本地模型档案。
- 为兼容旧档案文件，档案序列化仍容忍历史 `EnableRotation` / `RotationPriority` 字段，但当前 UI 不展示、不修改、不参与业务。
- 当前仍保留用户显式操作的档案行“切换 / 本地切换”、单条“测试”、顶部“测试中转”、本地中转启停、CPA Token 导入和加密包导入导出。
### 4.5 JWT Token 状态判定

- 从 `auth.json` 中尝试多个路径提取 `access_token` / `id_token`。
- 解析 payload 中 `exp` 字段计算状态：
  - **正常**：剩余有效期 > 7 天
  - **即将过期**：剩余有效期 ≤ 7 天
  - **已过期**：`exp < now`

### 4.6 导出加密包（.codexbox）

- 密码经 **PBKDF2**（SHA256，200,000 次迭代）+ 16 字节 salt 生成 64 字节密钥。
- **AES-256-CBC** 加密内容。
- **HMAC-SHA256** 对 `[Header+Salt+IV+Ciphertext]` 做完整性验证。
- 文件格式：`Header(CDXB) + SchemaVersion + Salt + Iterations + IV + CiphertextLength + Ciphertext + MAC`

## 五、微信数据管理

### 5.1 目录定位

- 从 `Documents\WeChat Files`、`Documents\Tencent Files`、`Documents\xwechat_files`、`Documents\xwechat_files\all_users`、`%APPDATA%\Tencent\xwechat_files` 和微信注册表 `FileSavePath` 中定位账号目录。
- 账号目录必须同时满足账号名规则（`wxid_*`、纯数字或数字加后缀）和微信数据目录证据。

### 5.2 扫描阶段

- 旧版微信枚举 `FileStorage` 下的 Image / Video / Voice2 / File / Cache / CustomEmotion / MsgTemp。
- 新版微信枚举 `msg\attach`、`msg\video`、`msg\file`、`cache`、`temp`、`resource`、表情缩略图与收藏临时目录。
- 按 `LastWriteTime` 过滤日期范围。

### 5.3 安全红线

- **禁止删除** `Msg*.db` 和 `MicroMsg.db`（核心聊天数据库）。
- 备份恢复禁止写入 `MMKV`、`config`、`db_storage`、`Msg*.db`、`MicroMsg.db`、`Login.dat` 和 `SafeStorage*` 等数据库、配置和登录态路径；新版 `xwechat_files` 的 `msg\attach`、`msg\video`、`msg\file` 媒体目录不按整目录禁止。
- 文件送到**回收站**（`RecycleOption.SendToRecycleBin`），不做永久删除。

### 5.4 备份格式

- ZIP 包，内含 `manifest.json`（描述来源、时间范围、类别）。
- 文件按相对路径存储。
- 备份前必须至少选择 1 个类别；恢复旧备份缺少 `category` 字段时，按缓存目录、媒体扩展名和目录段推断类别。

### 5.5 界面组织

“系统优化”页面中的微信数据管理入口统一为“微信工具”页签，页签内使用单张卡片承载 3 段功能：

| 分段 | 功能 | 命令 |
|---|---|---|
| 微信清理 | 日期范围、账号、类别筛选；扫描候选项；将选中文件送入回收站；账号下拉显示账号名与目录类型 | `ScanWeChatCleanupCommand` / `StartWeChatCleanupCommand` |

| 微信恢复 | 读取备份 ZIP；选择原目录或自定义目录；按类别恢复；最近备份快捷入口 | `SelectWeChatRestoreZipCommand` / `StartWeChatRestoreCommand` |

## 六、系统优化

### 6.0 系统维护卡片

“系统优化”页面顶部页签中的“系统维护”使用单张卡片承载 3 段功能：

| 分段 | 功能 | 状态 |
|---|---|---|
| 系统锁定 | 读取当前 Windows 10/11 产品名与功能版本，写入目标版本锁定策略；应用常亮电源策略 | `SystemStatusMessage` / `PowerPolicyStatusMessage` |
| 安全防护 | 关闭/恢复 Windows Defender 实时防护；刷新状态；执行后读回实际状态，避免篡改保护拦截时误报成功 | `IsDefenderEnabled` 徽章 |
| 自动更新 | 停止/恢复 Windows 自动更新；停止时写入 `NoAutoUpdate` / `AUOptions` 策略、禁用常见 Windows Update 计划任务，并停止、禁用 `wuauserv`、`UsoSvc`、`BITS`、`DoSvc`、`WaaSMedicSvc`；恢复和立即更新会移除停止策略，并把服务启动类型和计划任务恢复为 MyTools 默认更新配置 | `IsAutoUpdateEnabled` 徽章 |

卡片右侧操作区使用固定宽度操作列，按钮组在列内左对齐。`LockWin10Command` 保留历史绑定名，实际执行逻辑已改为按当前 Windows 10/11 版本锁定。自动更新状态由 `WindowsSecurityService.IsAutoUpdateRestoreReady()` 读取策略、服务启动类型和计划任务状态；停止命令完成后额外用 `IsAutoUpdateStopEnforced()` 校验策略、核心服务禁用和计划任务禁用均已生效，未生效时不显示“已停止”成功提示。

### 6.1 自动优化两步流程

“自动优化”页签分为两个动作：

| 阶段 | 触发 | 行为 |
|---|---|---|
| 扫描 | `ScanAutoOptimizeCommand` | 调用 `SystemOptimizationService.ScanAsync`，只读取系统状态并填充 `AutoOptimizePlanItems` |
| 优化 | `StartAutoOptimizeCommand` | 读取本次扫描结果中 `CanOptimize=true && IsSelected=true` 的步骤键，调用 `SystemOptimizationService.RunAsync(..., enabledStepKeys)` 执行实际优化 |

- 扫描阶段不会删除文件、清空回收站、重启 Explorer、启停服务、执行 UAC 提权脚本或写入系统设置。
- 扫描列表展示执行勾选、状态、项目、风险、类型、预计释放空间、安全边界、扫描证据和说明。
- 低风险且收益明确的项目可默认勾选；中高风险、会重启 Explorer、清理诊断证据、清空回收站、优化磁盘或执行 DISM 的项目默认不勾选，必须由用户手动选择。
- “优化”按钮仅在本次扫描结果中存在已勾选可优化项时可用；优化完成后清空本次扫描结果，用户再次优化前必须重新扫描。
- 确认弹窗汇总执行数量、预计释放空间、UAC 数量、中高风险数量；存在高风险项时列出具体项目名称。
- 历史报告仍写入 `OptimizationReports`，并可通过“查看”显示步骤明细。

### 6.1.1 14 步自动优化流水线

| 步骤 | 内容 | 权限 |
|---|---|---|
| 1 | 清空当前用户 Temp（24 小时前） | 普通 |
| 2 | 清空 Windows Temp（7 天前） | **UAC 提权** |
| 3 | 清理缩略图缓存（需要用户同意重启 Explorer） | 普通 |
| 4 | 刷新 DNS 缓存 (`ipconfig /flushdns`) | 普通 |
| 5 | 重置字体缓存（FontCache 服务） | **UAC 提权** |
| 6 | 清理 Windows Update 缓存 | **UAC 提权** |
| 7 | 清理 Delivery Optimization 缓存 | **UAC 提权** |
| 8 | 清理 Windows 错误报告（14 天前） | **UAC 提权** |
| 9 | 清理崩溃转储（30 天前） | **UAC 提权** |
| 10 | 系统盘 TRIM（SSD）/ 碎片整理（HDD） | **UAC 提权** |
| 11 | 组件存储清理（DISM StartComponentCleanup） | **UAC 提权** |
| 12 | 清空回收站 | 普通 |
| 13 | 清理事件日志（Application/System/Security > 500MB） | **UAC 提权** |
| 14 | 压缩当前进程工作集（`EmptyWorkingSet`） | 普通 |

- 提权操作通过 PowerShell 脚本 + `runas` verb 实现，用户取消 UAC、脚本超时或退出码非 0 时步骤标记为 Failed。
- 磁盘类型通过 `Get-Disk.MediaType` 检测是否为 SSD。
- 自动优化扫描、本地删除和提权脚本删除均通过白名单根路径、reparse point 跳过和根内路径校验保护递归范围；提权脚本使用 PowerShell 2.0 兼容写法，不使用 `Get-ChildItem -File/-Directory`；Windows Update 与 Delivery Optimization 缓存清理只在服务原本运行时尝试恢复服务，避免把用户已停止的更新服务重新拉起。

### 6.2 垃圾清理扫描范围

“垃圾清理”页签只保留两个动作：

| 阶段 | 触发 | 行为 |
|---|---|---|
| 扫描 | `StartJunkScanCommand` | 调用 `JunkCleanupService.ScanAsync`，只读取白名单目录并填充 `JunkCandidates` |
| 清理 | `RunJunkCleanupCommand` | 读取已勾选候选，普通文件发送到回收站，系统缓存按类别请求 UAC，但提权脚本只处理本次已勾选路径 |

扫描共 11 类：

| 类别 | 范围 | 默认勾选 |
|---|---|---|
| 用户临时目录 | 当前用户 Temp 与 `%LOCALAPPDATA%\Temp` 中 24 小时前文件 | 是 |
| 系统临时目录 | `%WINDIR%\Temp` 中 7 天前文件 | 是 |
| 回收站 | Shell 回收站总容量 | 否 |
| Edge / Chrome 浏览器缓存 | 顶层 `Default` / `Profile *` 下 `Cache_Data`、`Code Cache`、`GPUCache`、`Service Worker\CacheStorage` | 否 |
| 缩略图缓存 | `%LOCALAPPDATA%\Microsoft\Windows\Explorer\thumbcache_*.db` | 是 |
| Prefetch | `%WINDIR%\Prefetch` 中 30 天前 `.pf` 文件 | 是 |
| Windows Update 缓存 | `%WINDIR%\SoftwareDistribution\Download` | 是 |
| Delivery Optimization 缓存 | `%WINDIR%\ServiceProfiles\NetworkService\...\DeliveryOptimization\Cache` | 是 |
| Windows 错误报告 | 当前用户 WER `ReportArchive` / `ReportQueue` 中 14 天前文件 | 否 |
| 崩溃转储 | 当前用户 `%LOCALAPPDATA%\CrashDumps` 中 30 天前 `.dmp` 文件 | 否 |
| Installer 空目录 | `%LOCALAPPDATA%\Package Cache` 下空目录 | 是 |

- 扫描结果表展示选择、类别、大小、风险、建议、安全边界、扫描证据、路径和说明；不再提供“导出报告”按钮。
- `SafePathHelper` 的安全枚举会跳过 reparse point，并确认枚举文件仍在扫描根目录内。
- 清理前再次用 `SafePathHelper.IsPathInsideAny` 校验候选路径；普通文件使用 VisualBasic FileSystem 发送到回收站，目录候选按安全枚举逐个回收文件后删除空目录。
- 系统临时目录、Windows Update 缓存和 Delivery Optimization 缓存使用提权 PowerShell 脚本；脚本内包含 `Test-PathInsideRoot` 和 `Test-ReparsePoint`，删除前再次校验目标仍在批准根目录内，只处理本次已勾选路径，并跳过 junction/symlink。
- Windows Update 与 Delivery Optimization 缓存清理只在对应服务原本运行时尝试恢复服务，避免把用户已停止的服务重新拉起。
- **安全白名单**：以下目录**永远不在扫描范围内**：`System32`、`WinSxS`、用户文档/桌面/图片/Downloads、`Program Files` 等。

## 七、截图与录屏

### 7.1 截图

- 使用 `Graphics.CopyFromScreen` 捕获**虚拟屏幕**（全屏 + 多显示器）。
- 通过 `GetCursorInfo` + `DrawIconEx` 绘制鼠标光标。
- P/Invoke `GetSystemMetrics` 获取虚拟屏幕坐标。
- “划区域”截图先捕获整张虚拟屏幕，再用 `RegionSelectorWindow` 显示半透明蒙层；窗口创建后按 HWND DPI 与虚拟屏幕物理像素重新定位，选区转换为像素矩形时左上边界使用 floor、右下边界使用 ceiling，避免高 DPI 或边界四舍五入导致右侧缺失。
- 剪贴板写入使用 `ScreenshotService.SetClipboardCompatible()`，先复制为 32 位 BGRA 位图，再同时写入 WPF Image、32 位 DIB 和 PNG 数据，避免任意宽度区域截图在部分粘贴目标中被误读为缺少右侧像素。
- 截图编辑器窗口创建前按需加载延迟 UI 资源，避免快捷键直接截图时尚未进入截图模块，导致 MaterialDesign `StaticResource` 解析失败。

### 7.2 视频 / GIF 录制

- 依赖外置 `ffmpeg.exe`，查找顺序：`%ExecutableDir%\NativeBinaries\ffmpeg\ffmpeg.exe` → `%ExecutableDir%\ffmpeg.exe` → 常见安装目录 → PATH；安装包不再内置 FFmpeg。
- 支持指定帧率、画质、GIF 模式。
- `AppSettings` 保存 `IsGifRecordingMode`、`RecordingFrameRateOption` 和 `RecordingQualityOption`；截图设置页切换 MP4/GIF、帧率或画质时由 `MainViewModel.PersistRecordingBehaviorAsync()` 异步写入程序同目录 `MyTools.settings.json`，加载截图设置时回填并通过 `_suppressRecordingBehaviorAutoSave` 避免初始化回填触发重复写盘。
- 启动探测超时：**700ms**。

### 7.3 音频录制（扬声器内录）

- 使用 `MMDevice` API + `WasapiLoopbackAudioRecorder`，**不需要麦克风**。
- 默认输出 `.wav`，停止录音后直接把 WASAPI 临时 WAV 保存为最终文件。
- 录音格式可选 `.wav / .m4a / .mp3`；选择 `.m4a` 或 `.mp3` 时停止后调用 ffmpeg 转码，未采集到有效声音时不生成静音文件。
- 录音过程中 `WasapiLoopbackAudioRecorder` 保留最近 UI 刷新间隔内的短时峰值；`RecordingService.GetActiveAudioLevelSnapshot()` 被 `MainViewModel` 以 250ms 节奏读取并清零短时峰值，截图工具页顶部固定 28 根波形柱滚动显示实时电平，同时显示 `mm:ss` 或 `hh:mm:ss` 录音时长。
- 停止录音时 `WasapiLoopbackAudioRecorder` 按采样格式统计样本峰值和可听样本数；实时统计未命中时使用 `WaveFileReader` 复扫临时 WAV 文件，只有文件存在且超过静音阈值时才保存最终录音，否则删除临时文件并提示用户检查播放声音、音量和默认播放设备。
- 录音格式保存在程序同目录 `MyTools.settings.json` 的 `AudioRecordingFormat` 字段，旧配置缺省时按 `wav` 处理；点击截图设置页“保存设置”会同时写回当前录音格式，避免只改截图快捷键时覆盖其它截图工具设置。

### 7.4 OCR

- 基于 Tesseract 实现文字识别。

## 九、多媒体转换

- 多媒体页右侧媒体文件区支持“详细信息 / 列表 / 大图标”三种查看方式，切换只改变 `ListView` 的展示模板，数据源仍为同一个 `MediaFiles` 集合。
- 查看方式状态由 `MultimediaViewModel.FileViewMode` 管理，选中项、勾选状态、双击沉浸预览和右键转换菜单在三种视图间保持一致。
- 大图标模式使用固定单元宽度的 `WrapPanel`，关闭横向滚动并根据可用宽度自动换行。
- 音视频预览和沉浸播放的进度条由 `DispatcherTimer` 定时同步；用户拖动进度滑块时暂停同步，松开鼠标后写入 `MediaElement.Position` 并从该位置继续播放。
- 音视频预览和沉浸播放的音量滑块直接设置对应 `MediaElement.Volume`，范围为 `0.0` 到 `1.0`。
- `MediaFileItem.Thumbnail` 对图片直接懒加载小尺寸缩略图；对视频调用 ffmpeg 后台抽取首帧，缓存到 `MediaThumbnails/`，失败时继续显示扩展名占位。
- `MediaFileTypeHelper` 会将文本、Markdown、Word、Excel、PowerPoint 文件纳入右侧文件内容列表。
- 文本和 Markdown 通过 `MultimediaViewModel` 异步读取前 32 KB 内容并显示在左侧预览区；Office 文件只显示类型、大小、修改时间和外部打开入口，不引入 Office COM 或高版本运行时依赖。
- **图片**：JPG / PNG / BMP / GIF / TIFF 互转，支持缩放、压缩质量控制。
- **视频 / 音频**：基于 ffmpeg 转码。
- **字幕**：支持 SRT / VTT / ASS 加载，时间戳解析。

## 十一、启动项管理

### 11.1 枚举范围

- 当前版本枚举注册表 Run 启动项：
  - `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`
  - `HKLM\Software\Microsoft\Windows\CurrentVersion\Run`
- MyTools 自己禁用过的项目保存在同范围根下的 `Software\AJunTools\DisabledRun`。
- Windows 自身的启用/禁用状态读取 `Software\Microsoft\Windows\CurrentVersion\Explorer\StartupApproved\Run`。

### 11.2 禁用与恢复

- 点击“禁用”时，程序将原 Run 值写入 MyTools 备份，再写入 `StartupApproved\Run` 禁用标记，最后删除 Run 值。
- 如果第三方软件重新写回同名 Run 值，刷新列表时以 `StartupApproved\Run` 为准，显示为“注册表 Run（Windows 已禁用）”，避免误判为普通已启用项。
- 点击“启用”时，程序优先从 MyTools 备份恢复命令；备份不存在时使用现有 Run 值或当前列表命令兜底，同时写入 Windows 启用标记。
- 点击“永久删除”时，同时删除 Run、MyTools 备份和 `StartupApproved\Run` 同名值。

### 11.3 边界

- 系统级启动项需要管理员权限。
- 本模块不处理计划任务、服务、驱动、浏览器后台服务等非 Run 自启入口。
- 启动项扫描只在用户进入模块或点击刷新时执行，不进入 `App.OnStartup` 或 `MainWindow` 构造函数。

## 十二、基础设施规范

| 约束项 | 内容 |
|---|---|
| **启动性能** | `App.OnStartup` 与 `MainWindow` 构造函数禁止执行超过 **50ms** 的磁盘 IO / WMI；所有重型操作通过 `Dispatcher.BeginInvoke(DispatcherPriority.ApplicationIdle, ...)` 延后 |
| **ViewModel 懒加载** | `MainViewModel` 构造函数禁止直接创建重型子 ViewModel（`ScheduleViewModel` 等须以懒加载属性暴露） |
| **启动后响应** | `ScheduleStartupBackgroundLoads()` 只允许加载轻量 shell 状态；WMI、注册表枚举、模块数据扫描等会阻塞菜单响应的任务必须在用户进入对应模块或点击按钮后按需执行 |
| **日志** | Serilog `flushToDiskInterval` ≤ **2 秒**；日志不记录密码/完整连接字符串；单条日志 ≤ 1 KB |
| **安全** | 敏感凭据使用 **Windows DPAPI（当前用户范围）** 加密；日志保持脱敏，不记录密码、完整连接字符串或大文本 |
| **GC** | `App.config` 保留 `<gcServer enabled="true" />` + `<gcConcurrent enabled="true" />` |
| **单文件发布** | Costura.Fody 合并托管 DLL；FFmpeg 为外置依赖，不随安装包内置 |

## 十三、Codex 中转测试

- 入口：Codex 配置面板顶部“测试中转”按钮用于批量测试全部档案；每条档案行“测试”按钮用于单独测试当前档案；面板 relay 状态灯由“启动本地中转”按钮单独更新。
- 执行时机：仅在用户点击顶部“测试中转”按钮、点击档案行“测试”按钮、点击“启动本地中转”测试当前 NewAPI、本地中转已启用时点击普通手动“切换”触发目标上游检查时发起网络请求；启动、加载档案、刷新账号均不自动测试远程上游。
- 输入：逐条优先读取档案库中 DPAPI 加密保存的 `config.toml` 与 `auth.json`，旧记录缺少内嵌内容时只读回退来源目录文件；随后解析 `base_url`、`model`、`wire_api`、`requires_openai_auth`、`env_key`、`api_key`、`OPENAI_API_KEY` 和 `access_token`。
- 请求规则：如果存在 `model`，优先按 `wire_api` 向 `{base_url}/responses` 或 `{base_url}/chat/completions` 发送 `stream=true` 的 1 token 最小请求，并自动追加 `{base_url}/v1/...` 回退路径；测试结果携带实际成功命中的有效上游基址，供本地中转保存；如果缺少 `model`，只请求 `{base_url}/models` 做连通性检查；如果档案使用 `requires_openai_auth = true` 且没有普通 API key，则只验证中转网关可达与配置完整性；如果 `base_url` 是本机 loopback 地址，则允许无 API key 并直接测试本机 provider。
- 结果记录：每条档案保存 `RelayTestStatus`、`RelayTestedAt`、`RelayTestMessage`，状态值为“可用 / 不可用 / 未知 / 测试中”；UI 用绿灯、红灯、灰灯或黄色测试中标识展示；单条“测试”只更新该档案的结果并保存档案库，不切换账号、不备份、不覆盖当前 `~/.codex`。
- 安全限制：日志与档案只保存别名、状态和 160 字以内摘要，不保存 token、完整认证头、请求正文响应正文或完整连接凭据。
